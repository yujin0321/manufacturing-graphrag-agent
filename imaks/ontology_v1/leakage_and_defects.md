# 데이터 누수·결함 정책

2026-10-05. 기존 공통 전처리 정책을 Ontology v1에도 적용한다.

## 입력 분리

| 데이터·정보 | 탐지 입력/ML | 룰 베이스라인·문서 기반 설명 | 평가·감사 |
|---|---|---|---|
| raw `quality` | 제외. STUCK과 완전 일치하는 라벨 프록시 | 관측 입력에서도 제외 | 원본 보존 |
| annotated 이상 라벨·severity·alarm_flag | 제외 | 설명 입력에서도 제외 | 키로 대조 |
| nominal·warn_hi·crit_hi·warn_lo·crit_lo | 직접값과 임계값 유래 특징 모두 제외 | 룰 탐지와 문서에 근거한 조치 설명에서 사용 | 임계값 사용 여부를 결과에 명시 |
| MQTT status·alarms·readings quality | 제거한 스트림 사용 | 같은 제거본 사용 | 원본 보존 |
| 기존 AnomalyEvent 14건 및 사후 Safety/Maintenance 사건 | 입력 KG에서 제외 | 새로운 이상을 탐지·설명하는 실험에서도 정답 사건은 제외 | 별도 평가·사후 분석 |
| 규칙 추출 정답 86건·SPD 수정본 | Rule 생성과 프롬프트 입력에서 제외 | Rule은 원본 문서에서 생성 | 원본/문서 수정 기준을 구분하여 추출 평가 |
| day·shift·batch_id | 미검증 시간/배치 피처로 사용하지 않음 | timestamp로 정렬·연결 | 원본 메타데이터·불일치 기록 보존 |
| 출입·응답 사후 로그 | 이상 탐지 관측 입력으로 사용하지 않음 | 실제 운영 관측으로 검토·정제한 경우에만 별도 실험 | 범위 이탈·UNKNOWN·허위 참조 표시 |

`generated/ml_metadata.ttl`은 정적 구조만 포함한다. `generated/rule_context.ttl`에는 문서와 규칙이 있으며 룰·설명용으로만 사용한다. 문서나 GraphRAG 검색을 통해 얻은 임계값을 학습 모델의 피처로 다시 넣으면 미사용 조건이 깨진다. 현재 탐지 코드는 이 새 RDF를 읽지 않으며 기존 7컬럼 ML CSV를 사용한다.

동일 정답으로 임계값 사용 룰과 임계값 미사용 통계 탐지기를 비교할 수 있지만, 서로 다른 탐지기의 비교를 동일 모델의 피처 효과만 분리한 실험이라고 부르지 않는다. 검증 라벨은 윈도우 선택에, 테스트 라벨은 평가에 사용했다. 테스트 결과를 이미 확인한 상태이므로 후속 조정 성능은 새 비공개 평가로 표현하지 않는다.

## SHACL과 원문 검증의 역할

SHACL은 선언된 클래스·필수값·수치형·단위·출처 페이지·임계값 순서·명시적 누수 필드를 검사한다. 임계값 순서 검사는 **규칙 설정**을 검사하며 관측이 정상 범위 밖이라는 이유로 데이터를 삭제하지 않는다.

출처 문서와 페이지가 실재해도 내용이 정확히 인용됐다는 뜻은 아니다. 빌더는 원문 PDF 해시, 보정된 표 셀, 연속표, 규칙 원문과 위치를 확인하고 lineage를 남긴다. SHACL 통과만으로 의미적 프록시 누수, 문서 해석, 설치 모델 대응, 원인 추론을 모두 검증했다고 주장하지 않는다.

## 추가 보류 사항

1. 문서의 베어링·모터 언급은 점검/가능 원인 설명이다. 설치된 내부 부품·고장 사실로 자동 승격하지 않는다.
2. `correlatesWith`는 문서 근거 사전 관계 한 건을 보존한다. 신규 발견·자동 대칭·인과관계로 확장하지 않는다.
3. authorizedFor 218개를 유지한다. 설비 이상 분석에서 비중이 낮다는 이유로 삭제하지 않으며 권한 기록을 현장 자격·교육 이수로 해석하지 않는다.
4. 센서 전체 211,200행은 원본 값을 유지한다. RDF 관측 22개는 스키마 확인 표본이며 전체 시계열을 대표하는 탐지 결과가 아니다.
5. Rule 24개는 문서 표 22행과 수동 원문 예제 2개다. LLM 추출 결과나 86건 평가 완료로 보고하지 않는다.
