# 최종 비교 평가 계획 v1

2026-10-28. 사용자 위임에 따라 프로젝트 평가 절차를 정리했다. 팀원 전원의 합의나 독립 전문가 인증을 의미하지 않는다. **이번 작업은 계획과 기준 파일의 해시 고정이며 실제 평가/API 실행은 없다.**

## 1. 평가 목적과 기본 방침

같은 생성 모델에서 자료 접근 방식에 따라 제조 문서 QA의 내용·출처·충실성이 어떻게 달라지는지 비교한다. 온톨로지 자동 발명, 새로운 인과 법칙, 실시간 이상 탐지·설비 제어 성능을 이 평가로 주장하지 않는다.

우선 기존 저장 결과를 정리한다. 이미 실행한 결과만으로 최종 보고서 작성은 가능하며 비용을 쓰는 재실험은 필수가 아니다. 새로운 실행을 선택할 경우 아래 조건을 지키고 별도 실행 폴더를 사용한다. 이전 답변을 덮어쓰지 않는다.

## 2. 평가 집합과 표현

| 집합 | 용도 | 보고 방식 |
|---|---|---|
| 기존 dev 6문항 | 설정·오류 점검 | 개발 결과로 별도 집계 |
| 기존 eval 24문항 | 세 방식의 주 비교 | 이미 본 문항의 개발 재시험, 독립 미노출 평가 아님 |
| 온톨로지 진단 8문항 및 Agent 대표 사례 | 기능·실패 분석 | QA 24문항 점수와 합산하지 않음 |
| 선택적인 신규 문항 | 확장 평가 | 작성·원문 검토·정답 격리·해시 고정 후 실행. 아직 문항·개수 미확정 |

현재 계획의 기본 분모는 eval 24다. 신규 문항이 필요하면 별도 버전의 질문·정답·필수 근거를 만들고 답변 생성 전에 고정한다. 같은 자료·기존 정답을 본 개발자가 만든 새 문항을 강한 의미의 독립 미노출 자료라고 부르지 않는다. 새 질문을 만들었다는 이유로 기존 86건 정답 노출 이력이 사라지지 않는다.

## 3. 비교 시스템

| 시스템 | 모델 입력 근거 | 고정 사항 |
|---|---|---|
| LLM 단독 | 질문만, 문서·KG 없음 | 공통 답변 지침과 생성 설정 |
| Vector RAG | 기존 벡터 검색 원문 | 기존 인덱스·top_k=8·최대 근거 4,000토큰 |
| GraphRAG v2 | 기존 v2 검색의 원문·그래프 카드 | 예원 v2 KG·기존 retrieval_policy, 최대 근거 4,000토큰 |

생성 모델은 현재 설정의 `gpt-6.1-sol`, 답변 출력 상한 4,096토큰, temperature·seed 미지정 정책을 유지한다. 원문 7개·86청크, 임베딩 설정은 기존 구성과 같다. 모델을 바꾸면 새 비교 버전으로 세 시스템 모두 다시 구성한다. 특정 시스템만 유리한 설정으로 바꾸지 않는다.

세 방식은 **동일 질문·공통 system 지침·같은 채점표**를 사용한다. 각 검색 방식의 기존 정책은 유지하므로 근거 내용이나 개수가 완전히 같지는 않다. 최대 예산을 맞췄다고 실제 입력 토큰 수까지 같다고 주장하지 않는다.

자동 분류·후보 목록을 사용하는 Agent는 주 QA 비교에서 제외한다. 기존 GraphRAG QA 경로를 사용하여 검색 방식과 Agent 라우팅 효과를 섞지 않는다. Agent의 분류·선택 요청·실패 중단은 별도 기능 검증 표로 보고한다.

정답 이벤트 14건의 `gold_event_demo` 그래프, 정답표, 채점 메모, 과거 모델 답변은 검색·생성 입력에서 제외한다. 기존 기준선의 파일 검사용 scoring_lock 접근과 정답 내용 접근은 구분한다. 자료 접근이 다른 LLM 단독은 근거 점수가 불리하므로 총점만으로 모델 능력의 우열을 주장하지 않는다.

## 4. 채점 — 기존 기준 유지

[기존 QA 채점 기준](benchmark_yewon_v2_20261023/채점기준_확정_v1.md)을 그대로 적용한다.

- 내용: 필수 요소 3개, 각 0/1점.
- 근거: 올바르게 인용·연결한 필수 근거 단위 비율, 0~1점.
- 충실성: 질문 관련 원문 왜곡·무근거 단정이 없으면 1점.
- 총점: 5점. 완전 정답은 세 내용 요소·전체 근거·충실성을 모두 충족한 경우.
- 빈 답변·실행 실패는 기존 기준대로 0점 및 실패 기록. 정답표 자체가 불명확하면 판정보류하며 모델별 예외를 만들지 않는다.
- 한국어 지침 준수는 별도 지표로 기록한다. 기존 기준의 언어 의미 인정 규칙을 사후에 바꿔 추가 감점하지 않는다.

주 지표는 eval 평균 총점(/5), 완전 정답률이다. 내용 충족률·근거 충족률·충실성 비율·실행 실패율과 유형별 결과도 함께 보고한다. 추출 F1_content, 탐지 F1, QA 점수는 합치지 않는다.

## 5. 비용·속도·답변 유보

각 실행에서 요청/반환 모델, 입력·출력·임베딩 토큰, 캐시 적중, 단계별 경과 시간, 최종 상태를 저장한다. 캐시 응답의 과거 토큰을 신규 API 사용량에 중복 합산하지 않는다. 달러 비용은 실제 청구 또는 실행 당시 공식 단가와 계산 가정을 밝혀 산출하고, 토큰 수를 달러로 임의 변환하지 않는다.

속도는 첫 실행/캐시 재생을 분리하고 성공 건의 중앙값·범위와 실패 수를 제시한다. 서로 다른 날짜·네트워크·캐시 조건의 기존 기록으로 엄밀한 속도 우열을 주장하지 않는다. 신규 실행 시 문항별 시스템 실행 순서를 순환시키고 동시 실행하지 않아 경쟁 부하를 줄인다.

답변 유보는 무조건 정답 처리하지 않는다. 사전 정답표상 답할 수 없는 문항에서 한계와 이유를 올바르게 설명했는지, 답할 수 있는 문항에서 부당하게 유보했는지 나누어 수와 분모를 보고한다.

## 6. 실행 통제 및 채점 절차

1. 팀 인수 체크리스트를 확인하고 실행 담당·채점 담당을 기록한다.
2. 실행 전 질문·정답표·원문·KG·검색 정책·생성 설정·코드 해시를 점검한다. 이번 계획의 manifest는 현재 파일을 기록한 것이며 미래 결과를 인증하지 않는다.
3. 실행을 선택하면 질문당 시스템별 1회 답변을 수집한다. 자동 재시도·답변 골라내기를 하지 않는다. 기술적 오류를 수정하면 원실패를 보존하고 새 실행 버전을 명시한다.
4. 생성 프로세스는 질문·허용 근거만 사용한다. 평가 정답은 별도 후처리에서 읽는다. 요청 원문과 검색 경로를 보존한다.
5. 채점 시 시스템 이름을 익명 코드로 바꾸고 동일 정답 요소·원문으로 대조한다. 답변 스타일로 시스템을 짐작할 수 있으므로 완전한 맹검을 주장하지 않는다.
6. AI 채점을 쓰면 reviewer에 명시한다. 독립 인간 검토가 없으면 AI 단독 결과로 보고한다. 가능한 별도 검토자는 불일치·무근거·시간 경계 사례를 재검토한다.
7. 판정보류가 있으면 최종 점수 확정을 보류한다. 임시 점수는 동일 문항 집합·실제 분모·제외 사유를 공개한다. 시스템 실패는 임의 제외하지 않는다.
8. QA 오류를 검색 누락, 내용 해석, 숫자·조건, 출처, 무근거 주장, 실행 실패로 분류한다. 온톨로지 부족은 원문·검색·표현을 대조한 근거가 있을 때만 별도 분류한다.

예산 미확정 상태에서는 새 유료 실행을 시작하지 않는다. 기본 계획대로 기존 결과를 사용하면 새 생성 비용은 없다. 신규 24문항 세 방식 전량 재시험은 최대 72개 답변이 필요하므로 실제 시작 전에 별도 실행 범위·예산을 확정한다.

## 7. 최종 보고와 완료 조건

보고 표는 시스템별 질문 수, 평균/총점, 완전 정답 수, 내용·근거·충실성, 실패 수, 유보 분류, 신규 토큰·캐시 여부·속도 측정 범위로 구성한다. 기존 결과를 사용하면 각 결과의 실행일·코드·검색 버전·채점 방식 차이를 함께 표시한다. GraphRAG 개선 전후의 개발 효과를 통계적 우월성이나 순수 그래프 인과 효과로 확대하지 않는다.

평가 완료 조건: 선택한 질문 집합의 세 방식 결과와 채점 근거가 모두 있고, 판정보류가 해소됐으며, 비용/실패/노출 이력과 버전이 기록돼 있어야 한다. 이번에는 **계획만 확정**했다. 팀원 인수·신규 문항 작성·새 평가 실행·팀 합의는 수행하지 않았다.
