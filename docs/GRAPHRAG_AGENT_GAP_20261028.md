# GraphRAG + Agent 단계 요구사항 대조와 남은 작업

최종 진행(2026-10-28): [4단계 전체 점검](../reports/e2e_handoff_20261028_verify.md) 및 [공유 ZIP 추출 실행 검증](../reports/team_bundle_smoke_20261028_verify.md) 완료. 아래 최초 감사·중간 진행 기록은 이력으로 보존한다.

최신 진행(2026-10-28): 2단계 모델 연결·대표 경로·UI 검증을 마쳤고, [3단계 정답 이벤트 별도 시연](../reports/gold_event_demo_20261028_verify.md)을 완료했다. 아래 표는 최초 감사 기록이다. 다음 작업은 4단계 전체 점검·공유 묶음이다.

검토일: 2026-10-28. 원래 일정의 11/1~11/10 항목인 ‘GraphRAG + Agent End-to-End 완성, KG에 정답 이벤트 14건 선투입’을 현재 코드와 저장된 실행 보고서에 대조했다. 이번 작업은 구현 감사와 후속 계획 확정이며 새 답변 생성이나 성능 재평가가 아니다.

후속 진행: 1단계 [도구 계약 v1](AGENT_CONTRACT_V1_20261028.md)을 작성하고 입력·후보 선택 검증 테스트 7개를 통과했다. 아래 표는 최초 감사 당시 상태다. 실제 도구 연결·모델 선택은 아직 미구현이며 다음 작업은 2단계다.

## 1. 결론

**GraphRAG 질의응답과 탐지 후보 설명은 각각 연결돼 있으나, 원래 일정의 GraphRAG + Agent 전체가 완료된 상태는 아니다.** 주요 미완료 항목은 통합 요청 처리, Agent의 도구 선택·실행 기록, 정답 이벤트 14건을 사용하는 별도 시연 경로다.

예원 v2 2,806트리플은 계속 기본 KG로 유지한다. `requiresRuleCheck` 후보는 채택하지 않는다. 새로운 모델 탐색이나 온톨로지 확장은 이 단계의 선행 조건이 아니다.

## 2. 요구사항과 실제 구현

| 항목 | 상태 | 확인 근거 및 남은 범위 |
|---|---|---|
| 새 질문 → 임베딩 → GraphRAG → 답변 | 구현·기존 사례 검증 완료 | `src/imaks_kg/rag/live.py:answer`. KG·설정 해시, 원문·응답·사용량 저장 |
| 문서·규칙 ID, 비교 문서, 출처 경로 검색 | 구현·기존 개발 평가 완료 | `src/imaks_kg/rag/graph_v2.py`, 기존 답변 평가 보고서. 미노출 일반화 성능은 아님 |
| 답변·원문·그래프 경로 화면 | 구현·기존 사례 검증 완료 | `src/imaks_kg/rag/demo.py`, `demo.html`. 실제 검색 경로와 모델 사용·인용 여부는 구분 |

| 후보 → 센서·규칙·출처 → 설명 | 구현·기존 대표 사례 검증 완료 | `event_explain.py:prepare/answer`. 전체 93건 검색 준비 검사, 대표 4유형 생성 결과 검토 |
| 사용자 요청에 따른 도구 선택 | 미구현 | 현재 `/api/ask`와 `/api/explain-event`를 화면에서 사용자가 선택. 모델의 도구 선택이나 통합 라우터 없음 |
| 여러 기능의 실행 상태·종료 조건 통합 | 부분 구현 | 각 경로의 성공·실패 기록, 재시도 금지는 있음. 통합 도구 실행 추적·단계 제한은 없음 |
| 근거 부족·충돌 자동 판정 | 미구현 | 주의 문구 및 모델 지침은 있지만 독립 판정기가 아님. 현재 자료만으로 전면 자동 판정을 약속하지 않음 |
| 정답 이벤트 14건 선투입 | 미완료 | 현재 기본 v2에서 제외됨. 탐지 후보 93건으로 대체할 수 없음 |
| 통합 Agent E2E 검증 | 미완료 | 개별 QA·후보 설명 검증과 구분해 통합 경로 검증 필요 |
| 팀원이 재현할 수 있는 자료 묶음 | 부분 완료 | 코드·안내는 있으나 인덱스·원문·KG 등 로컬 제외 자료 필요. 새 clone만으로 실행되지 않음 |

실시간 설비 연결과 자동 조치 실행은 원래 일정에 명시되지 않았고 현재 프로젝트 목표에 필수로 추가하지 않는다. 문서에 있는 조치 안내와 실제 조치 실행을 구분하면 된다. 기존 초기 문서의 인과관계 발굴·원인 확률 점수 제안은 이후 확정한 v2 중심 범위와 다르므로, 이를 현재 완료 요구사항이나 검증된 기능으로 인용하지 않는다.

## 3. 제안하는 최소 Agent 범위

사용자 요청을 받아 **문서 검색, 저장된 탐지 후보 조회, 선택 후보 근거 조회** 중 필요한 도구를 선택하고, 도구가 반환한 사실과 원문으로 설명하는 제한된 도구 사용 Agent를 제안한다. 이는 이번 감사에서 제안하는 구현 범위이며 팀이 처음부터 확정했던 상세 명세는 아니다.

- 문서 질문은 기존 v2 검색을 재사용한다.
- 후보 조회는 센서·규칙 ID 등 명시적 필터로 저장된 후보를 찾는다. 새 이상을 추측하거나 확정하지 않는다.
- 후보가 하나로 정해지면 기존 `event_explain.prepare`의 근거 구성을 재사용한다. 여러 개면 선택을 요청하고 임의로 하나를 고르지 않는다.
- 답변 생성은 근거 조회 후 수행한다. 기존 `answer` 함수를 도구로 반복 호출해 불필요하게 생성 비용을 늘리지 않는다.
- 도구 선택·입력·결과·종료 이유를 기록하고, 도구 호출 상한·생성 예산·실패 중단 규칙을 고정한다.
- 현재 상태나 실제 조치 이력처럼 없는 정보는 확인 불가로 처리한다.

비용 없는 규칙 기반 라우터만 구현한다면 ‘통합 워크플로’라고 표기한다. 모델이 도구를 선택하는 기능 없이 자율 Agent가 완성됐다고 표현하지 않는다. 반복적 계획·자기수정이나 범용 자율 행동은 이번 최소 범위에 필요하지 않다.

## 4. 실행 순서와 완료 조건

### 1단계 — 통합 입출력과 도구 계약 고정

문서 질문, 후보 목록 조회, 후보 설명, 정보 부족의 네 요청 유형을 정의한다. 도구 입력은 허용된 ID·필터로 제한하고 출력은 관측값·규칙·출처·한계·실행 추적으로 통일한다. 잘못된 ID와 모호한 후보를 처리하는 정책을 정한다.

완료 조건: 도구 명세와 예제 입력·출력, 비용·호출 상한, 오류·명확화 처리 기준이 문서와 로컬 테스트에 고정된다. API 없이 진행할 수 있다.

### 2단계 — 기존 기능을 통합 도구로 연결

기존 검색 및 후보 준비 함수를 재사용하는 어댑터와 실행기를 만든다. 먼저 가짜 모델 응답으로 도구 선택·검증·호출 한도·실패 종료를 테스트한다. 그 다음 모델의 제한된 도구 선택을 연결한다.

완료 조건: 문서 조회, 후보 필터 조회, 후보 설명의 각 경로와 잘못된 입력·모호성·근거 없음 경로가 기록을 남기며 종료된다. 기본 v2와 보존된 평가 자료는 변하지 않는다. 실제 모델 선택·생성 확인에는 API 비용이 발생하므로 로컬 검증과 구분한다.

### 3단계 — 정답 이벤트 14건 전용 시연 경로

원래 일정의 항목을 유지한다면 원본 이벤트의 필드·출처·센서 연결을 확인한 후 **별도 시연용 그래프와 실행 모드**로 적재한다. 예원 v2 파일 자체는 수정하지 않는다. 14건을 정확히 식별할 수 있는지, 원본에 없는 원인·조치 필드를 만들어 넣지 않았는지 검사한다.

완료 조건: 원본 이벤트 14건과 적재된 개체의 대응표·출처·무결성 검사가 있고, 화면과 실행 기록에 ‘정답 이벤트를 제공받은 시연’이 표시된다. 일반 QA·탐지 평가 경로에서 해당 그래프를 읽지 않는 격리 검사도 통과해야 한다.

정답을 넣은 뒤 그 정답을 찾아 설명하는 시연은 가능하지만 독립 탐지 성능 검증이 아니다. 이 분리를 원하지 않는다면 팀 일정에서 14건 선투입을 제외하는 범위 변경을 명시해야 하며, 조용히 완료 처리하지 않는다.

### 4단계 — 통합 E2E 검증과 공유 묶음

단일 문서 규칙, 여러 문서 비교, 특정 후보 설명, 복수 후보 선택, 없는 현재 상태, 잘못된 ID, 도구 실패, 정답 시연/일반 경로 분리를 대표 사례로 검증한다.

완료 조건: 사전 기대 경로와 실제 도구 추적, 인용 원문, 답변 내용, 종료 이유, 사용량이 저장되고 기존 QA·후보 설명 기능에 회귀가 없는지 확인한다. 기능 검증 결과를 독립 정확도 점수로 보고하지 않는다. 팀 공유용 실행 안내와 필요한 로컬 파일 목록·해시도 함께 제공한다.

## 5. 병행 관리할 기존 한계

- 진단 OD-08의 일본어 출력은 생성 지침 준수 문제다. 통합 출력 검사 대상으로 기록하되 자동 재생성으로 무조건 숨기지 않는다.
- STUCK의 동일값 11표본 가정은 문서별 정의와 대조가 더 필요하다. 현재 후보의 설명에는 가정을 유지해서 표시하고, 탐지 로직을 바꿀 경우 별도 버전과 재검증을 사용한다.
- 독립적인 문서 충돌 판정기는 현재 없다. 서로 다른 조건·적용 범위를 보여주는 기능과 실제 모순 판정을 구분한다.
- 도메인 전문가 검증, 새로운 인과관계 발견, 미노출 성능 검증은 이번 최소 Agent 구현으로 달성되는 항목이 아니다.
