## 파생 신호 참조를 검증한 방법

기존 후처리 코드는 감시 알람으로 승격한 신호를 `signals.json`에서 제거한다. 따라서 `source_signal` ID를 일반 신호 목록에서 찾는 것만으로는 네 알람의 원본을 확인할 수 없었다.

원래 신호에 포함됐던 관측·시각·표본 수·규칙·유형·봉인 sigma를 사용해 내용을 재구성하고, 원래 ID 생성 방식으로 계산한 해시가 기록된 `source_signal`과 정확히 같을 때만 복원으로 인정한다. 시각이나 값이 비슷하다는 이유로 연결하지 않는다. 해시가 다르면 거절한다. 원본 알람이나 신호 파일은 수정하지 않았다.

그 후 원시 시계열로 기울기와 표본 조건을 재계산하고, 원인 후보 사건의 경고 게이트·설정된 감시 시작점·90분 범위·효과 방향을 확인한다. 이는 저장된 승격 정책과 참조를 검증하는 것이며 실제 인과를 확정하지 않는다. 원인 후보 사건의 전체 생성 과정, 사건 묶음과 종료·복구 판정까지 독립 검증한 것은 아니다.

## 설명에 필요했던 추가 출처

파생 감시는 직접 연결된 문서 규칙 외에 SOP-002의 기울기·감시 시간 정의도 필요했다. 문서 의존성을 명시적으로 조회해 각 방식의 두 사건에 필요한 정의 청크를 추가했다. 원문과 실제 KG 출처 간선만 사용한다. 데이터에서 없던 관계를 만들지는 않는다.

새 사건 설명은 이 근거를 모델 컨텍스트에 포함한다. 과거 답변을 무료 재점검할 때는 추가 조회 내역을 `dependency_sources_added_for_recheck`에 따로 기록한다. 과거 모델이 당시에도 새 출처를 받았다고 표현하지 않는다. 원 답변·당시 검색 기록은 그대로 둔다.

## 여전히 구분해야 할 해석

- OUT_OF_RANGE의 실행 IR은 20개 연속 표본이다. 30초 주기에서 첫 표본~20번째 표본은 9분 30초다. 원문의 `>10 min` 설명과 `20+ readings` 기준을 같은 식으로 통일하지 않았다. 검사 통과는 기존 20표본 실행을 재현한다는 뜻이다.
- MAINT-02는 기본 엔진에서 명목값 편차를 30분 이상 유지하는 연산이고, 성호 DRIFT 대안에서는 정확히 30분 전보다 증가한 값이다. 두 해석과 후보 개수는 구분한다.
- 완전 고정과 작은 표준편차는 다른 조건이다. 연속 2점 확인을 붙이면 같은 고정 구간도 더 늦게 발동한다.
- 상관 후보·발동 조건 확인은 고장 원인·조치 수행·현장 안전 인증이 아니다. 모든 자연어 문장, 모든 미발동 시점과 오탐·미탐 성능도 이번 점검 범위가 아니다.

## 재현과 API

기존 런타임 복원 ZIP을 그대로 사용할 수 있다. 새 가중치·임베딩·데이터는 필요하지 않다.

```powershell
python scripts/check_decision_evidence.py
```

결과는 `kg_build/window_evidence_20261114/after.json`에 저장한다. 읽기 전용 서버의 `GET /api/decision-evidence/<실행 ID>`도 새 검사기를 사용한다. `xai.decision_evidence.items[*].trigger_check`에는 연산·계산 값·표본 수·최초 발동 결과가 들어간다. 감시 알람은 원래 기울기 검사와 sigma 검사도 포함한다.

입력 경계·결측 간격·잘못된 참조 해시·잘못된 경고 앵커·미래값 배제와 기존 Agent/API 회귀를 포함한 82개 검사가 모두 통과했다. 네 파생 감시 사례의 설명 경로는 모의 모델로 모두 실행해 필요한 출처와 4,000토큰 제한을 확인했다. 실제 모델의 답변 품질 향상은 이번에 측정하지 않았다.
