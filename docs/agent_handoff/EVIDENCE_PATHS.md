# 주장별 근거 경로·방향·단절 검사

완료일: 2026-11-15. Agent `incident-agent-v4-20261114`, 주장 목록 `incident-claim-binding-v2-20261114`.

UI는 별도 담당이며 이번 작업은 응답 데이터와 검증이다. LLM을 추가 호출하거나 KG에 새 관계를 쓰지 않았다. 기존 사건·문서·답변·점수와 복원 ZIP도 유지했다.

## 반환하는 경로

각 주장에 `evidence_paths`를 붙인다. `status`, 연결된 `paths`, 끊긴 `breaks`를 제공한다. 주장 종류에 따라 필요한 끝점이 다르다.

| 주장 | 확인하는 경로 |
|---|---|
| 관측 | 주장→사건→센서→원본 관측 참조 |
| 조건 | 주장→사건→규칙→출처→원문 + 알람→검사→IR→KG 규칙 연결 |
| 조건부 권고 | 주장→사건→규칙의 저장 필드·문서·출처·원문 |
| 저장 유형 보고 | 주장→사건→봉인된 메타데이터. 실제 유형 정답 확인은 아님 |
| 검증 한계 | `scope_only`. 실제 사실을 입증하는 KG 경로로 표시하지 않음 |

센서–사건 방향은 원본을 보존한다. 기본 엔진은 저장된 `Sensor triggers Event`를 사건에서 센서로 **역방향 조회**한다. 성호 미분류 후보는 저장된 `Candidate observedOnSensor Sensor`를 정방향 조회한다. 출력은 `traversal`과 원래 `stored.s/p/o`를 함께 반환한다.

문서와 출처는 규칙에서 갈라지는 실제 두 가지 관계다. 주 경로는 `Rule → hasProvenance → Provenance → 원문 청크`이고, 문서 관계는 같은 Rule에서 시작하는 `sourceDocument` 분기로 표시한다. 없는 `Document → Provenance` 간선을 만들지 않는다.

## 세 종류의 단계

| `kind` | 의미 | 검사 |
|---|---|---|
| `rdf` | 실제 저장 KG·사건 오버레이 관계 | 현재 메모리 그래프와 고정/봉인 파일의 원래 트리플에 존재, 방향 보존 |
| `runtime_reference` | 주장·사건·알람·DEC 검사·IR·파생 신호의 실행 참조 | 봉인 JSON 선택자·파일 해시·검사 보고서 해시·정확한 식별자 조인 |
| `file_lookup` | 센서 관측이나 출처에서 고정 청크로 이어지는 참조 | 이전 관측 검사·봉인 알람과 일치, 문서·쪽·해시·위치 및 인용 확인 |

모든 주 경로에서 앞 단계의 `to`와 다음 단계의 `from`이 같아야 한다. 분기는 주 경로에 실제로 나타나는 노드에 붙어야 한다. 실행 참조나 파일 참조를 RDF 간선으로 바꾸지 않는다. 파생 감시의 신호는 기존 정확 해시 복원 검사에 연결하고, 원래 기울기 IR·감시 규칙·시간 정의를 서로 구분해 연결한다.

## 원문 위치 검사 범위

- 문서 ID·원본 파일 해시·쪽·인용문 해시·청크 텍스트 해시를 함께 확인한다.
- 표는 `tableId`, 헤더를 포함한 `rowIndex`, 실제 데이터 행, 인용문을 대조한다.
- `colIndex`는 저장된 메타데이터로 보존하며 `column_check=recorded_metadata_only`로 표시한다. PDF 원본의 실제 열을 시각 검증한 결과는 아니다.
- 문자 범위가 인용문과 정확히 같으면 `exact_quote_span`, 인용을 포함하는 상위 청크 범위이면 `enclosing_chunk_span`으로 표시한다. 상위 청크 범위를 정확한 인용 시작·끝이라고 표현하지 않는다.
- 정규화된 표 행과 고정 추출 텍스트를 검사하는 것이며, 원본 PDF의 모든 문자 배치·연속 원문 문장이나 규칙 의미의 참거짓을 새로 인증한 것은 아니다.

## 단절 처리

`complete`는 해당 주장에 필요한 선언된 참조가 이어짐, `scope_only`는 검증 한계 표현, `broken`은 필요한 연결이나 메타데이터가 맞지 않음이다. `breaks`에는 `code`, 한국어 `message`, `at_node`, 기대 관계·필드 등의 `detail`을 담는다.

예를 들어 필요한 방향의 간선이 없으면 `missing_stored_relation`, 다른 사건/IR로 연결되면 `different_incident` 또는 `IR_rule_binding_mismatch`, 문서·쪽·해시가 바뀌면 출처 메타데이터 오류를 반환한다. 해시가 맞는 인용문이 존재한다는 이유만으로 사라진 사건–규칙·규칙–출처 간선을 통과시키지 않는다.

단절된 주장은 모델 선택 목록에서 제외한다. 해당 ID를 직접 선택해도 게시를 보류한다. 정상 경로도 사실·인과·현장 안전이나 답변 완전성을 보증하지 않으며 기존 검증 범위를 유지한다.

단절·역방향·문서/출처 누락·잘못된 쪽/표 행/해시·IR 참조·과거 답변 보존과 기존 Agent/API를 회귀 검사했다. 이는 개발 자료의 참조 검증이며 실제 모델의 새로운 답변 성능 평가는 아니다.

전체 회귀 110개 통과 후 오류 메시지·파일 경로 메타데이터와 저장 주장 기록 분기를 보완하여 관련 16개 검사를 다시 통과했다(고유 검사 총 111개). 실제 유료 API 호출 0회다.

```powershell
python scripts/check_claim_paths.py
```

집계와 전체 예제는 로컬 `kg_build/claim_paths_20261115/`에 저장한다. 원문이 포함된 전체 예제는 Git에 넣지 않는다.

## UI 담당자용 API

새 사건 답변의 `claims[*].evidence_paths`와 `xai.claim_path_summary`를 사용한다. `claim_paths.json`에 전체 허용 목록의 경로 기록도 남긴다. `scope_only`를 실제 사실 검증이나 그래프 경로 완료로 표시하지 않는다.

무료 조회: `GET /api/claim-paths/<실행 ID>`.

- 게시된 주장 기록이 있으면 해당 주장들의 참조 경로를 점검한다.
- 과거 자유답변에 주장 기록이 없으면 현재 허용 가능한 목록의 경로를 반환한다. `path_scope`로 이 차이를 표시한다.
- `past_answer_prose_revalidated=false`, 원 답변 SHA-256과 API 호출 0회를 함께 반환한다. 과거 자연어 답변에 새 검증을 소급하지 않는다.

문서 자유답변·정형 KG 조회는 이번 사건 경로 계약의 적용 대상이 아니다. 원본 답변이나 KG를 수정하지 않는다.
