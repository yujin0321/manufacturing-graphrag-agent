# 룰 기반 탐지기와 예원 v2 KG 연결

2026-10-26 실행. 기존 예원 v2 KG와 질의응답 평가 기준선은 유지하고, 과거 센서 데이터의 규칙 일치 후보를 별도 그래프로 저장했다.

## 구현과 실행 결과

- 입력: `preprocessed/sensors/input/ts_input.csv`, 22개 센서, 211,200행, 30초 간격.
- 문서에서 확인한 규칙 25개를 30개 실행 조건으로 작성했다. 상하한, 엄격한 초과/미만, 지속 시간, 11회 동일 값 조건을 처리한다.
- 기존 센서 메타데이터의 경고 임계값 검사 22개도 별도로 실행했다.
- 문서 규칙 후보 43건(train 2 / validation 14 / test 27), 메타데이터 임계값 후보 50건(5 / 12 / 33).
- 후보 93개를 모두 기존 센서 노드에 연결했다. 실행 조건 → 원문 청크와 기존 규칙 노드 연결을 별도 `candidate_events.ttl`에 저장했다(1,116 트리플). 이벤트가 발생한 문서 실행 조건 17개에 기존 규칙 연결이 있다.
- 한 구간이 여러 규칙에 해당할 수 있다. 93건은 중복 제거한 실제 이상치 수가 아니며, 정답 이벤트 14건과 직접 비교하면 안 된다.
- 탐지 실행은 정답 라벨을 읽지 않으며 학습 및 API 호출이 없다. 이번 탐지 산출물은 약 132 KiB이다. 새 모델 설치는 없다.

## 별도 정답 평가

탐지 결과와 입력 해시를 봉인한 뒤 별도 평가 프로세스에서 행 단위 라벨을 대조했다. 다음 점수는 **메타데이터 임계값 검사만**의 결과다. 문서 규칙 전체 성능이나 LLM 추출 F1이 아니다.

| 구간 | TP | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| train | 35 | 0 | 63 | 100.00% | 35.71% | 52.63% |
| validation | 190 | 1 | 118 | 99.48% | 61.69% | 76.15% |
| test | 416 | 0 | 638 | 100.00% | 39.47% | 56.60% |

이는 기존 데이터에 대한 재현 결과이며 새로운 미노출 평가가 아니다. 정답 라벨은 탐지기, 후보 그래프, 시연 화면에 전달하지 않는다. 프로젝트의 과거 정답 노출 이력까지 없어진다는 의미도 아니다.

## 운영상 정의와 미지원 범위

- 경계값은 원문의 `>`와 `<`를 따른다. 5분 초과는 30초 표본에서 최초 5분 30초에 판정한다.
- 표본 누락이나 train/validation/test 경계에서는 지속 상태를 초기화한다.
- STUCK은 11회 정확히 같은 관측값으로 구현했다. 허용 오차를 둔 센서 고착 검출 성능은 검증하지 않았다.
- 점검 기한(예: 5분 이내 점검)을 지속 조건으로 바꾸지 않았다.
- RULE-RND01-02는 절대 습도 기준으로 구현했다. 추세의 기울기를 추정하는 DRIFT 검출이 아니다.
- 작업자 명령, 출입·재실 정보, 설치 제품 매핑이 없는 규칙은 실행하지 않는다. MAINT-01/02/06/08 등의 DRIFT 및 통계적 SPIKE 정의도 합의 없이 만들지 않았다. 상세 사유는 `rules.json`에 있다.
- 조치 문구는 원문 근거로 표시할 뿐, 실제 조치를 수행하거나 설비 고장을 확정하지 않는다.
- 종료 시각은 사후 마지막 일치 시각이다. 최초 판정 당시 알 수 있었던 미래 정보로 취급하지 않는다.

## 파일과 재현

- 구현: `src/imaks_kg/detection/rules.py`
- 탐지 산출물: `kg_build/rule_detector_20261026/` (`complete.json`으로 해시 검증)
- 평가: `scripts/evaluate_rule_detector.py`, `evaluation/rule_detector_20261026/baseline_row_metrics.json`
- 시연: `python -m imaks_kg.rag.demo --port 8765`, 화면 아래 **탐지 후보와 원문 열기**. 읽기 전용 `/api/detections`는 봉인된 산출물만 제공한다.

저장소에서 `PYTHONPATH=src`로 설정하고 기존 가상환경 Python을 사용한다. 탐지 재실행 명령은 `python -m imaks_kg.detection.rules --out <새 결과 폴더>`다. 기존 결과 폴더는 덮어쓰지 않는다. 평가 스크립트는 현재 고정 결과를 대상으로 하므로 새 버전 평가에는 경로 변경과 별도 결과 폴더가 필요하다.

## 프로젝트 위치

검증: 탐지 단위 테스트 7개와 시연 서버 테스트 4개 통과. 서버 테스트 최초 실행에서 Windows 연결 중단 1회가 있었고 재실행에서 전부 통과했다. 기존 기준선 699개 파일 해시가 동일함을 확인했다. 브라우저에서 후보 93건 표시와 RULE-ST02-01의 최초 판정 값 212.8202°C, 시각, 원문 청크 연결을 확인했다. 화면 기록은 `reports/rule_detector_demo_20261026.png`이다.

룰 기반 탐지기의 재현 가능한 기준 구현과 시연 연결을 완료했다. 모든 문서 규칙을 지원하거나 실운영 검증을 완료한 것은 아니다. 기존 GraphRAG 답변 컨텍스트에는 이번 이벤트를 자동 투입하지 않았다. 다음 확장은 사용자가 특정 후보를 선택했을 때 해당 센서 값·규칙·근거로 설명하는 흐름이며, 기존 문서 QA 성능과 구분해 검증해야 한다.
