# 탐지 후보 설명 기능 — 유형별 후속 검증

2026-10-26. 이전 지속 시간 사례 1건에 단순 임계값, STUCK, 메타데이터 사례를 추가했다. 기존 탐지 결과와 그래프를 변경하지 않고 현재 설명 기능을 실행했다.

## 1. 전체 후보 검색 준비 검사

93건 전체에 대해 봉인된 탐지 산출물, 원문 해시, 기존 KG 노드 연결, 원문 청크 선택, 컨텍스트 한도를 검사했다.

- 문서 규칙 후보 43건: 각 실행 규칙에 지정된 원문 청크가 컨텍스트에 포함된다.
- 메타데이터 후보 50건: 문서 청크를 임의로 추가하지 않는다.
- 전부 4,000토큰 컨텍스트 예산 이내이며, 최댓값은 1,443토큰이다.
- 추가 API 호출은 없다.
- 기록: `evaluation/event_explanation_20261026/retrieval_audit.json`

이는 입력 및 검색 경로 검사다. 답변 생성이나 93건 전체의 의미적 정확도를 평가한 결과는 아니다.

## 2. 실제 답변 검토

기존 1건과 이번 3건의 실제 응답을 후보 기록·실행 규칙·원문과 대조했다. 아래 검토 항목에서 불일치는 발견하지 못했다.

| 유형 | 확인한 사실 | 답변의 근거와 한계 처리 |
|---|---|---|
| 지속 시간: MAINT-05 | 26.9452°C, 12:00:00 시작 → 12:05:30 최초 판정. 25°C 초과가 5분 초과 지속 | SOP-003 인용. 보조 냉각 가동은 문서상 조치이며 실행 여부는 모른다고 구분 |
| 범위 이탈: RULE-ST02-01 | 212.8202°C, 허용 범위 175–195°C, 상한 대비 17.8202°C 초과 | SOP-001 해당 규칙 인용. 해당 청크에 구체적 정지·점검 절차가 없어 만들어내지 않음 |
| STUCK: MAINT-03 | 2.2613 N, 09:30:00 시작 → 09:35:00 최초 판정. 같은 값 11개는 30초 간격에서 5분 | 5분 초과 조건과 구분. 값 자체의 범위 이탈이 아님을 설명. 센서 교체는 문서상 조치이며 고장 확정은 아님 |
| 메타데이터: ST02 온도 | 212.8202°C, warnLo 175.0 / warnHi 195.0 | CSV 출처 표시. 문서 청크가 없어 문서상 조치를 제시할 수 없다고 설명 |

네 답변 모두 최초 판정 시점과 사후 구간 통계를 구분하고, 과거 규칙 일치 후보를 실시간 상태나 조치 완료로 표현하지 않았다. STUCK은 정확히 같은 값이라는 구현 가정도 밝혔다.

검토는 개발 과정의 **AI 단독·비맹검 원문 대조**다. 외부 전문가 검토, 독립 평가 또는 전체 답변 정확도 점수가 아니다. 따라서 `4/4 정확도 100%`라는 벤치마크 성능으로 보고하지 않는다. 이번에 정답 라벨을 입력하지 않았다는 사실이 프로젝트의 과거 정답 노출 이력을 없애는 것도 아니다.

## 4. 활용과 남은 범위

시연 화면의 저장된 결과 목록에서 위 네 사례를 비용 없이 다시 볼 수 있다. 이미 열어둔 화면은 새로고침하면 목록이 갱신된다. 네 유형을 대표 시연 사례로 사용할 수 있다.

현재 완료 범위는 센서 관측 → 규칙 일치 후보 → 그래프의 센서·규칙·출처 조회 → 근거 기반 설명이다. 실시간 설비 연동, 미지원 규칙 판정, 자동 조치 실행, 도메인 전문가 검증은 포함하지 않는다. 다음에는 이 흐름과 한계를 프로젝트 구현 문서·시연 대본에 정리하고, 성능 주장은 기존 비교 평가와 이번 기능 검증을 구분해 제시하면 된다.
