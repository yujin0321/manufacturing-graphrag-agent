# 팀 공유용: iMAKS 전처리·Ontology·SHACL 수행 정리

2026-10-06. 프로젝트: **제조 공정 지식그래프와 Graph RAG 기반 설비 이상 분석 AI Agent**.

사용자가 채택한 주 분석 설정은 **평균 10개 / STUCK 11개 / stride 1개**, 원본 관측 간격은 **30초**다. 2/10/2는 검증 탐색의 선택 이력과 비교 결과로 남긴다. 10/11/1은 기존 평가 결과와 사건 중심 분석 목적을 참고해 채택했으며, 새로운 독립 평가에서 최적임을 입증한 설정은 아니다.

이 문서는 앞서 제시한 ‘공통 전처리 / 각자 구현 작업’ 표와 ‘추가 과제 / 최소 제출물’ 표에 맞춘 설명이다. 아래의 완료는 실제 파일 생성·실행·검증을 확인한 범위를 뜻한다.

### 센서: 무엇을 왜 계산했는가?

**정규화**는 각 센서가 자신의 평소 상태에서 얼마나 벗어났는지 나타내는 작업이다. 온도와 진동처럼 단위·수치 크기가 다른 센서에 같은 원시 숫자 기준을 적용하지 않도록 센서별 학습 기준을 사용했다.

```text
z = (관측값 - 학습 구간 중앙값) / max(1.4826 × MAD, 1e-8)
MAD = 학습값과 학습 중앙값의 차이 절댓값들의 중앙값
```

학습 47,520행으로만 기준을 계산했다. 검증·평가 데이터로 기준을 다시 맞추지 않았고, 정답을 읽어 학습 중 정상 행만 골라내지도 않았다. 원본 value와 정규화 value_z를 함께 보존했다. 현재 모델은 이 기준을 사용하는 강건 통계 탐지기이며, 별도의 지도학습 모델을 학습한 것은 아니다.

**윈도우**는 과거와 현재의 연속 관측을 묶는 것이다.

| 설정 | 실제 사용 관측 | 첫 관측~마지막 관측의 시간 차이 | 목적 |
|---|---|---:|---|
| 평균10 | 현재값 + 과거9개 | 270초 = 4분30초 | 순간값뿐 아니라 지속적인 수준 변화를 확인 |
| STUCK11 | 현재값 + 과거10개 | 300초 = 5분 | 최근 값들이 거의 변하지 않는지 확인 |
| stride1 | 관측이 추가될 때 한 칸 이동 | 30초마다 판정 | 새 관측마다 최근 구간을 다시 확인 |

평균10을 ‘10분 평균’이라고 부르면 안 된다. 10개 관측의 명목 길이를 5분이라고 적을 수 있지만, 실제 첫~끝 시각 차이는 4분30초이므로 두 정의를 구분했다. STUCK11은 통계 윈도우이며, SOP 문장의 연속 샘플 조건을 완전히 구현했다는 뜻은 아니다.

센서·시간 공백·학습/검증/평가 경계에서 윈도우를 초기화했다. 미래값과 다른 센서값을 끌어오지 않았다. 평균10 준비 전594행, STUCK11까지 포함한 특징 준비 전660행은 NaN으로 남겼다. 특징이 모두 준비된210,540행을 별도 저장했지만, 탐지 평가는 전체211,200행을 사용했다.

**특징 계산**에서는 정규화값·편차 절댓값, 직전 변화량과 분당 변화율, 최근10개 평균·표준편차·최소·최대·범위·끝−처음 변화량·변화율 등을 raw/z 두 기준으로 계산했다. 시점별 숫자 특징은21개이며, 10관측 배열에 대응하는 특징20개와 STUCK11 표준편차를 구분했다.

예를 들어 ST02 온도가185.9012°C에서185.0552°C로 바뀌었다면 변화량은−0.846°C이고, 30초=0.5분이므로 변화율은−1.692°C/분이다.

현재 탐지 판정은 아래 세 분기 중 하나가 참이면 이상으로 표시한다.

- 순간 편차 절댓값 `z_abs > 6`.
- 평균10 편차 절댓값 `abs(mean_z) > 4`.
- 최근11개 원본 값의 표준편차가 `0.001 × max(abs(학습 중앙값), 1e-8)`보다 작은 STUCK 플래그.

추가 변화량·최소·최대 등은 후속 모델용으로 준비했다. 21개 특징을 모두 현재 모델 학습에 넣었다고 설명하면 안 된다. 평균은 파생 특징으로 계산했고, 원본 관측을 평균값으로 교체하지 않았다.

### 문서: 청킹·임베딩·LLM 추출 입력은 서로 다른 작업

| 작업 | 실제 수행 | 쉬운 설명 |
|---|---|---|
| 청킹 | 본문18 + 규칙28 + 표24 = 70청크. 본문 최대1000자/겹침200자. 규칙 블록과 표 제목·헤더·단위·조건 보존 | 긴 문서를 검색 가능한 조각으로 나눔 |
| 원문 연결 | 문서ID·페이지·문자 위치·줄·표ID/행·bbox와 원문 PDF 해시 기록 | 답변 근거를 실제 원문에서 다시 찾을 수 있게 함 |
| 임베딩 | 캐시된 다국어 MiniLM으로70×384 벡터 생성. 벡터 길이 정규화·유한값·입력 토큰 길이 검증 | 의미가 비슷한 문장을 검색할 숫자 표현으로 변환 |
| LLM 입력 | 원문·출처·허용 클래스/관계·출력 형식을 넣은 JSONL70건 생성 | LLM이 읽고 구조화할 요청을 준비 |

기존64청크는 초기 프로토타입이다. 이번70청크는 같은 데이터셋을 공통 문서ID·표 복원·규칙 보존 정책으로 다시 나눈 결과다. 입력480토큰 예산으로 모델 잘림을 막았으며 실제 최대는395토큰이었다.

**LLM을 호출해 개체·관계·규칙을 추출한 단계는 아직 아니다.** 임베딩 생성 완료와 LLM 추출 완료를 구분한다. PDF의 지시 문장은 분석할 자료이며, 이 작업을 수행하는 에이전트에게 내린 명령으로 취급하지 않았다.

### KG: 스키마와 데이터를 연결하고 문서 근거를 추가

원본 Component9개는 모터·베어링이 아니라 스테이션 수준이므로 Station으로 매핑했다. ID와 원본 타입 기록은 남겼다. 내부 부품이나 실제 품질불량 자료가 없어서 설치 부품·불량 사례를 만들어 넣지 않았다.

| 구성 | 수행 결과 |
|---|---|
| 스키마 | 클래스12개·객체 관계12개·데이터 속성34개 |
| 원본 정적 구조 | 83노드·269관계 유지 |
| 문서/규칙 | Document7개·Rule24개 추가. Rule은 SOP 표22개와 원문 수동 예제2개 |
| 새 관계 | 스테이션→구역9개, 규칙→문서24개, 규칙→적용 센서24개, 규칙→조치 대상3개, 규칙→추가 확인 센서1개: 합계61개 |
| RDF | ML 메타데이터와 문서/룰 맥락을 구분한2개 그래프 생성·검증 |
| Neo4j 적재 파일 | 기존83+Document7+Rule24 = 114노드, 기존269+신규61 = 330관계. CSV와 Cypher 생성 |

예를 들어 `RULE-ST02-02 → appliesToSensor → ST02 온도 센서`, `RULE-ST02-02 → sourceDocument → SOP-001`, `RULE-ST02-02 → actionTarget → ST03`처럼 연결했다. 조치 대상 관계는 문서의 권장 대상이며, 실제 조치가 수행됐다는 뜻이 아니다.

RDF에는 속성과 출처도 triple로 저장하므로2,413/3,056 triple 수를 Neo4j330관계와 직접 비교하면 안 된다. RDF의 Observation22개는 형식 확인용 예제이며 전체 시계열을 KG에 적재한 결과는 아니다. Neo4j CSV에는 중복ID와 연결 대상 없는 관계가0개였고 RDF 관계와의 대응을 확인했다. 실제 DB 적재, 검출 경보의 KG 연결, 새 KG의 GraphRAG 연결은 남아 있다.

## 2. 설정 선택과 시계열 평가

| 구간 | 행 수 | 정답 사건 수 | 역할 |
|---|---:|---:|---|
| 학습: 1/6 | 47,520 | 2 | 센서별 중앙값·MAD 계산 |
| 검증: 1/7 | 63,360 | 4 | 기존 임계값·윈도우 개발/선택 |
| 평가: 1/8~1/9 | 100,320 | 8 | 고정 설정의 성능 대조 |

정답 행은 sensor_id+timestamp로 일대일 연결했다. 사건은 같은 센서에서 예측 경보와 정답 기간이 겹치는지 확인하고 일대일로 매칭했다. 정답은 특징·판정 계산에 넣지 않았다.

평균2~120 × STUCK2~120 × stride1~10의141,610개 조합을 탐색해 검증 기준으로2/10/2를 선택했다. 2/11/2와 최고 지표가 같았고 작은 STUCK 길이를 고르는 규칙으로10을 선택했다. 이후2/10/2와10/11/1을 같은 학습·검증·평가 데이터로 다시 계산하고 전체 행 예측과 지표의 재현을 확인했다.

| 평가 구간 지표 | 주 분석10/11/1 | 비교2/10/2 | 원본 임계값 룰 기준선 |
|---|---:|---:|---:|
| 사건 탐지 | 8/8 | 8/8 | 7/8 |
| 경보 이벤트 | 11 | 17 | 33 |
| 같은 이상에 대한 추가 경보 조각 | 3 | 9 | 26 |
| 순수 오경보 이벤트 | 0 | 0 | 0 |
| 이벤트 F1 | 84.21% | 64.00% | 34.15% |
| 행 F1 | 81.01% | 83.81% | 56.60% |
| 정상 행을 이상으로 판정 | 52 | 8 | 0 |
| 평균 탐지 지연 | 17.94분 | 13.25분 | 29.21분 |

10/11/1은 사건별 KG·SOP 연결에 앞서 같은 이상이 여러 경보로 쪼개지는 현상이 적었다. 이 프로젝트 목적을 고려해 주 분석 설정으로 채택했다. GraphRAG 답변 정확도의 향상까지 입증한 결과는 아니다. 2/10/2는 행 F1과 탐지 속도가 더 좋다. 특히10/11/1의 최대 지연은75.5분이므로 긴급 대응을 이 탐지기 하나에 맡기는 구조는 적절하지 않다. 별도 임계값 룰 경로를 보존했지만 실제 실시간 긴급 대응 Agent를 구현한 것은 아니다.

8/8은 사건을 한 번씩 탐지했다는 뜻이다. 모든 이상 시점을 맞혔다는 뜻은 아니다. 주 설정의 행 재현율은71.44%이고 놓친 이상행은301개다. 순수 오경보 이벤트0개도 정상 행 오판정0개를 뜻하지 않는다.

이 평가는 이미 사용했던 데이터의 재비교다. 검증에는 SPIKE·CORRELATED가 없고 평가에는 STUCK이 없다. STUCK10/11의 일반화 우열이나 새로운 공장의 성능을 확정할 수 없다.

| ST02 온도212°C라는 가정에서 조치·대상·문서 근거는? | TMP 임계값, RULE-ST02-02, actionTarget/sourceDocument | 가정한 수치의 문서상 대응 조회 |
| ST02 전류 SOP 임계값과 데이터시트 연속 사양의 차이는? | SOP-002 표, 전류 데이터시트 Note2, 출처 | 비교 가능. 실제 설치 모델 적합성은 자료 부족으로 보류 |
| P043의 Chemical Storage 권한 기록만으로 현재 입장이 가능한가? | authorizedFor, SOP-004 권한표, SOP-001 교육 조건 | 기록 조회 가능. 교육 이수·최종 입장 허용은 판정 보류 |

질문 정의는 KG에 넣을 데이터와 답변의 범위를 정하는 작업이다. 이번5개 조회 성공을 LLM 답변 정확도100%라고 보고하지 않는다.

### Ontology를 설명하는 핵심 예

클래스는 대상의 종류, 관계는 대상 간 연결, 속성은 대상의 구체적인 값이다. 예를 들어 Sensor라는 종류에 ST02 온도 센서가 속하고, Station이 hasSensor로 해당 센서를 연결하며, 센서는 unit=°C를 갖는다. Rule은 조건·조치·페이지·인용문을 가지고 sourceDocument로 SOP에 연결된다.

12개 클래스는 System, Zone, Station, Sensor, Person, Document, Rule, ThresholdRule, Observation, InputGraph, InternalComponent, QualityDefect다. 마지막 두 클래스는 확장 후보이며 현재 인스턴스는0개다. 각 관계12개와 속성34개의 전체 이름·의미·예시는 schema_tables.md에 있다.

### SHACL 핵심5개와 실제 예제

| 제약 | 검사 내용 | 통과 예 | 실패 예 |
|---|---|---|---|
| C1 센서 정합성 | ID·종류·단위·소속이 존재하고 맞는가 | TMP/°C와 Station 소속 존재 | unit 누락 |
| C2 관측 정합성 | 센서·시각·유한 수치·단위가 맞는가 | 큰 유한 이상값도 형식·단위가 맞으면 통과 | TMP 관측 단위를 A로 기재 |
| C3 문서 근거 | 출처·페이지·인용·조건·조치가 있는가 | 실제 SOP-001 p.1을 기록 | 2쪽 문서에 p.99를 기록 |

실제 RDF2개 통과, 통과 예제5개 통과, 실패 예제5개 거부, ML 문서/룰 차단 예제 거부를 확인했다. 관측값이 정상 범위를 벗어났다고 거부하지 않는다. C4는 센서값의 정상 여부가 아니라 규칙 설정의 순서를 검사한다. SHACL은 명시적인 누수 패턴과 구조를 검사하며 의미적 누수가 전혀 없거나 규칙 내용이 완전하다는 증명은 아니다.
