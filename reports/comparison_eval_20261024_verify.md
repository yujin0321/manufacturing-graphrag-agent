## 구현과 비교 조건

- 세 방식 모두 생성 요청/반환 모델 **gpt-6.1-sol**, 동일한 system 지시문과 max_completion_tokens=4,096, temperature/seed 생략, store=false. 모든 문항은 독립 API messages 배열이며 다른 문항의 답변·점수·피드백을 전달하지 않았다.
- LLM 단독은 질문만 제공하고 참고문서 필드는 비웠다. 따라서 낮은 총점은 문서 접근의 차이를 포함한다. RAG와의 격차를 생성 모델 자체의 우열로 표현하지 않는다.
- Vector RAG: 문서7개/86청크, text-embedding-3-small 1,536차원, 코사인 top8, 최대 4,000 기준 토큰.
- GraphRAG: 같은 원문 검색에 원래 예원 v2 2,806트리플을 추가. 최대 시작6노드/방문24노드/2홉, 그래프 카드 최대1,500, 원문과 합계 최대4,000 기준 토큰. seed 구조 및 문서 보조 검색을 사용하는 로컬 GraphRAG이며 그래프만의 순수 검색 실험은 아니다.
- 두 RAG의 토큰 예산 기준은 o200k_base이며 실제 모델 토크나이저와 같다고 가정하지 않는다. 예산 상한은 같지만 실제 입력 길이는 다르다.
- API 재시도·답변 재생성 없이 첫 응답을 보존했다. 최대3개의 질문을 병렬 처리하되 각 질문 내 시스템 호출은 순차 실행하여 같은 질문 임베딩 캐시를 공유했다. 병렬 실행 때문에 지연시간을 직렬 처리 성능 비교로 제시하지 않는다.

## 실패 분석과 구현 한계

두 RAG는 아래 필수 근거를 동일하게 놓쳤다. 순위는 사후에 저장 질문 벡터로 전체 코퍼스를 조회한 진단값이다.

| 문항 | 누락 근거 | 코사인 순위 | 점수에 미친 영향 |
|---|---|---:|---|
| Q08 | SOP-003 정비 표1 | 18 | MAINT-04의 ID·조건·조치·우선순위 미답변, 0점 |
| Q09 | SOP-003 정비 표1 | 27 | MAINT-05 조건·조치 누락, PLC 종료 기준만 답변 |
| Q20 | SOP-001 RULE-SRV01-02 | 15 | 모든 PLC 자동 종료 규정 누락, SOP-002 대응만 충족 |
| Q25 | SOP-004 역할 표1 | 10 | security YES와 문서 간 차이 누락 |
| Q28 | SOP-002 CORRELATED 정의 표6 | 10 | 90분 정의와 해당 근거 누락 |
| Q29 | DS-THERM-2200 TMP-2210 표1 | 11 | 내용은 충족하나 데이터시트 근거 누락 |

해당 문항들의 문서 청크는 컨텍스트 예산 초과로 잘린 것이 아니다. top8에 포함되지 않았고 그래프 확장도 가져오지 못했다. 각 실패 문항에서 GraphRAG가 포함한 그래프 카드는 2개였다. 따라서 현재의 벡터 시작점·제한된 식별자 연결·그래프 탐색이 부족한 근거를 회수하는 데 성공하지 못했다고 해석할 수 있다. 이것만으로 각 설계 요소의 인과적 기여를 분리할 수는 없다.

GraphRAG Q10은 **일본어로 응답해 한국어 출력 지시를 위반**했다. 내용·부등호·인용은 정확하여 기존 QA 규약의 의미 일치 기준에 따라 5점으로 채점했고, 미리 정하지 않은 언어 벌점을 사후 추가하지 않았다. 언어 준수 결함 1건을 점수와 별도로 보고한다.

Q20은 인용한 RULE-SRV01-01 자체에 구체 조치가 없다고 범위를 한정했다. 실제 누락된 RULE-SRV01-02는 내용·근거에서 감점하고 충실성에 중복 감점하지 않았다. Q28은 복합 정답 요소에 포함된 90분 정의를 말하지 못해 세 방식 모두 해당 요소를 0점 처리했다. Q19의 LLM은 두 조건·시간 병기에 실패해 내용 0점이지만, 단일 허용시간을 확정할 근거가 없다는 실질적 답변은 정확해 충실성 1점을 부여했다. 모든 상세 사유는 비공개 채점표에 보존했다.

## 실제 API 사용량

| eval24 방식 | 생성 입력 토큰 | 생성 출력 토큰 | 합계 |
|---|---:|---:|---:|
| LLM | 6,821 | 5,159 | 11,980 |
| Vector RAG | 29,596 | 7,206 | 36,802 |
| GraphRAG | 62,990 | 7,844 | 70,834 |

GraphRAG의 eval 생성 토큰 합계는 Vector RAG의 약 **1.92배**다. 실제 청구 금액은 확인하지 않았으며, 캐시 가격 차이 등이 있으므로 토큰 비율을 비용 비율로 단정하지 않는다.

이번 작업의 신규 사용량은 dev12+eval72의 **생성84회, 입력115,956+출력22,772=138,728토큰** 및 **질문 임베딩24회, 1,366토큰**이다. 이전 문서 임베딩과 Vector RAG dev 생성은 제외했다. dev 질문 벡터와 동일 eval 질문의 GraphRAG 벡터는 캐시를 재사용했다. 대용량 모델이나 새 패키지는 설치하지 않았다.

## 채점·재현·한계

응답 수집을 끝낸 후 AI가 동결된 정답 요소와 원문을 직접 대조했다. 별도의 자동 의미 채점 모델을 호출한 것이 아니다. `aggregate_comparison_20261024.py`는 기록된 판정을 검증하고 산식만 집계한다. 같은 AI가 구현·채점했고 시스템 정체를 알고 있으므로 **독립 전문가 평가나 완전 블라인드 평가가 아니다**.

정답·채점표를 생성 API 입력이나 검색 인덱스에 넣지 않았다. 문항·원문·기존 v2 KG·평가 기준 해시 및 실행 코드/설정 잠금을 사후 재확인했다. 그러나 과거 개발 과정의 정답 노출, 문항 작성에 사용된 문서 중복, 소규모 표본의 한계는 남아 있다. eval은 미리 분리한 비교용 집합이지 외부의 미노출 독립 홀드아웃이라고 주장할 수 없다. 이번 QA 점수는 기존 규칙 추출 F1_content 86.19%와 별개다.

산출물:

- 실행 코드: `scripts/run_comparison_benchmark.py` (정답 로더 없음)
- 원본 응답과 실행 잠금: `kg_build/comparison_benchmark_20261024/dev/`, `eval/`
- 90행 dev/eval 통합 채점표: `evaluation/comparison_20261024/scores_PRIVATE.csv`
- 수동 AI 판정: 같은 폴더 `decisions_PRIVATE.json`
- 집계와 원본 해시·사용량 감사: 같은 폴더 `summary.json`, `execution_audit.json`
- 오프라인 집계 스크립트: `evaluation/benchmark_yewon_v2_20261023/aggregate_comparison_20261024.py`

기존 빈90행 템플릿과 이전 Vector RAG dev 결과는 보존했다. Git 커밋·푸시는 하지 않았다. 평가를 보고 현재 실행을 덮어쓰거나 상위 점수 답변을 골라 넣지 않았다.

## 프로젝트에 적용할 결론

현재 근거로는 **원래 예원 v2 KG를 지식 저장·구조화의 기준으로 유지하고, 현재 QA 기준선은 더 적은 생성 토큰으로 같은 점수를 얻은 Vector RAG로 보존**할 수 있다. 그래프 구축 가치와 GraphRAG의 QA 개선 효과는 별개의 주장이다. 발표에서는 “KG 구축은 완료했으며, 이번 제한된 GraphRAG 구현에서는 문서 Vector RAG 대비 QA 개선을 확인하지 못했다”고 설명하는 것이 정확하다.

추가 개선을 한다면 모델 교체보다 문서·규칙 식별자 연결, 다중 문서 근거 회수, 그래프 카드 예산을 먼저 별도 버전으로 점검할 수 있다. 다만 이번 eval 실패를 보고 개선하면 같은 eval은 이후 개발 자료가 되므로, 재실행 점수를 새로운 미노출 평가 성능으로 표현하면 안 된다. 이번 결과는 그대로 남긴다.
