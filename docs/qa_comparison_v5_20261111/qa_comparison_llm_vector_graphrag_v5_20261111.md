# LLM 단독 vs Vector RAG vs GraphRAG v5 비교

- 작성일: 2026-11-11
- 기준 코드: `main` [`72d23dd`](https://github.com/yujin0321/manufacturing-graphrag-agent/tree/72d23dd9386d45ab9a81ccadb1957ed1b7d246bb)
- 실행 결과 출처: `예원8` 브랜치 [`reports/final_qa_comparison_20261109.md`](https://github.com/yujin0321/manufacturing-graphrag-agent/blob/예원8/reports/final_qa_comparison_20261109.md) (2026-11-09 실행, 응답 108개)
- 이 문서는 위 실행 결과를 비교 기준·채점 방법과 함께 정리하고 재검토한 것이다. 새 API 실행은 하지 않았다.

## 1. 요약

| 평가 범위 | LLM 단독 | Vector RAG | GraphRAG v5 | Graph − Vector |
|---|---:|---:|---:|---:|
| 제조 문서 QA (24문항, 평균 /5) | 0.750 | **4.938** | 4.917 | −0.021 |
| KG 관계·집합·경로 QA (12문항, 평균 /5) | 1.000 | 3.541 | **4.210** | **+0.669** |

1. **문서 QA는 두 RAG가 사실상 동점이다.** 24문항 중 23문항이 같은 점수였다. 문서에 직접 적힌 규칙·수치를 묻는 질문은 벡터 검색만으로 충분하다.
2. **KG 구조 질문에서 GraphRAG가 앞선다.** 필수 KG 근거 회수율이 33.2% → 83.7%로 올랐고, 완전 정답은 5 → 8문항이었다.
3. **LLM 단독은 문서 고유 규칙·수치를 거의 답하지 못한다.** 모든 문항에서 완전 정답은 0개였다. 같은 생성 모델이므로 이 차이는 모델 능력이 아니라 자료 접근 차이다.
4. **GraphRAG의 남은 약점은 "전체 목록" 질문이다.** 일부만 회수한 결과를 전체 집합처럼 단정하거나(ADD-02·03), 맞게 나열하고 합계를 틀리는 문제(ADD-05)가 남았다.

## 2. 비교 대상

**원칙: 지식에 접근하는 방식만 다르게 하고, 생성 조건은 모두 같게 한다.**

| 항목 | LLM 단독 | Vector RAG | GraphRAG v5 |
|---|---|---|---|
| 생성 모델 | `gpt-6.1-sol` | 동일 | 동일 |
| 지시문 | main v5 실험 공통 지침 | 동일 | 동일 |
| 입력 자료 | 질문만 (closed-book) | SOP 4개 + 데이터시트 3개 원문 행 | 같은 원문 + 고정 RDF KG |
| 검색 | 없음 | 밀집 벡터 검색 | v5: 그래프 관계 확장 + 명시적 규칙 참조 + BM25 결합 + 출처별 근거 구성 |
| KG 문항의 KG 정보 | 없음 | KG 노드 레코드를 **텍스트로** 검색 | 같은 노드 레코드 + 저장된 관계로 집합·경로 구성 |
| 검색 문맥 상한 | 0 | 문서 4,000 / KG 8,000토큰 | 동일 |
| 출력 상한 | 문서 2,200 / KG 6,000토큰 | 동일 | 동일 |

- **두 RAG가 받는 정보의 양은 같다.** KG 문항에서도 Vector RAG에 같은 KG 사실을 텍스트로 주었다. 따라서 KG 트랙의 차이는 "정보가 있느냐"가 아니라 **"관계 구조를 써서 모으느냐"**에서 나온다.
- **GraphRAG는 main의 v5 검색 엔진에 공통 생성기를 붙인 조합이다.** main 기본 Agent인 v4.1(자기검증 루프 포함)은 호출 횟수가 달라 이 비교에서 제외했다.
- **여기서 Vector RAG는 main `docs/vector_rag_v1`(cosine top-8)과 다르다.** v5 실험의 행 단위 밀집 검색이다. 평균 문서 문맥은 약 2,000토큰으로, 11/1 벤치마크의 v1(약 900토큰)보다 길다.

## 3. 평가 설계

### 3.1 문항 (트랙을 나누고, 트랙끼리 평균을 섞지 않음)

| 트랙 | 문항 수 | 출처 | 정답 기준 |
|---|---:|---|---|
| 제조 문서 QA | 24 | main 고정 문서 평가 세트 (예원 v2 eval) | 원문 대조로 작성된 정답 요소 3개 + 근거 위치 |
| KG 관계·집합·경로 QA | 12 | v5 문항집 중 실행 가능한 KG 구조 문항 (REL-K01~06, ADD-01~06) | 고정 RDF에 대한 결정적 질의 결과 |

### 3.2 채점: 문항당 5점 (main [`채점기준_확정_v1.md`](https://github.com/yujin0321/manufacturing-graphrag-agent/blob/main/docs/benchmark_yewon_v2_20261023/채점기준_확정_v1.md)을 그대로 사용)

| 항목 | 배점 | 판정 |
|---|---:|---|
| 필수 정답 요소 1~3 | 각 0/1 | 요소 안의 조건(수치·단위·부등호·기간·대상)을 모두 맞아야 1 |
| 출처 근거 | 0~1 | 충족한 근거 단위 수 / 필요한 근거 단위 수. 문서명만 쓰면 0 |
| 충실성 | 0/1 | 원문 왜곡, 무근거 단정, 허위 인용이 없으면 1 |

- **완전 정답:** 내용 3/3 + 근거 1/1 + 충실성 1/1
- 답할 수 있는 질문에 "모른다"고만 답하면 0점이다. 빈 답변과 실행 실패도 0점이다.
- 문서가 서로 충돌하면 양쪽 값을 출처별로 구분해 답해야 정답이다.

### 3.3 지표

| 구분 | 지표 |
|---|---|
| 답변 품질 (주 지표) | 평균 /5, 완전 정답 수, 필수 내용 충족, 근거 점수, 충실성, 실행 실패 |
| 검색 품질 | 필수 KG 근거 회수율, 전부 회수한 문항 수 (RAG만 해당) |
| 문항별 대결 | Vector 대비 GraphRAG의 승·무·패 |
| 비용 | 생성 입력·출력 토큰, 평균 검색 문맥 토큰 |

### 3.4 채점 절차

1. 답변을 봉인한 뒤 시스템 이름을 익명화해 채점했다.
2. 채점자는 생성 모델과 같은 모델의 별도 세션(AI)이다. 인정한 근거는 답변의 실제 인용과 대조했다.
3. AI가 판정을 보류한 1문항(ADD-06)은 원본 RDF(`KG:N0105`)로 재검토해 확정했다.
4. 문서 Q28은 정답의 셋째 요소(90분 이내 수치)를 원래 AI 채점이 인정했다. 원문 대조 후 세 방식 모두 0점으로 정정했고, 정정 내역은 보존했다.
5. 사람 교차 채점은 하지 않았다.

## 5. 사례

| 문항 | 관찰 |
|---|---|
| REL-K01 | Vector는 ST04 센서에 연결된 seed `MAINT-01`을 빠뜨려 차집합과 개수가 틀렸다(1.92점). GraphRAG는 두 집합과 저장된 경로를 모두 제시했다(5점). |
| REL-K03 | SOP-003 출처 규칙 19개 중 Vector는 6개만 받아 설명했다. GraphRAG는 19개와 연결 속성을 모두 제시했다. |
| REL-K05 | Vector는 `MAINT-05`의 출처 경로를 확인하지 못했다. GraphRAG는 두 규칙의 출처·위치·해시를 제시했다. |
| ADD-02·03 | **GraphRAG의 실패 사례.** 검색된 기록만으로 전체 집합을 단정해 규칙 2개와 센서 1개를 빠뜨렸고, 충실성까지 잃었다(1.20 / 1.52점). Vector도 전체 목록을 내지 못했지만 "검색된 범위 내"라고 한정해 충실성을 지켰다. |
| ADD-05 | **GraphRAG의 생성 오류.** 문서별 2·1·3개를 맞게 나열하고도 합계를 7로 썼다. 근거가 충분해도 집계 실수가 남는다. |
| 문서 Q18 | GraphRAG가 압력 데이터시트의 적용 안내를 가져오지 못해 근거 0.5점을 잃었다. |

## 6. 해석과 한계

**결론으로 말할 수 있는 것**
- 그래프 구조는 **여러 노드에 걸친 집합·경로·출처 질문**에서 같은 토큰 예산으로 근거 회수를 크게 높인다.
- 문서 한두 곳에서 끝나는 질문에서는 그래프의 추가 이득이 없다. v5 오프라인 검색 실험에서도 그래프 조회를 끈 대조군(GraphNoTopology)이 문서 QA에서 GraphRAG와 같았다.

**결론으로 말할 수 없는 것 / 재검토에서 확인한 문제**

| # | 문제 | 영향 |
|---|---|---|
| 1 | **문서 QA는 천장 효과가 있다.** 두 RAG 모두 4.9점대이고 23/24문항이 동점이다. 개발 중 이미 사용한 문항이기도 하다. | 문서 QA로는 두 RAG를 구별하지 못한다. "그래프가 문서 QA에서 이득이 없다"보다 "이 문항으로는 차이를 측정할 수 없다"가 정확하다. |
| 2 | **채점자가 생성 모델과 같은 모델이고, 사람 교차 채점이 없다.** | 자기 선호 편향이 가능하다. 세 방식 모두 같은 생성 모델이라 편향이 공통으로 작용할 가능성은 있다. |
| 3 | **1회 실행이다.** temperature를 고정하지 않았다. | KG 12문항처럼 작은 표본에서는 1~2문항 변동으로 평균이 크게 움직인다. |
| 4 | **LLM 단독의 기권 처리가 트랙마다 다르다.** 문서 QA에서는 기권한 18문항이 0점(충실성 0)이다. KG QA에서는 12문항 모두 충실성 1점(1.00)을 받았다. 루브릭은 "답할 수 있는 질문에 '모른다'만 답하면 0점"이다. | KG 트랙 LLM 점수가 최대 1점 과대평가됐을 수 있다. RAG끼리의 비교에는 영향이 없다. **확인이 필요하다.** |
| 5 | **완전 목록 질문(ADD-02·03)은 두 방식 모두 실패했다.** | 전수 조회는 검색이 아니라 결정적 쿼리(SPARQL/Cypher)로 처리해야 한다. 개선 과제다. |
| 6 | **문항 수가 적고(36) 근거가 겹친다.** | 통계적 우월성은 주장하지 않는다. 독립 미노출 평가도 아니다. |
| 7 | **평가 범위.** | 문서·KG에 있는 지식의 검색·설명 능력만 평가했다. 새 인과관계 발견, 실제 설비 진단 정확도, 현장 안전성은 평가하지 않았다. |
