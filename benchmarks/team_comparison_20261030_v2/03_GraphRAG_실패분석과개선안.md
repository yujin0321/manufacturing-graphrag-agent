## 새 문항을 반영한 개선 우선순위

| 문제 유형 | 대응 |
| --- | --- |
| 단위·불확실성·반올림 | 단위 일치 확인과 범용 산술 검증. 특정 벤치마크 정답값 하드코딩 금지 |
| 지속시간·샘플·결측 | 관측 사실과 연속 유지 증거를 분리. 문서에 없는 보간·누적·리셋 정책을 생성하지 않음 |
| 역추론·규칙 미발동 | 조건→조치 방향과 조치→조건 추정을 구분. 한 규칙 미발동을 전체 안전 허가로 확대하지 않음 |
| 인용문·대상 일치 | 실제 센서·측정량·단위·표 행이 주장을 지지하는지 검사 |
| 모호한 질문·부분 응답 | 센서가 불명확하면 최소한으로 질문. 답 가능한 항목은 남기고 실시간 값은 필요한 자료와 함께 유보 |
| 관계·전체 집합 | 범용 관계 조건 조회로 전체 결과를 계산하고 필요한 필드·출처만 압축해 전달 |

새 논리·단위 문항은 그래프 탐색만으로 해결되지 않을 수 있다. 검색 실패, 입력에서 근거가 잘린 경우, 근거가 있는데도 계산·판단을 틀린 경우를 나눠 개선한다. 계산 도구를 추가한다면 두 RAG에 같은 조건으로 제공하고 별도 버전으로 검증한다.

## 이전 77문항에서 검증한 개선 근거 — 재사용

아래는 이전에 수행한 진단·단일 사례이며 이번 새 19문항에 개선 코드를 적용한 결과가 아니다. 본 비교의 검색 코드는 유지했고 개선 예시 점수를 96문항 평균에 섞지 않았다. 이전 사건형 문항은 현재 버전에서 교체·삭제됐으며 아래 시계열 관련 제안은 향후 별도 평가에 관한 것이다.

## 실제로 확인한 개선 사례 — REL-K01 한 문항

| 항목 | 측정 결과 |
| --- | --- |
| 전체 조회에 필요한 서로 다른 규칙 | 13개: A 11개, B 11개, 교집합 9개, 각 차집합 2개 |
| 기준 GraphRAG 탐색 | 관련 규칙 12개 방문, 답변 입력에는 규칙 카드 5개 포함 |
| 범용 관계 조회 + 결과 압축 | 13개 모두 조회, 독립 SPARQL 기준 집합과 정확히 일치 |
| 조회 결과 JSON 크기 | 1231토큰 / 검색 예산 4,000토큰 |
| 추가 쌍별 AI 검토 | 기준 답변 1.4/5 → 개선 답변 5.0/5 |

문제는 찾아낸 지식 상당수가 답변 입력에 전달되지 않는 데 있었다. 공정 ID를 인자로 받는 범용 함수로 저장 관계의 전체 집합을 조회하고, 필요한 관계·식별자·출처만 짧게 전달하자 같은 모델이 전체 집합과 경로를 답했다. 함수는 문항 ID·정답표·고정 ST04 값을 읽지 않는다. 별도 검증 코드에서만 기존 조회 정답과 대조했다.

알려진 실패 사례를 골라 개발한 **단일 사례의 추가 실험**이다. 이 점수는 별도 쌍별 AI 검토 결과로 본 비교의 점수와 독립적이며, 77문항의 원래 답변·평균·완전 정답 수에는 반영하지 않았다. 전체 성능 향상이나 새 문항 일반화를 입증하지 않는다. 코드와 출력은 검증 ZIP의 improvements/structured_station_query.py 및 structured_query_case_comparison.json에 있다.

## 추가로 수행한 로컬 검색 진단

77문항 중 14문항은 GraphRAG의 실제 입력이 그래프 확장을 끈 hybrid 검색 입력과 완전히 같았다. 해당 문항에서 VectorRAG와 점수 차이가 나더라도 그래프 탐색 효과로 볼 수 없다. 이 비교는 입력 동일성 검사이며 추가 답변 실험이 아니다.

최신 코드에 이미 있는 retrieval_v4의 유형별 검색도 원문·KG 복사본에서 별도로 확인했다. 이번 기준 실행의 검색 입력은 바꾸지 않았다.

| 실제 확인 | 해석 | 해결 방향 |
| --- | --- | --- |
| G08 고착 센서 유형 정의 행 | 기준 GraphRAG 입력에는 없고, 기존 유형별 검색은 해당 행 1개를 찾아 넣음 | 고착 조건 질문에 정의표를 연결하는 개선 후보. QA 점수 상승을 측정한 것은 아님 |
| “공정의”에 정의 검색이 발동 | 정규식 “정의”가 “공정의” 일부와 일치해 관계 질문에도 이상 유형 정의표를 추가 | 부분 문자열 대신 문맥·어절·의도 조건으로 정의 검색을 제한 |
| Q23 경보 확인 시간에 정비 검색도 발동 | CRITICAL과 “정비 완료 기한인지”라는 비교 표현을 함께 보고 정비 우선순위 검색을 추가 | 경보 확인과 정비 규칙 조회 의도를 구분 |
| 문서·전체 규칙을 출발점으로 하는 질문 | 엔티티 시작점이 없어 그래프 확장이 실행되지 않는 사례 확인 | 문서 ID·규칙 클래스 출발 조회를 지원 |

유형별 검색이 반환한 모든 행을 정답 필수 근거라고 부르지 않는다. 무관한 행이 섞일 수 있으므로 typed_retrieval_probe.json에는 실제 반환·선택 ID를 그대로 남겼다. 이 진단은 검색 개선 후보와 부작용을 함께 보여준다.

**수정 제안과 로컬 점검:** 원본과 별도로 검색 의도 판정 패치를 작성했다. “공정의” 일부를 정의 요청으로 취급하지 않게 하고, 단순히 “CRITICAL”과 “정비”가 함께 있다는 이유만으로 정비 우선순위 검색이 발동하지 않게 좁혔다. G01·G06·Q23의 불필요한 검색을 제거하면서 G08의 고착 정의, G13의 역할 확인 시간, G14의 이상 유형 정의 검색을 유지하는 6개 점검을 통과했다. 수정으로 검색 계획이 달라진 문항은 YV2-Q23, REL-K03, G01, G06이다.

제안 패치는 검증 ZIP의 improvements/retrieval_v4_scope_proposal.patch, 점검 결과는 improvements/verification.json에 있다. 원본 브랜치와 기준 실험 입력에는 적용하지 않았다. 정규식 보완의 적용 범위가 제한되어 있어 다른 한국어 표현도 추가 검토해야 하며, 답변 정확도 향상을 확인한 결과는 아니다.

## 다음 검증 실험

1. 이번 기준 결과와 입력을 보존한다.
2. dev에서 한 요소씩 바꾼다: 동일 hybrid에서 그래프 확장 OFF/ON → 문서·출처 간선 추가 → 집합/경로 조회 → 근거 압축.
3. 변경 전후 같은 문항·같은 답변 모델·같은 토큰 예산으로 재실행한다. 기준 결과와 개선 결과를 구분한다.
4. 기존 eval을 반복 튜닝에 썼다면 개발 재시험으로 표시하고, 새 문항으로 개선 효과를 확인한다.
5. 정확도가 동점이면 전체 호출 토큰·시간·유지 비용을 비교한다. 비용까지 개선되지 않았다면 해당 질문 유형에서 VectorRAG를 선택할 근거가 된다.
