## 1. 요약

예원 님 결과는 **"문서 QA는 동점, KG 구조 질문은 GraphRAG 우세"**였다. 이번 보강의 목표는 그 결과에서 답할 수 없던 세 질문에 답하는 것이었다.

| 질문 | 답 |
|---|---|
| 문서 QA가 동점이었던 건 문항이 쉬워서였나? | **부분적으로 그렇다.** 그래프 유리 유형의 문서 문항 21개에서 GraphRAG가 평균 +0.20점(2회 평균) 앞섰다. 다만 두 번 실행 모두 일관되게 이긴 문항은 2개(G01, G08)뿐이고, 그 차이는 **그래프 구조가 아니라 BM25 결합 같은 검색 방식**에서 나왔다. |
| KG에서 이긴 건 그래프 구조 덕분인가? | **검색에서는 그렇고, 답변 점수에서는 일부만 그렇다.** 구조 조회는 근거 회수율을 44% → 85%로 올렸다. 그러나 답변 점수 이득(+0.70) 중 +0.57은 구조 없이도 얻어졌고, 구조 자체의 몫은 +0.13이다. 구조가 결정적이었던 문항은 ADD-06과 REL-K05다. |
| 애초에 검색이 필요한가? | **이 문서 규모에서는 정확도만 보면 필요 없다.** 문서 전체(약 1.1만 토큰)를 그대로 넣은 LLM이 문서 QA 24문항에서 5.00/5 만점을 받았다. 대신 입력 토큰을 RAG의 약 4.7배 썼다. |

추가로 확인한 점은 다음과 같다.
- 예원 님 KG 트랙의 **LLM 단독 점수(1.00)는 기권 채점 불일치로 부풀려진 값**이다. 루브릭대로라면 0.00이다.
- 채점 정답을 계산하는 `kg_oracles.py`에 **`/`가 들어간 값을 자르는 버그**가 있다.
- 같은 채점 방식으로 다시 채점했을 때 **예원 님 최종 점수와 108건 중 105건이 일치**했다.

## 2. 실험 설계

### 2.1 비교 방식

모든 방식이 같은 생성 모델(`gpt-6.1-sol`), 같은 지침, 같은 출력 상한, 같은 별칭 확장 임베딩 순위를 쓴다. 예원 님 실행기(`run_final_v5.py`) 설정을 그대로 가져왔다.

| 방식 | 입력 | 이번에 새로 추가했나 |
|---|---|---|
| LLM 단독 | 질문만 | – |
| Vector RAG | 밀집 벡터 검색 결과 | – |
| **그래프 끈 GraphRAG** (GraphNoTopology) | GraphRAG v5와 같은 엔진·같은 텍스트 기록·같은 BM25 결합. **RDF 그래프만 비워** 구조 조회를 끔 | ✅ (main v5 오프라인 실험에 정의된 대조군) |
| GraphRAG v5 | v5 검색 전체 | – |
| **LLM + 전체 문서** (LLMFullDoc) | 검색 없이 문서 전체 157행(약 1.08만 토큰) | ✅ |

그래프 끈 대조군이 이 실험의 핵심 장치다. GraphRAG가 이겼을 때 그 이유가 **그래프 구조**인지, 아니면 BM25 결합·규칙 참조 같은 **검색 방식**인지를 가려낸다.

### 2.2 문항과 정답

| 실험 | 문항 | 정답 출처 |
|---|---|---|
| A. 그래프 유리 문서 문항 | G01–G15 (나열·다단계·현장 표현·대조) + REL-D01–06 = 21 | 유진 님 `expanded/answer_key.json`. main `suite_lock.json`의 잠금 해시와 일치(실행 전 고정) |
| B. KG 구조 문항 확장 | 예원 님 KG 12 + YB 9 (YB-01·02·03·04·11·12·13·16·17) = 21 | main `kg_oracles.py`가 RDF에서 결정적으로 계산 |
| C. 전체 문서 LLM | 예원 님 문서 eval 24 | 예원 님 `answer_key_PRIVATE.json` (scoring_lock 해시 일치) |

- G 문항에는 실행 전에 고정한 그래프 이득 가설이 있다(이득 예상 / 부분 / 이득 없음). G13–G15와 G01은 "이득 없음"으로 예상한 대조 문항이다.
- YB 18문항 중 정답 코드가 있는 9개만 B에 넣었다.

### 2.3 채점

- 예원 님 채점 지시문과 5점 루브릭(내용 3 + 근거 1 + 충실성 1)을 그대로 쓴다.
- 한 문항의 답변 4개를 익명화해 한 번에 채점한다. 예원 님은 3개씩 채점했으므로, 답변이 늘어난 만큼 채점 출력 상한만 5,500 → 16,000으로 올렸다.
- A는 2회 실행해 평균을 냈다. B와 C는 1회 실행이다.

## 3. 결과 A — 그래프 유리 문서 문항 21개

### 3.1 유형별 평균 /5 (2회 실행 평균)

| 유형 | 사전 가설 | LLM | Vector | 그래프 끈 | GraphRAG |
|---|---|---:|---:|---:|---:|

| 다단계 G05–08 | 이득·부분 | 0.00 | 4.67 | 4.83 | 4.83 |
| 현장 표현 G09–12 | 이득·부분 | 0.62 | **4.17** | 3.62 | 4.04 |
| 대조 G13–15 | 이득 없음 | 0.00 | 4.67 | 4.67 | 4.67 |
| REL-D01–06 | – | 0.33 | 3.50 | 3.65 | 3.67 |
| **G 15문항** | | 0.17 | 4.42 | 4.49 | **4.63** |
| **전체 21문항** | | 0.21 | 4.16 | 4.25 | **4.36** |

| 실행 | Vector | 그래프 끈 | GraphRAG | GraphRAG − Vector (승/무/패) |
|---|---:|---:|---:|---|
| 1회차 | 4.18 | 4.37 | 4.48 | +0.30 (3 / 18 / 0) |
| 2회차 | 4.14 | 4.13 | 4.23 | +0.10 (2 / 17 / 2) |

### 3.2 근거 회수 — 문서 문항에서는 그래프 구조가 아무것도 바꾸지 않았다

| 방식 | 필수 근거 회수 |
|---|---:|
| Vector RAG | 68/77 (88.3%) |
| 그래프 끈 | 76/77 (98.7%) |
| GraphRAG v5 | 76/77 (98.7%) |

**21문항 모두 그래프 끈 대조군과 GraphRAG가 생성 모델에 넘긴 문맥이 글자 하나까지 같았다.** 그러니 문서 문항에서 Vector 대비 개선은 전부 그래프가 아닌 요소(BM25 결합, 명시적 규칙 참조, 출처별 구성)에서 나온 것이다. main v5 오프라인 실험의 결론("문서 QA에서 그래프 끈 대조군 = GraphRAG")과 같다.

이 덕분에 두 방식의 점수 차이는 **같은 입력에서 생기는 생성 잡음**으로 해석할 수 있다. 그 크기는 문항당 평균 절대 차이 0.11점이었다.

### 3.3 두 번 모두 같은 결과가 나온 차이

| 문항 | Vector | GraphRAG | 이유 |
|---|---:|---:|---|
| G01 (CRITICAL 정비 규칙 전체 찾기) | 2.0 / 2.0 | 5.0 / 5.0 | Vector가 해당 표 행(MAINT-05~07)을 검색하지 못해 "CRITICAL 규칙은 없다"고 답함. GraphRAG는 BM25로 행을 찾아 3개를 정확히 제시 |
| G08 (STUCK 판정 연결) | 3.67 / 3.67 | 5.0 / 5.0 | Vector가 이상 유형 정의 근거를 놓침 (근거 회수 2/3) |

G01은 "그래프 이득 없음"으로 예상한 문항이다. 그런데 GraphRAG v5가 이겼고, 이유는 그래프가 아니라 키워드 검색이었다. 가설과 결과가 다른 경우로 기록한다.

### 3.4 실행 실패

REL-D06은 두 번 실행 모두 **RAG 세 방식이 실패**했다. 출력 상한 2,200토큰을 내부 추론에 다 써서 답변 본문이 비었다. 예원 님 프로토콜의 상한을 그대로 적용한 결과이고 세 방식에 똑같이 영향을 줬다. 루브릭대로 0점으로 처리했다. REL-D06을 빼도 순위는 같다.

## 4. 결과 B — KG 구조 문항 21개

### 4.1 평균 /5

| 범위 | LLM (원채점 → 루브릭 적용) | Vector | 그래프 끈 | GraphRAG |
|---|---:|---:|---:|---:|
| 예원 님 KG 12 | 1.00 → **0.00** | 3.46 | 4.05 | **4.21** |
| 추가 YB 9 | 1.22 → 0.44 | 4.23 | 4.77 | **4.86** |
| **전체 21** | 1.10 → **0.19** | 3.79 | 4.36 | **4.49** |

| 전체 21 세부 | Vector | 그래프 끈 | GraphRAG |
|---|---:|---:|---:|
| 완전 정답 | 8 | 12 | **15** |
| 필수 내용 (/63) | 49 | 55 | **58** |
| 근거 점수 (/21) | 11.6 | 15.6 | **18.3** |
| 충실성 (/21) | 19 | **21** | 18 |

| 비교 (전체 21) | 평균 차이 | 승 / 무 / 패 |
|---|---:|---|
| GraphRAG − Vector | +0.70 | 10 / 8 / 3 |
| 그래프 끈 − Vector | +0.57 | 11 / 9 / 1 |
| **GraphRAG − 그래프 끈 (구조 자체의 효과)** | **+0.13** | 4 / 14 / 3 |

### 4.2 근거 회수

| 방식 | 필수 KG 근거 회수 (21문항) |
|---|---:|
| Vector RAG | 77/222 (34.7%) |
| 그래프 끈 | 98/222 (44.1%) |
| GraphRAG v5 | 188/222 (84.7%) |

### 4.3 해석: 검색과 답변 점수가 다른 이야기를 한다

- **검색:** Vector 대비 늘어난 근거 111개 중 90개(81%)가 구조 조회 덕분이다.
- **답변 점수:** 이득 +0.70 중 +0.57은 그래프 끈 대조군도 얻었다. 같은 KG 텍스트 기록을 BM25로 찾는 것만으로 대부분의 질문에 답할 수 있었다. 구조 자체의 몫(+0.13)은 3.2에서 잰 생성 잡음(0.11)과 비슷한 크기다.
- **구조가 결정적이었던 문항:** ADD-06 (그래프 끈 1.0 → 5.0, 근거 39개 전부 회수), REL-K05 (3.5 → 5.0, 출처 경로 추적).
- **구조가 오히려 손해였던 문항:** ADD-05 (5.0 → 3.0, 맞게 나열하고 합계를 틀림), ADD-02·03 (일부만 회수한 결과를 전체 집합처럼 단정). GraphRAG의 충실성이 18/21로 가장 낮은 이유다. 근거를 많이 받으면 "이게 전부"라고 단정하는 경향이 생긴다.

정리하면, 그래프 구조는 **"많은 노드를 빠짐없이 모으거나 출처 경로를 따라가야 하는 질문"**에서 결정적이다. 일반적인 KG 조회 질문에서는 KG 기록을 텍스트로 만들어 하이브리드 검색하는 것만으로 대부분 해결된다.

## 5. 결과 C — 전체 문서를 넣은 LLM (예원 님 문서 24문항)

| 방식 | 평균 /5 | 완전 정답 | 생성 입력 토큰 |
|---|---:|---:|---:|
| LLM 단독 | 0.75 | 0/24 | 8,021 |
| Vector RAG | 4.94 | 23/24 | 57,228 |
| GraphRAG v5 | 4.92 | 22/24 | 55,687 |
| **LLM + 전체 문서** | **5.00** | **24/24** | 271,349 (RAG의 약 4.7배) |

- 문서가 7개(약 1.1만 토큰)뿐이라, 다 넣어도 모델 문맥에 충분히 들어간다. 이 규모에서는 **검색 실수(필요한 행을 못 찾음)가 RAG 오답의 주원인**이고, 전부 넣으면 그 실수가 사라진다.
- 따라서 이 데이터셋에서 RAG의 가치는 정확도보다 **비용과 확장성**에 있다. 문서가 수백 개로 늘어 문맥에 다 들어가지 않을 때 비로소 검색이 필수가 된다.
- KG 구조 문항(노드 514개)은 전체 문서 방식으로 시험하지 않았다.

## 6. 예원 님 결과에 대한 확인 사항

| 항목 | 내용 | 영향 |
|---|---|---|
| 기권 채점 불일치 | LLM 단독은 두 트랙에서 똑같이 "자료가 없어 확인할 수 없다"고 답했다. 문서 QA에서는 `NO_ANSWER`로 0점, KG에서는 충실성 1점을 받았다. 채점 지시문에는 "답할 수 있는 질문에서 단순 기권은 0점"이 명시돼 있다. | KG LLM 1.00 → 0.00. RAG 비교에는 영향 없음 |
| 오라클 `/` 버그 | `kg_oracles.py`가 문자열 값에도 `short()`를 적용해 `m/s` → `s`(YB-02), 조건 문장 잘림(ADD-06)이 생긴다. | YB-02는 KG에 저장된 실제 값(`m/s`)으로 정답을 고쳐 재채점했다. 원래 채점은 보존했다. ADD-06은 예원 님과 같이 점수를 유지했다. **main 코드 수정이 필요하다.** |
| 채점 일관성 | 예원 님 답변을 같은 채점 방식으로 다시 채점했다. 문서 72건은 예원 님 최종 점수와 전부 일치(Q28 정정 포함). KG 36건 중 33건이 일치하고, 3건은 Vector 충실성이 1점씩 다르게 나왔다(ADD-02·06 −1, REL-K05 +1). | 예원 님 결과는 재현 가능하다 |
| 검색 재현 | 예원 님 임베딩을 재사용해 KG 12문항 검색을 다시 돌렸다. Vector와 GraphRAG가 고른 근거가 전부 일치했다. | 실행 조건이 정확히 재현됨 |

## 7. 결론과 다음 과제

**결론 — 언제 무엇을 쓰는가**

| 질문 유형 | 권장 | 근거 |
|---|---|---|
| 문서에 직접 적힌 규칙·수치 | Vector 또는 하이브리드 검색으로 충분. 문서가 적으면 전체 투입이 가장 정확 | A 대조 문항 동점, C 전체 문서 만점 |
| 여러 문서·행을 모아야 하는 나열·다단계 문서 질문 | 하이브리드 검색(BM25 + 벡터 + 규칙 참조) | A에서 그래프 끈 = GraphRAG |
| KG의 많은 노드 집합·출처 경로 | **그래프 구조 조회** | B의 ADD-06, REL-K05 |
| "전체 목록·개수"를 확정해야 하는 질문 | 검색이 아니라 **결정적 쿼리(Cypher/SPARQL)** 로 처리 | B의 ADD-02·03·05에서 모든 방식이 실패 또는 과신 |

**다음 과제**
1. `kg_oracles.py`의 문자열 값 처리 버그 수정.
2. 전체 목록 질문을 결정적 쿼리로 넘기는 라우팅(Agent v4.1 경로와 연결).
3. 문서 생성 출력 상한(2,200) 재검토. 추론 토큰 때문에 실패하는 문항이 있다(REL-D06).
4. 시스템과 별칭 사전을 보지 않은 팀원이 새 문항을 작성해 미노출 평가 수행.

- **AI 채점:** 생성과 같은 계열 모델이 채점했다. 사람 교차 채점은 아직 하지 않았다. 다만 6장에서 같은 채점의 재현성(108건 중 105건 일치)은 확인했다.
- **반복 횟수:** A는 2회, B와 C는 1회 실행이다. 문항당 생성 잡음은 약 0.11점이고, 이보다 작은 차이는 우열로 해석하지 않는다.
- **채점 묶음 크기:** 답변 4개를 한 번에 채점해서 예원 님(3개)과 조건이 조금 다르다. 재채점 일치율로 영향이 작음을 확인했다.
- **실제 설비 진단 아님:** 문서·KG에 이미 있는 지식의 검색·설명 능력만 평가했다. 새 인과관계 발견, 실제 설비 진단 정확도는 평가하지 않았다.
