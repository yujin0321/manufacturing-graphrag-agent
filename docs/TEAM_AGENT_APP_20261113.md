# 네 사람의 실험을 반영한 통합 Agent 앱

## 이번에 통합한 것

기준은 2026-11-13 main `020c863`에 보존된 코드·자료다. 한 앱에서 공통 지식 기반과 사건 도구를 사용하고, 같은 역할의 대안은 선택한다. 과거 실험 점수를 합치거나 새 앱의 정확도로 옮기지 않는다.

| 팀원 | 앱에서 적용한 내용 | 보존 범위와 한계 |
|---|---|---|
| 예원 | 고정 v2 KG, 문서 출처와 해시, v5 문서 검색 구성 | 기존 비교 결과는 원래 조건의 결과로 보존한다. |
| 유진 | 봉인된 사건 엔진, 사건 KG, 근거·상관 조회 도구, v5 그래프 검색 | v3.1 기본값과 v3.2 대안을 선택한다. 상관 후보를 원인으로 확정하지 않는다. |
| 성호 | 원본 `experiments/rule_detector_20261106/code/detector.py` 실행 | 연속 2점 확인·2점 해제, 기본 규칙 또는 DRIFT 보강 규칙을 선택한다. 원본 소스는 수정하지 않는다. |
| 수민 | 실험 분석을 바탕으로 문서 하이브리드·전체 문서 대안과 KG 전수 조회를 구성 | main에 있는 것은 보고서다. 보고서의 GraphNoTopology·확장 KG 실험을 그대로 재현했다고 주장하지 않는다. 이번 라우팅·어댑터는 새 구현이다. |

원래 실험과 조건은 [팀 실험 색인](TEAM_EXPERIMENTS_20261113.md)에서 확인한다. 별도로 공유된 성호 11/9 정정본은 main에 실행 코드가 없어 이번 앱의 원본 구현으로 사용하지 않았다. 사용자가 제외한 사건 17건의 검색→답변 연계 재평가도 사용하지 않았다.

## 화면 사용 순서

1. `http://127.0.0.1:8770/`을 연다.
2. **사건 탐지 방식**을 고른다. 처음에는 기본 v3.1을 사용한다.
3. 문서 질문의 경우 **문서 검색 방식**을 고른다. 처음에는 자동을 사용한다.
4. 사건을 선택하고 **선택 사건으로 질문 채우기**를 누른다.
5. **Agent 질문 실행**을 누른 뒤 답변·실제 경로·실행 조건·원문·검토 결과를 읽는다.
6. **저장된 실행 → 기록 열기 · 무료**로 이미 만든 답변을 다시 볼 수 있다.

방식 선택·목록·저장된 답변 열기는 API를 호출하지 않는다. 질문 실행에는 기존 OpenAI API 설정을 사용하며 비용이 발생한다. 로컬 모델 가중치를 설치하지 않는다.

## 선택 가능한 방식

| 선택 | 실제 동작 |
|---|---|
| 기본 v3.1 | main의 v3.1 사건 엔진과 별도 오버레이 |
| 유진 v3.2 | main의 v3.2 감시·상관 설정과 별도 오버레이 |
| 성호 연속 2점 | 원본 스캐너 + 공개 `rules_baseline.json` |
| 성호 연속 2점 + DRIFT | 같은 원본 스캐너 + 공개 `rules_improved.json` |
| 문서 자동 | BM25·벡터 융합 + 출처·표 행 조건 필터 |
| 문서 Vector RAG | 같은 157개 행의 벡터 순위 |
| 문서 GraphRAG v5 | 같은 행 검색에 고정 KG 관계·출처 경로를 사용 |
| 문서 전체 원문 입력 | 고정 157개 행 전체를 입력, 질의 임베딩 없음 |

탐지 선택은 과거 사건 도구에 적용하고, 문서 선택은 문서 질문에 적용한다. 공정별 센서 전체 목록·규칙 개수·생산 방향 경로 질문은 선택 문서 방식과 별도로 **고정 KG 전수 질의**를 실행한다. 모델은 허용 질의와 인자를 고르고, 개수와 경로는 코드가 계산한다. 따라서 화면의 선택 방식과 실제 처리 경로를 함께 확인한다.

전체 문서 입력은 원문을 제공하는 방식이다. 원문을 주지 않는 LLM 단독 실험과 동일하지 않다. 여러 방식은 앱의 대안이지 자동으로 공정한 성능 비교 실험이 되지는 않는다.

## 성호 후보를 해석하는 방법

성호 스캐너는 규칙별 이벤트를 반환한다. v3.1의 여러 알람을 묶은 사건과 단위가 다르므로 이벤트 개수를 직접 성능으로 비교하지 않는다. 원본 ID와 확인·해제 시각을 보존하고, 원본에 없는 SOP-002 이상 유형은 `UNCLASSIFIED`로 유지한다. `ADVISORY`는 기존 화면 계약과 맞추기 위한 표시용 기본값이며 원본의 심각도 판단이 아니다.

기존 온톨로지 S2는 AnomalyEvent에 정확히 하나의 하위 유형을 요구한다. 이를 완화하지 않고 미분류 결과를 별도 `det:RuleMatchCandidate`로 표현했다. `det:observedOnSensor`, `det:matchedRule`, `det:sourceWindow`로 센서·규칙·시계열 출처를 연결하고 전용 SHACL로 검사한다. 확정 이상이나 기존 AnomalyEvent 유형으로 승격하지 않는다.

## 실행과 재현

PowerShell에서 이 작업 폴더로 이동한다.

```powershell
$env:PYTHONUTF8='1'
..\.venv\Scripts\python.exe scripts/run_xai_agent.py --prepare-team
..\.venv\Scripts\python.exe scripts/run_xai_agent.py --serve --port 8770
```

문서 검색은 기존 11/9 v5 실행의 임베딩 응답에서 동일 입력인 157개 행을 확인한 뒤 벡터를 재사용했다. 새 원문 임베딩 API 호출은 0회다. 새 질문은 질의 임베딩 API를 사용할 수 있다. 다른 환경에서 초기화할 때는 기존 영수증 폴더를 `--prepare-team --reuse-embedding-cache <폴더>`로 지정한다. 영수증이 없다면 벡터 방식 초기화가 필요하며, 전체 문서 모드는 벡터 색인 없이 사용할 수 있다.

질문 실행 예시:

```powershell
..\.venv\Scripts\python.exe scripts/run_xai_agent.py --question 'ST04_PACKAGING에 연결된 센서 전체와 단위는?' --run-dir kg_build/graphrag_live/my_new_query --document-mode graph
```

실행 폴더는 매번 새 이름을 사용한다. 실패 기록을 덮어쓰거나 성공까지 자동 재호출하지 않는다.

## 기록과 검증 범위

`answer.json`의 `integration`에는 선택한 탐지기·문서 방식과 실제 라우팅이 기록된다. 사건 경로는 `store_lock.json`, 문서 경로는 `documents/agent_lock.json`, KG 질의는 `kg_query.json`으로 원본을 추적한다. 요청·응답·초안·검토도 같은 실행 폴더에 남는다. 개인 키는 기록하지 않는다.

자동 검사는 입력 검증·전수 집합·방향·단위·원본 매핑·봉인·인용·HTTP 선택 전달을 확인한다. 대표 API 실행은 연결 확인이며 새 정확도 평가가 아니다. AI 검토 통과는 도메인 전문가 검토나 현장 안전 승인이 아니다. 실제 센서 조회·설비 제어·조치 실행 기록은 연결하지 않았다.

2026-11-14 인계 절차는 [백엔드 인계 안내](agent_handoff/README.md)를 따른다. 공유용 개발 브랜치와 별도 로컬 복원 ZIP을 구분한다. main에는 직접 반영하지 않는다.
