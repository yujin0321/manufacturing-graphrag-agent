# GraphRAG 검색 개선판 v2 — 구현 단계

2026-10-24. 이 v2는 **검색 코드의 새 버전**이며, 원래 예원 v2 KG를 새로 추출하거나 수정했다는 뜻이 아니다. 기존 comparison.py·Vector RAG·기준선 응답·점수를 유지하고 graph_v2.py와 별도 retrieval_policy.json을 추가했다.

## 변경 내용

1. **식별자 인식:** 영문·숫자·하이픈·밑줄 경계를 사용하여 `MAINT-03의`, `SOP-003과`처럼 한국어 조사가 붙은 ID를 인식한다. `MAINT-030` 같은 다른 긴 ID와는 구별한다. KG의 `candidate-문서::규칙` 식별자에서 원래 규칙 ID도 별칭으로 읽는다.
2. **문서별 후보 확보:** 질문에서 명시한 문서마다 최대2개 청크를 교대로 우선 배치한다. 전체 코사인 순위와 원문 단어의 희소성 가중 겹침 순위를 reciprocal rank fusion(RRF 상수60)으로 결합한다. 이는 BM25나 추가 학습 모델이 아니다. 최대 원문 후보24개다.
3. **원문 출처 우선:** 정확한 규칙 ID의 출처를 그래프 카드가 예산에 들어가는지와 무관하게 원문 후보에 넣는다. 이후 명시 문서별 후보, 그래프 방문 노드의 출처, 일반 검색 순으로 우선 배치한다. 원문 텍스트와 표는 자르지 않는다.
4. **관련 규칙 탐색:** 기존 구조 관계를 최대2홉·24노드로 탐색하고 원문/규칙 문자열에 명시된 RULE-/MAINT- 참조를 따라간다. 문자열 참조는 `text_reference_not_new_fact`로 기록하며 새로운 RDF 관계나 검증된 인과 사실로 KG에 추가하지 않는다.
5. **예산·추적 기록:** 원문 먼저, 간결한 그래프 카드 나중으로 합계4,000 기준 토큰 이내에 구성한다. 그래프 카드만 최대800토큰이다. 원문이 예산을 다 쓰면 그래프 카드가 0개일 수 있다. 전체 provenance는 로컬 추적 기록에 보존한다. 누락 문서, 예산 때문에 제외된 청크, 후보 수 제한, 후보 선정 사유와 실제 포함 노드를 기록한다.

문서별 후보 우선 배치는 모든 근거가 반드시 포함된다는 보장이 아니다. 큰 청크나 다수의 명시 문서 때문에 빠질 수 있으며 `uncovered_explicit_documents`로 확인한다. 문서가 직접 명시되지 않은 질문에는 명시 문서별 후보 확보가 적용되지 않는다. 한국어 동의어·조사 전체에 대한 형태소 분석이나 질의 재작성은 하지 않는다.

## API 없이 실행

검색만 제공하며 답변 생성 함수는 없다. 기존 질문 임베딩 캐시를 읽고, 캐시가 없으면 네트워크 호출 없이 오류를 반환한다. 정답·채점 파일을 읽거나 문항 ID별로 정답 근거를 지정하지 않는다.

저장소 루트 PowerShell:

```powershell
$env:PYTHONPATH='src'
$env:PYTHONUTF8='1'
..\.venv\Scripts\python.exe -m unittest discover -s tests -p test_graph_v2.py -v
# 캐시에 있는 정확한 질문 문자열과 새로운 출력 폴더를 지정한다.
..\.venv\Scripts\python.exe -m imaks_kg.rag.graph_v2 --question '기존에 임베딩한 질문' --run-dir kg_build/graphrag_v2_retrieval/new_run
```

검증 단계에서는 전체 순위·정답 근거 대조를 평가 전용 스크립트에서 따로 수행해야 한다. 정답 대조 결과를 검색 입력으로 되돌리지 않는다. 사용법의 예시 질문은 실행 가능한 기존 캐시 질문을 뜻하는 자리표시자다.

## 현재 완료 범위

2번 구현 완료. 합성 테스트7개와 실제 KG를 이용한 합성 검색 구성 점검을 수행했다. 기존 benchmark 전체에 대한 근거 회수율 비교는 **다음 3번**, 개선판의 유료 답변 생성·점수 비교는 **4번**이다. 현재 점수 개선을 주장하지 않는다. 이전 평가 결과를 본 뒤 만든 개선판이므로 같은24문항 재시험은 개발 개선 실험이다.
