## 구현·검증 연결

`queries/CQ1.rq`부터 `CQ5.rq`까지 실행 가능한 SPARQL 조회를 저장한다. 실제 결과는 `validation/competency_answers.json`이다. CQ1·CQ2는 정적 연결과 문서 규칙을, CQ3는 가정한 수치에 대한 안내를, CQ4·CQ5는 보류 판단에 필요한 근거와 적용 한계를 조회한다. CQ5는 SOP-004 권한 표의 원문 발췌와 SOP-001의 교육·역할 조건을 함께 반환한다.

검증은 행 수와 센서·단위·임계값·조치 대상·근거 문서 값이 예상대로 조회되는지 확인한다. 보류 이유는 설계자가 작성한 설명이며, 모델이 스스로 보류 결정을 내리는 능력을 자동 평가한 것은 아니다.

이 다섯 조회가 성공해도 전체 LLM 질의응답 정확도나 86건의 LLM 추출 정확도가 입증된 것은 아니다. 설치 부품·실제 고장 원인·실제 품질불량·교육 이수 여부는 현재 그래프의 사실로 추가하지 않는다.

## 다음 실험에 필요한 추가 데이터

- 실제 경보 설명: 탐지기가 생성한 경보 ID·관측 시각·센서·점수·사용한 모델 버전·과거 관측 근거. 정답 GT ID와 사후 대응 로그는 사용하지 않는다.
- 내부 부품 분석: 확인 가능한 설비 도면, BOM, 제조사 매뉴얼 및 설치 이력. SOP의 부품 점검 언급만으로 설치 인스턴스를 생성하지 않는다.
- 품질불량 분석: 검사 시각·배치·검사항목·측정치·불량 판정 근거. 온도 이탈이나 QC HOLD 권고만으로 실제 불량을 확정하지 않는다.
- 데이터시트 적용성: 실제 설치 센서 모델과 문서 모델의 대응 근거.
- 출입 최종 판정: hazmat 교육·자격 유효기간, 방문 승인과 문서 충돌에 대한 합의.
