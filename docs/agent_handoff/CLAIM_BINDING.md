# 사건 답변의 주장별 근거 연결

2026-11-14. Agent `incident-agent-v3-20261114`, 주장 계약 `incident-claim-binding-v1-20261114`.

## 적용 범위와 변화

관측·발동 근거가 연결된 **새 사건 설명 답변**에 적용한다. 모델이 자유 문장을 작성한 뒤 근거 ID만 붙이는 대신, 허용된 주장 ID를 선택하고 코드가 그 주장 문장으로 답변을 조립한다. 이 방식은 표현의 자유를 줄이고 각 문장의 출처를 확인할 수 있게 한다.

기존 문서 자유답변 Agent와 정형 KG 조회는 보존한다. 이 경로는 `claim_binding.status=not_applied`로 명시한다. 과거 답변도 재작성하거나 새 주장 검증을 수행했다고 소급 표시하지 않는다. 전체 앱의 모든 자연어를 검증했다는 주장은 하지 않는다.

## 네 종류의 주장

| 유형 | 확인하는 내용 | 근거와 검증 방식 |
|---|---|---|
| observation | 센서·시각·관측값·단위 | 고정 CSV 파일 해시, 관측 식별자, 봉인 알람과 일치 |
| condition | 실행 조건의 충족·재계산 일치 | `DEC-*` 검사 ID, 규칙, 지원 연산 계산, 원문 청크 |
| recommendation | KG에 저장된 조건·조건부 권고 표현 | 실제 KG 노드·필드 값과 원문 출처 연결 |
| interpretation | 과거 후보·검증 한계, 저장된 추정 유형 보고 | 코드가 정한 범위 문장·봉인 메타데이터. 새 자유 추론을 허용하지 않음 |

권고는 고정 KG의 표현을 그대로 사용한다. 원문으로부터 새로 번역하거나 의미를 독립 검증한 것이 아니다. 현재 설비에서 반드시 실행해야 한다는 승인이나 실제 실행 완료로 해석하지 않는다. 추정 유형도 저장 메타데이터를 보고하며 정답 판정은 아니다.

각 주장에는 `claim_id`, `claim_type`, `text`, `evidence_refs`, `values`, `validation`이 있다. 검증 상태는 근거가 연결된 `grounded`와 한계 표현인 `scope_statement`를 구분한다. `method`가 무엇을 확인했는지 설명하며 `domain_truth_certified=false`다.

## 생성·검사 순서

1. 기존 사건 도구·발동 근거 검사를 수행한다. 근거가 불일치하면 목록을 만들지 않는다.
2. 관측·조건·조건부 권고·한계 문장을 코드로 만들고, 내용과 사건 ID로 주장 ID 및 목록 해시를 고정한다.
3. 모델은 `{"claim_ids":[...]}`만 반환한다. 질문에 필요한 관측·조건을 선택하고 요청된 권고가 있으면 포함한다. 최대 16개를 고르며 한계 문장 2~3개는 코드가 자동으로 추가한다.
4. 목록에 없는 ID, 다른 사건의 ID, 중복, 자유 문장·추가 필드, 필수 관측/조건 누락을 거절한다.
5. 승인 가능한 주장만 원래 문장으로 조립한다. 수치·조치·새 해석을 모델이 다시 쓰지 않는다. 각 문장에는 `[CLM-...]` 식별자와 해당 원문 인용이 붙는다.
6. 기존 AI 검토로 질문 관련성·누락·조건부 표현을 점검한다. 통과한 경우만 `published=true` 및 최종 `claims`를 제공한다.

이 절차가 모델의 질문 이해·선택 완전성을 수학적으로 보증하지는 않는다. 일부 근거만 선택할 수 있으므로 관련성·빠진 항목은 검토 대상이다. 실제 모델의 새 답변 성능은 아직 실행·측정하지 않았다.

## 보류와 한 번 보완

잘못된 주장 선택은 답변에 섞지 않고 보류한다. 기본 설정에서는 그 시점에 종료한다. `repair_incident=true`인 경우 한 번만 올바른 ID를 다시 선택하도록 하고 모든 시도를 보존한다. 결정적 주장 검사에서 거절된 선택을 AI의 승인으로 덮어쓸 수 없다.

결정적 검사에서 이미 거절된 초안은 불필요한 AI 검토를 호출하지 않는다. 정상 경로의 최대 호출 수는 기존처럼 계획1 + 선택1 + 검토1이며, 선택적 보완에서는 최대 계획1 + 선택2 + 검토2다. 이번 개발과 검사에서는 모의 모델만 사용했다.

## UI 인계

질문 요청은 기존 `POST /api/agent`의 `question`·탐지·문서 옵션을 그대로 쓴다. 클라이언트가 직접 `claim_ids`를 제공하는 API가 아니다.

새 사건 답변의 최종 `claims`에는 게시된 주장만 들어간다. `xai.claim_binding`에는 선택 상태·시도·보류 사유·목록 해시가 있다. AI가 거절한 초안의 선택 항목도 진단용으로 남을 수 있으므로 `published`와 최종 `agent_status`를 함께 확인한다. 문장을 임의로 바꾸면 해당 주장과의 정확한 조립 일치가 깨진다.

원래의 4종 답변 파일에는 새 주장 ID가 없다. 화면 전달용 응답은 이를 `not_recorded`로 표시한다. 읽기 전용 서버의 다음 무료 조회로 **현재 만들 수 있는 주장 목록만** 확인할 수 있다.

`GET /api/claim-catalog/team_main_20261113_01`

이 응답은 `past_answer_claim_binding=not_performed`, 원 답변의 SHA-256을 함께 반환한다. 과거 답변의 문장들을 자동 분석해 검증한 결과는 아니다. 재점검에서 추가 조회한 출처도 별도로 표시한다.

## 오프라인 검증

고정 4방식 사건 178개에서 주장 목록 무결성과 코드 기반 최소 선택 규약을 검사했다. 가장 큰 목록은 47개 주장, 선택 입력은 최대 약 3,502토큰이었다. 모든 선택용 입력이 4,000토큰 예산 안에 들어왔다. [집계](claim_catalog_audit.json).

이 검사는 코드가 고른 최소 선택을 확인한 것으로, 실제 모델이 178개 질문에 적절히 답했다는 결과가 아니다. 같은 데이터의 중복 사용을 포함하며 정확도 점수로 사용하지 않는다.

```powershell
python scripts/check_claim_binding.py
```

변조 수치·자유 문장 삽입·다른 사건 ID·원문 없는 선택·목록 해시 변조·요청 항목 누락·과거 답변 보존과 기존 경로를 포함한 94개 무료 회귀 검사가 통과했다. 검토자에게 주장 ID를 전달하는 경로와 과거 표시도 후속 재검사했다. 예제 전체 응답은 원문 표현이 들어 있어 로컬 `kg_build/claim_binding_20261114/example.json`에만 둔다. 기존 복원 ZIP을 이용할 수 있으며 새 모델 가중치·임베딩은 필요하지 않다.
