## 실행 조건과 비용 기록

생성 요청·반환 모델 모두 `gpt-6.1-sol`이다. 각 질문은 이전 문항의 대화나 평가 피드백 없이 독립 요청했다. 임베딩은 `text-embedding-3-small`, 코사인 상위 8개, 컨텍스트는 `o200k_base` 기준 최대 4,000토큰, 출력 한도 4,096토큰이다. 6문항 모두 예산 초과로 제외된 검색 청크는 없었다.

이번에는 질문 임베딩 6회(합계 274토큰), 생성 6회(입력 6,679 + 출력 1,609 = 8,288토큰)를 사용했다. 기존 문서 임베딩 인덱스를 재사용했다. 이전 3단계의 문서 임베딩 7,037토큰은 위 사용량에서 제외했다. 실제 청구 금액은 조회하지 않았다. 재생성·자동 재시도 없이 첫 응답을 보존했다.

정답 파일은 API 입력이나 검색 코퍼스에 포함하지 않았다. 6개 응답이 모두 생성된 뒤 로컬 평가 파일과 대조했다. 질문·정답·채점 규약·원문·기존 v2 KG의 동결 해시 8개를 확인했다. 이 절차가 프로젝트의 과거 정답 노출 이력을 없애거나 독립 홀드아웃을 만드는 것은 아니다.

## 문항별 판정과 실패 분석

**Q01·Q06·Q11:** 요구한 범위·단위, 허용오차를 포함한 전류 수치, 공정 진행 순서를 각각 정확히 제시하고 올바른 규칙/표/절을 인용했다. Q11의 하류 전파 설명도 해당 원문에 있다.

**Q16:** 공정 경보 임계값과 데이터시트의 연속 정격을 구분하고 두 출처를 인용했다. 추가한 단시간 정격·지속 시간은 데이터시트 표와 Note 2에서 확인했다. 실제 설치는 조건부로 표현했고 문서를 임의로 수정하거나 연속 운전을 허용하지 않았다.

**Q21:** 필요한 `SOP-003:p1:table1:chunk`는 전체 코사인 검색 순위 **9위**여서 top8에 들지 못했다. 답변은 MAINT-03의 센서·발동 조건·조치·우선순위를 모두 답하지 못했다. 다른 유지보수 규칙을 설명했지만 해당 질문의 근거를 대체하지 못한다. 고정 기준 5절의 실질적 답변 없음 규정을 적용하여 전체 0점으로 판정했다. 검색 실패를 솔직히 밝힌 응답으로, 허위 사실 생성으로 분류한 것은 아니다. 충실성 0은 이 전체 0점 처리 규정의 결과다.

**Q26:** 실제 원인을 확정할 수 없다는 점과 과부하가 문서상 후보라는 점은 정확하다. 그러나 복합 정답 요소 3에서 요구한 작업자 명령 유무 확인이 빠졌다. 필수 조건 여러 개를 모두 충족해야 한다는 기존 기준을 적용해 요소 3은 0점이다. SOP-003 표 근거는 인정했지만 `RULE-ST04-03`은 인용하지 않았다. 이 규칙도 검색 순위 **9위**였다. 인용한 `RULE-ST02-04`에는 작업자 명령 전제가 없어 해당 근거 단위의 대체로 인정하지 않았다. 따라서 근거 1/2, 충실성 1로 총 3.5점이다.

이 순위 분석은 저장된 질문 벡터를 재사용한 **사후 진단**이다. 두 문항 모두 top8 경계 밖에 필요한 근거가 있다는 사실을 확인했지만, top-k를 늘렸을 때 점수가 실제로 오른다고 검증한 것은 아니다. 결과를 보고 이번 설정·답변·배점을 바꾸지 않았다. 검색 개선 실험은 필요할 경우 별도 버전으로 진행하고 현재 결과를 보존해야 한다.
