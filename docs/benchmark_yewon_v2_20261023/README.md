# 예원 v2 질의응답 벤치마크 실행·채점 안내

2026-10-23 작성·원문 검토. 사용자 위임에 따라 **1단계 원문 검토 완료, 2단계 사용자 위임에 따른 프로젝트 채점 기준 확정** 상태다. 16문항은 그대로 통과, 14문항은 수정 후 통과, 보류 0개다. 원본 PDF 7개/10쪽을 시각 확인하고 파일 해시·전처리 근거도 대조했다. 모델 비교 실행이나 성능 점수 산출은 아직 하지 않았다. 작성자와 검토자가 같은 AI이므로 독립 전문가 검토로 표현하지 않는다.

## 범위와 기준본

사용자가 선택한 예원 v2만 사용한다. `manifest.json`에 지정한 원래 v2 `graph/candidate.ttl` 및 추출 결과를 기준으로 고정했다. 이후의 정비 priority 추가 레이어, 관계 확장본, 다른 팀원 검증 모듈은 사용하지 않았다. 원래 v2의 구조화 누락도 임의 보정하지 않는다. 정답은 추출 결과를 복제하지 않고 전처리 원문에서 작성했다. 따라서 KG가 정보를 빠뜨린 경우도 그대로 드러날 수 있다.

ground_truth 86건 대조의 F1_content 86.19%는 **규칙 추출 평가**다. 이번 30문항은 **질의응답 평가**이며 QA 채점법은 사용자 위임으로 확정한 프로젝트 기준이다. 기존 팀의 규칙 추출 평가 기준을 대체하거나 이미 합의된 QA 기준이라고 주장하지 않는다. 이번 실행에서 팀 평가 원본 Markdown 2개는 해당 다운로드 경로에 없어 재확인하지 못했다.

## 산출물

- `문항목록.md`: 팀 분담용 30문항 목록.
- `questions_dev.jsonl`: 실행과 채점 연습용 6문항.
- `questions_eval.jsonl`: 비교 평가용 24문항.
- `manifest.json`: v2·원문·질문 파일과 정답 파일의 해시, 포함·제외 범위.
- 로컬 `evaluation/benchmark_yewon_v2_20261023/정답과_근거_PRIVATE.md`: 정답 요소, 오답 주의점, 문서·쪽·chunk·원문 인용.
- 같은 평가 폴더의 `answer_key_PRIVATE.json`: 기계가 읽을 수 있는 정답과 근거 위치·해시. 표와 연결된 Rule ID는 넓은 후보 목록이므로 모두 정답이라고 취급하지 않는다.
- 같은 평가 폴더의 `채점표_PRIVATE.csv`: 30문항 × 3방식 = 90행의 빈 채점표. 빈칸은 미채점이며 0점이 아니다.

정답과 채점표는 평가 전용 폴더에 두며 Git에서 제외된다. 질문 파일도 검색 코퍼스에 적재하지 말고 한 번의 질의 입력으로만 전달한다. 정답·작성 스크립트·기존 평가 매칭 파일을 검색 인덱스, KG, 추출 프롬프트에 넣지 않는다. 문서 원문 자체가 검색에 포함되는 것은 정상적인 RAG 설정이다.

## 분담안

실제 이름을 임의 지정하지 않고 담당1~5로 나눴다. 각 담당은 6개 유형을 하나씩, 총 6문항을 검토한다. 각 유형의 첫 문항이 dev이므로 담당1은 dev 6개를 맡는다. 담당2~5는 각각 eval 6개를 맡는다. 인원이 다르면 문항 ID 단위로 재배정한다.

검토는 제조 전문 지식을 추정해 추가하는 작업이 아니다. 제공된 원문에서 숫자·단위·부등호·기간·조치 대상·출처가 일치하는지 확인한다. 충돌 문항은 어느 문서가 실제 운영에서 옳은지 결정하지 않고, 두 출처를 정확히 병기하는지를 본다. 도메인 전문가 승인·현장 안전성 검증을 받았다고 표현하지 않는다.

문항 원문 대조는 사용자 위임으로 AI가 완료했다. 문항별 판정·이유·수정 전 내용은 평가 폴더의 `source_review_PRIVATE.json` 및 `원문검토_결과_PRIVATE.md`에 기록했다. 사용자 위임으로 2단계 채점 기준을 확정하고 scoring_lock_v1.json에 질문·정답·채점 해시를 고정했다. 팀 전체의 별도 승인이라고 표현하지 않는다. 비교 실행 결과를 본 뒤 문제나 채점표를 유리하게 고치지 않는다. 불가피한 오류 수정은 변경 이유와 영향을 공개하고 세 방식 모두 같은 버전으로 재평가한다.

## 세 방식의 비교 조건

1. 같은 생성 모델·버전·공통 답변 지침·출력 토큰 한도를 사용한다. 가능하면 동일한 temperature와 seed를 사용하고 지원되지 않는 설정은 기록한다.
2. LLM 단독은 질문만 입력한다. 이는 폐쇄형 지식 조건이므로, 성능 차이는 모델 능력뿐 아니라 자료 접근 차이를 포함한다고 명시한다.
3. Vector RAG는 동일한 SOP 4개·데이터시트 3개의 전처리 원문을 검색한다.
4. GraphRAG는 같은 원문 집합 및 그 자료와 seed에서 만든 고정 예원 v2 KG를 사용한다. 문항·정답은 KG에 추가하지 않는다. 정답을 검색 컨텍스트로 제공하지 않는다.
5. Vector RAG와 GraphRAG는 검색 컨텍스트 토큰 예산·생성 모델을 맞춘다. top-k, 검색 방식, 그래프 탐색 깊이, seed 구조 사용 여부는 기록한다. 문서 비교 문항을 답하기 위해 GraphRAG가 원문 검색을 보조 사용하는 경우도 명시한다.
6. dev 6문항으로 입출력·검색·채점 절차만 점검한 후 설정을 고정한다. eval 24문항은 독립 세션으로 실행하고, 이전 문항 정답/평가 피드백을 다음 질문에 전달하지 않는다.
7. 문항별 답변, 인용, 실제 검색 컨텍스트 ID, 모델 설정, 실행 시각, 지연 시간, 토큰 사용량을 저장한다. 오류는 삭제하지 않고 오류율과 재시도 정책을 함께 기록한다.

공통 답변 지침 예시:

> 주어진 질문에 한국어로 답하라. 제공된 근거가 있으면 문서 ID와 쪽 또는 규칙·표 위치를 인용하라. 숫자·단위·부등호·기간·대상을 보존하라. 서로 다른 문서의 규정을 임의로 합치지 말라. 실제 상태나 인과관계를 확인할 자료가 없으면 한계를 명시하라. 제공되지 않은 근거나 확률을 만들어내지 말라.

## 확정 채점 기준

[채점기준_확정_v1.md](채점기준_확정_v1.md)가 유일한 현재 채점 기준이다. 기존 초안의 모호한 판정 문구는 이 기준으로 대체한다.

- 내용 요소 3개(각 0/1), 근거 0~1, 충실성 0/1: 합계 5점.
- 주 지표는 eval 24문항 평균 QA 총점. 완전 정답률과 내용·근거·충실성 지표를 함께 보고한다.
- 비공개 평가 폴더의 `문항별_채점체크리스트_PRIVATE.md` 및 `채점예시_PRIVATE.md`로 판정한다.
- `scoring_lock_v1.json`은 입력·기준 해시를 고정한다. 예시는 인위적으로 만든 채점 연습 사례이며 모델 성능 측정이 아니다.
- 다음은 3단계 Vector RAG 구현이다. 비교 시스템 실행과 채점은 아직 하지 않았다.

## 해석상의 한계

6개 유형 × 5개 = 30개이며 유형마다 dev 1개/eval 4개이다. 같은 문서와 일부 같은 규칙이 반복되므로 이 분할은 **운영용 분리**이며 규칙·문서 수준의 독립 홀드아웃이 아니다. 작성 과정은 예원 v2와 원문을 알고 있고 과거 정답 노출 이력도 없어지지 않는다. 고정 코퍼스에서 세 시스템의 응답 품질을 비교하는 개발 벤치마크로 보고한다. 문항 수가 작고 중복 근거가 있어 근소한 차이를 일반적인 우열로 확대하지 않는다.

문서에 이미 있는 관계의 검색·설명 성능을 평가하며 새로운 인과관계 발견이나 실제 설비 진단 안전성을 입증하지 않는다. 현재 시계열·실제 이벤트를 입력하지 않으므로 실제 이상 탐지율도 측정하지 않는다.
