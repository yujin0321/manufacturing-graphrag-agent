# 저장된 그래프 관계 탐색의 답변 기여 비교

2026-10-28. 예원 v2 KG 고정, 기존 평가용 24문항의 개발 재시험.

**결론: 이번 실험에서는 저장된 관계 탐색을 켜도 답변 점수의 추가 향상이 관찰되지 않았다.** OFF와 ON 모두 120/120점이며 문항별 24개가 모두 동률이다. 이는 그래프 전체의 무효성이나 일반적인 성능 동등성을 입증하지 않는다.

## 실험 범위

동일 모델 `gpt-6.1-sol`에 같은 질문·시스템 지시문·최대 출력 4,096토큰을 사용했다. 각 조건별 24개, 총 48개 답변을 새로 생성했다. 반환 모델 ID도 48개 모두 `gpt-6.1-sol`이었다. 기존 GraphRAG 답변을 재사용하지 않았다. temperature/seed는 기존 설정과 같이 생략했다.

OFF에서는 `traverse_predicates=[]`, ON에서는 `appliesToSensor`, `actionTarget`, `hasSensor`, `feedsInto`를 탐색한다. 원문 규칙 참조 알고리즘, KG 노드의 식별자·출처 매핑, 공통 벡터·어휘 순위, ID 우선 검색, 시작 노드 선정, 탐색 상한은 유지했다. 따라서 OFF도 KG의 매핑을 사용하는 검색기이며, 순수 Vector RAG와 같지 않다. 그래프 카드는 두 조건 모두 제공하지 않았다.

측정 대상은 **현재의 원문 참조·출처 매핑 검색기에 네 종류의 저장된 관계 탐색을 추가하는 증분 효과**다. 탐색으로 새로 도달한 노드의 원문 참조 및 제한된 탐색 예산 내 경쟁도 포함한다. 온톨로지 전체나 카드 표현의 효과를 측정한 것은 아니다.

입력은 이전 오프라인 작업에서 동결한 최대 24청크·4,000토큰 컨텍스트를 사용했다. 평가용 24문항 중 23문항의 컨텍스트가 다르고, 20문항의 청크 집합이 다르다. Q23은 컨텍스트가 완전히 같으며 두 번 따로 생성했다. 조건별 실행 순서를 문항마다 교차했다.

## 팀 기준 채점 결과

팀의 기존 `채점기준_확정_v1.md`를 그대로 적용했다. 내용 3개 각 0/1점, 근거 0~1점, 충실성 0/1점이다. 생성 완료 후 48개 응답을 무작위 익명 ID R01~R48로 섞어 OFF/ON 표시를 가리고 읽었다. 원문·정답 요소·추가 설명의 출처를 대조하여 명시적인 AI 판정을 기록하고, 판정 파일 작성 후 조건별로 집계했다. 별도의 유료 채점 API는 호출하지 않았다.

| 지표 | 저장 관계 OFF | 저장 관계 ON | ON−OFF |
| --- | ---: | ---: | ---: |
| 총점 | 120/120 | 120/120 | 0 |
| 평균 QA 점수 | 5.00/5 | 5.00/5 | 0.00 |
| 완전 정답 | 24/24 | 24/24 | 0문항 |
| 내용 충족률 | 100% | 100% | 0%p |
| 근거 충족률 | 100% | 100% | 0%p |
| 충실성 비율 | 100% | 100% | 0%p |
| 실행 실패 | 0/24 | 0/24 | 0 |
| 필수 근거 회수 | 35/35 | 35/35 | 0 |

개선 0문항, 동률 24문항, 악화 0문항. 여섯 문항 유형 모두 각 조건 4문항·20/20점이다. 판정보류는 없다. 이번 실행에서 팀 기준상 실패 사례는 발견되지 않았다.

한 번의 생성 반복에서 모든 문항 차이가 0이라 문항 단위 paired bootstrap 10,000회 구간도 [0, 0]으로 퇴화한다. 이것을 실제 성능 차이에 불확실성이 없다는 뜻으로 해석하지 않는다. 포화된 점수와 제한된 24문항, 생성 반복 1회의 한계가 있다.

## 사례와 해석

- **Q13 — 규칙 참조 추적:** 두 조건 모두 작업자 명령 없음·0.95<1.00 m/s를 확인하고 RULE-ST04-03 → RULE-ST02-04 → ST02 전류 확인을 설명했다. 원문 참조 탐색은 OFF에도 있으므로 이런 성공만으로 저장된 RDF 관계의 효과를 주장할 수 없다.
- **Q28 — 시차·확률 한계:** 두 조건 모두 RULE-ST02-04와 일반 CORRELATED의 90분 정의를 인용하고, 이를 실제 측정 시차·확률로 사용할 수 없다고 답했다. 이전 B/C 실험에서 B가 놓쳤던 근거는 이번 OFF에서도 회수됐다. 이전 B는 원문 참조 확장까지 껐지만, 이번 OFF는 그것을 유지하기 때문이다.
- **Q23 — 동일 입력 대조:** 두 조건 모두 technician 2분, supervisor 1분, 차이 1분 및 경보 확인과 정비 완료의 구별을 충족했다. 문장 형태는 달랐으나 점수는 같았다.
- **Q29 — 검색 발췌 범위:** 한 답변(R29)은 SOP-001/002/003 발췌만 제공됐다고 덧붙였다. 해당 입력의 실제 SOP 문서 집합을 확인해 사실과 일치함을 검증했다. 전체 코퍼스에 SOP-004가 없다고 주장한 것이 아니다. 설치 모델 미확정·추가 자산 매핑 필요 및 두 요구 출처를 충족하므로 감점하지 않았다.
- **R19/Q30 — 표현상의 한계:** SOP-002 공칭값을 설명하면서 일반명칭 ‘데이터시트’를 사용한 부분은 부정확하다. 다만 정확한 SOP-002 표 인용, 수치 및 현재값과의 구별은 명확하여 기존 기준상 새로운 감점을 추가하지 않았다. 5점은 문체까지 완벽하다는 의미가 아니다.

두 조건 모두 필수 근거를 이미 100% 회수했다. 최종 입력에 포함된 부가 청크·순서는 바뀌었지만 이 문항 집합의 정답 요소·인용 점수에는 추가 이득이 없었다. OFF는 그래프 전체 제거가 아니므로 이 결과를 기존 Vector RAG 106.5점과 직접 비교해 인과 효과를 계산하면 안 된다.

## API 사용량과 보존

| 항목 | OFF | ON | 합계 |
| --- | ---: | ---: | ---: |
| 입력 토큰 | 76,310 | 81,426 | 157,736 |
| 출력 토큰 | 8,195 | 8,094 | 16,289 |
| 총 토큰 | 84,505 | 89,520 | 174,025 |

API 요청 48회, 정상 응답 48개, 로컬 응답 캐시 재사용 0회, 새 임베딩 0회, 자동 재시도 0회. API가 보고한 캐시된 입력 토큰은 총 3,305개이며 로컬 응답 재사용과 다르다. 정확한 달러 청구액은 계정 Usage/Billing에서 확인해야 하며, 이 보고서는 청구액을 추정하지 않는다.

ON은 이번 실행에서 입력 토큰이 5,116개(약 6.7%), 총 토큰이 5,015개(약 5.9%) 더 많았다. 평균 원문 컨텍스트 토큰은 OFF 2,847.71, ON 3,060.50이다. 이 수치는 API 메시지 포맷·지시문을 포함한 입력 토큰과 다르다.

실행·채점 결과는 로컬에서 약 0.83 MB를 차지한다(보고서·후속 봉인 파일 제외). 추가 모델 설치는 없다. 기존 기준선 699개 파일은 작업 중 다시 검증해 변경 없음을 확인했다. 운영 검색 코드·v2 KG·기존 결과를 덮어쓰지 않았다. 커밋·푸시는 수행하지 않았다.

## 재현 파일

- 준비: `scripts/prepare_stored_edge_ablation.py`, `kg_build/stored_edge_ablation_20261028/`
- 실행: `scripts/run_stored_edge_answers.py` — 기본은 검증만, `--execute`에서만 API 호출. 이전 응답은 보존하며 미해결 시도를 자동 재전송하지 않는다.
- 실행 봉인: `kg_build/stored_edge_answers_20261028/run_lock.json`, `complete.json`
- 채점 준비/집계: `scripts/review_stored_edge_answers.py prepare|aggregate`
- 원문 대조 판정: `evaluation/stored_edge_answers_20261028/decisions_PRIVATE.json`
- 익명 검토 자료·매핑: 같은 폴더의 `packets_PRIVATE.json`, `mapping_PRIVATE.json`
- 집계: 같은 폴더의 `summary.json`, `paired.json`, `scores_PRIVATE.json`, `retrieval_and_execution.json`

생성 스크립트는 정답 파일을 읽지 않는다. 생성 입력과 응답은 해시로 검증하며, 채점 준비는 48개 생성 완료 봉인이 있어야 실행한다. API 호출 형식은 기존 구현을 유지했고 [OpenAI Chat Completions 공식 문서](https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create)를 확인했다.

## 보고할 수 있는 결론과 다음 선택

> 기존 24문항의 개발 재시험에서 원문 참조 탐색과 출처 매핑을 유지한 채 저장된 네 종류의 관계 탐색만 비교했다. 두 조건 모두 평균 5.00/5점으로, 해당 탐색의 추가 답변 성능 이득은 관찰되지 않았다. ON의 입력 토큰은 더 많았다.

익명화는 조건명에 대한 선입견을 줄이는 조치이며, 기존 정답 노출을 없애지 않는다. 채점은 AI 단독이며 독립적인 인간·도메인 전문가 검증이 아니다. 이번 결과를 미노출 일반화 성능이나 관계의 안전성·신규 인과관계 검증으로 표현하지 않는다.

현재 프로젝트 보고에는 이 결과를 그대로 포함하면 된다. 그래프의 다른 이점을 계속 평가한다면 출처 추적 가능성·명시적 관계 조회·제약 검증을 답변 정확도와 구분해서 제시할 수 있다. 추가 QA 실험은 필수가 아니다. 새로 한다면 점수가 오르는 문항만 고르지 말고, 실행 전에 원문에 근거한 평가 목적·문항 집합·예산을 고정해야 한다.
