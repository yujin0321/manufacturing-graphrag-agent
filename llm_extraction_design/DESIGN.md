# 설계: 문서 전체를 읽는 규칙 추출

## 입력과 책임 분리

입력은 source-only JSON 7개와 input_manifest.json이다. manifest에 기재된 9개 파일(문서 7개, ontology.ttl, shapes.ttl)의 SHA-256을 먼저 검증한다. manifest 자체 해시는 추적용으로 계산하며 외부 신뢰값이 없는 상태에서 진위를 주장하지 않는다.

요청 준비 코드는 선택 문서의 document_id, inventory, units를 그대로 전달한다. source 내부 prompt, ontology의 과거 평가/설계 주석은 모델 지시문으로 사용하지 않는다. 검증된 4개 클래스 계약을 사용한다. 기존 추출 결과·기대 건수·점수는 입력에 넣지 않는다.

한 문서의 모든 본문/표 단위를 한 요청에 넣는다. 행을 규칙으로 바꾸는 파서를 만들지 않는다. 모델이 조건/조치/클래스/대상을 판단하며 프로그램은 해시·포장·검증을 맡는다. 문서가 컨텍스트를 넘으면 임의 절단하지 않고 중단한다. 분할 방식은 제목·표 연속성 보존 설계를 별도로 검토해야 한다.

## 출력 계약과 원자화

- 독립 조건을 분리하고 같은 조건의 연속 조치는 유지한다. 동일 심각도 상·하한은 같은 조치의 대안 조건으로 함께 표현할 수 있다.
- 원문 ID 보존, 분할 시 원 ID 접미사. 없는 ID는 DOCID-EX-001 형식.
- sourceQuote는 unit_id text의 정확한 부분 문자열. 조치 없는 문장은 responseText="".
- sensorIds와 actionTargets는 명확한 inventory 항목만. 데이터시트 모델을 설치 센서로 가정하지 않는다.
- 숫자·부등호·단위·기간·부정·권고/필수 및 문서 간 차이를 보존한다.
- numeric/priority는 API 스키마에서는 nullable 필수 키이다. 검토본/최종 JSONL에서는 null 값을 제거한다. 숫자가 일부만 근거 있으면 나머지 numeric 값은 null.
- coverage는 모든 원문 단위에 포함/제외 사유 및 연결 규칙 ID를 기록한다. 숫자는 예상 건수에 맞추지 않는다.

## 예정된 실행 단계

1. 입력 해시와 프롬프트/스키마 해시 기록 → 문서 전체 요청 JSON 준비. 현재 구현됨.
2. 명시적인 실호출 모드에서만 API 요청. API 키는 환경변수 OPENAI_API_KEY로 주입하고 로그/파일/Git에 기록하지 않는다. 현재 미구현.
3. 응답 원문을 raw_responses에 독점 생성 모드로 저장. 성공/실패·refusal·incomplete 및 response ID, 요청/응답 모델 ID, 토큰 사용량 기록. 현재 미구현.
4. status가 completed이고 refusal이 없을 때만 JSON 파싱. 원문은 보존하고 reviewed를 별도 생성. 현재 미구현.
5. 클래스/필수 필드/유한 숫자/중복 ID/정확 인용/inventory/coverage/분할 ID 계보 검사. 의미적 검토는 별도이며 기계 검사를 사람 검토로 표시하지 않는다. 현재 미구현.
6. 모든 문서가 검증을 통과한 경우에만 predictions.jsonl을 만들고 입력·출력 manifest로 고정한다. 부분 성공을 전체 완료로 표시하지 않는다. 현재 미구현.

## 오류 및 비용 처리 요구사항

- 크레딧/할당량 부족 오류는 자동 반복하지 않고 중단하여 상태를 기록한다.
- 인증·스키마 오류는 수정 전 재시도하지 않는다.
- 일시적 rate limit/서버 오류 재시도는 상한과 backoff를 두되 오류 종류를 구분한다.
- 불확실한 timeout 후 무조건 재전송하지 않는다. 중복 호출 비용 가능성을 실행 기록에 남긴다.
- 출력 잘림/incomplete, refusal, 잘못된 JSON은 완료로 취급하지 않는다. 원문 응답을 보존한다.
- 문서/프롬프트/스키마/모델/옵션 해시가 동일한 검증 완료 건만 재사용한다. 존재 여부만으로 건너뛰지 않는다.
- 동시성 1, 명시적 문서 제한으로 한 문서 smoke test부터 시작한다. 예상 비용과 지출 상한은 모델 선택 뒤 확정한다. max_output_tokens는 비용 총액 상한이 아니다.

## API 연결 재개 조건

크레딧과 호출 권한, 대상 모델의 Structured Outputs/컨텍스트 지원, 허용 지출 범위가 확인되어야 한다. 이후 transport 및 응답 검증기를 구현하고 한 문서 실호출을 통과한 뒤 7개 문서로 확장한다. 실호출 전에는 추출 성능·정답 점수·API 성공을 주장하지 않는다.
