# 예원 v2 QA 벤치마크 채점 기준 v1

2026-10-23. 사용자가 기준 설정을 위임하여 이 프로젝트의 실행 기준으로 확정했다. 팀원 전체의 별도 동의나 제조 전문가 인증을 받았다는 뜻은 아니다. 적용 대상은 원문 검토를 마친 30문항(dev 6 / eval 24)이며, 모델 응답을 보기 전에 기준을 고정한다.

## 1. 무엇을 평가하는가

제공된 제조 문서에 근거해 질문에 정확하고 추적 가능한 답을 하는지를 평가한다. 실제 설비 운전 허가, 안전성 인증, 신규 인과관계 발견, 이상 탐지율은 평가하지 않는다. 원문이 충돌하면 출처별 내용을 구분하는 것이 정답이다. 채점자가 현장 상식을 보태 어느 문서가 옳은지 결정하지 않는다.

정답 권위 순서는 ① 해당 질문의 지정 원문 ② 원문 검토가 완료된 정답 요소/문항별 메모 ③ 이 채점 기준이다. 정답표에 오류가 의심되면 모델별 임의 예외를 주지 않고 해당 문항을 `판정보류`로 둔다. 원문 확인 후 같은 버전의 세 시스템 모두에 동일하게 판정한다. 원문·문항을 바꿔야 한다면 새 버전과 변경 이유를 남긴다.

## 2. 문항별 5점

| 항목 | 배점 | 판정 |
|---|---:|---|
| 필수 정답 요소 1 | 0 또는 1 | 정답표의 첫 요소를 모두 충족하면 1 |
| 필수 정답 요소 2 | 0 또는 1 | 정답표의 둘째 요소를 모두 충족하면 1 |
| 필수 정답 요소 3 | 0 또는 1 | 정답표의 셋째 요소를 모두 충족하면 1 |
| 출처 근거 | 0~1 | 필요한 근거 단위 중 정확히 인용·연결한 비율 |
| 충실성 | 0 또는 1 | 질문 관련 실질적 답변에 원문 왜곡·무근거 단정이 없으면 1 |

**총점 = 내용 3개 점수 합 + 근거 점수 + 충실성 점수.** 내용 요소 내부의 0.5점은 사용하지 않는다. 하나의 요소에 필수 조건이 여럿 있으면 모두 맞아야 1점이다. 내용이 모두 맞아도 근거가 없으면 최대 4점이다. 정답표에 없는 추가 설명을 필수로 요구하지 않는다.

**완전 정답 = 내용 3/3, 근거 1/1, 충실성 1/1을 모두 충족한 답변.** 소수 표시를 반올림해 5점으로 보인다고 완전 정답으로 처리하지 않는다. 실제 충족 여부로 판정한다.

## 3. 내용 판정의 세부 규칙

1. **뜻이 같으면 인정:** 한국어·영어, 자연스러운 동의어, 공정의 명확한 약칭은 인정한다. 예: emergency stop / 비상 정지. 숫자 식별자인 ST02를 ST03으로 바꾸는 것은 동의어가 아니다.
2. **숫자와 단위:** 13.5와 13.50은 같다. 정확한 단위 변환은 인정한다. 질문·표 머리말에서 단위가 명확히 공유되면 답변의 모든 숫자에 단위를 반복할 필요는 없다. 단위를 알 수 없거나 틀리면 해당 요소는 0점이다. 측정 오차를 이유로 정답 수치를 임의로 반올림하거나 바꾸는 것은 인정하지 않는다.
3. **부등호와 시간:** `>`, `≥`, `<`, `≤`는 구분한다. 지속 시간과 변화량도 보존한다. 문항 Q10처럼 경계 판정이 핵심이면 ‘초과’를 ‘이상’으로 바꾼 답은 오답이다. 범위를 모호하게 쓰면 해당 요소를 충족하지 못한 것으로 판정한다.
4. **조건 조합:** 수치 조건과 시간 조건이 함께 있으면 둘 다 필요하다. 명목 대비 증가량을 절대값으로 해석하지 않는다. 작업자 명령 유무처럼 명시된 전제도 생략해 일반화하지 않는다.
5. **조치와 대상:** 필수 조치 또는 대상 하나라도 빠지면 그 요소는 0점이다. 여러 정답 요소에 같은 표기 오류가 영향을 주는 경우 실제로 틀린 요소들에 각각 반영한다. 다만 인용 누락만으로 내용 점수를 깎지 않는다.
6. **순서:** 순서를 묻는 Q14는 각 조치가 원문의 단계 위치와 일치해야 그 요소가 1점이다. 번호 없이도 ‘먼저→다음→마지막’이 명확하면 인정한다. 원문에 없는 실행 순서는 추가하지 않는다.
7. **문서 비교:** 두 문서가 다르면 양쪽 값·조건을 각각 귀속시켜 답해야 한다. 최신 날짜라는 이유만으로 자동 우선 적용하지 않는다. 서로 다른 사양을 한 값으로 합치지 않는다.
8. **정보 부족:** Q26~Q30은 문서 내용과 알 수 없는 실제 상태/확률/설치 정보 등을 구별한다. ‘모르겠다’ 한마디만으로 세 요소가 모두 맞는 것은 아니다. 질문이 요구하는 이유와 한계·추가 자료까지 정답표대로 평가한다.
9. **가정:** 질문의 가상 관측값은 사실 조회 결과가 아니다. 이를 실제 센서에서 측정했다고 답하면 충실성 오류다. 질문의 가정에 따른 문서 규칙 적용은 허용한다.

## 4. 근거 점수

근거 단위는 정답 JSON의 `evidence` 항목이다. 동일 chunk 중복 인용은 한 번만 센다. **근거 점수 = 충족한 근거 단위 수 / 필요한 근거 단위 수.** 두 개 중 하나를 충족하면 0.5점이다.

각 단위가 인정되려면 다음 두 조건을 모두 충족해야 한다.

- 답변에서 식별 가능한 출처를 제시한다: 정확한 chunk ID, 또는 문서 ID+규칙 ID, 또는 문서 ID+쪽/절+표의 대상 행. 문서명만 나열하는 것은 0이다. 유일한 규칙 ID를 정확히 붙인 경우 쪽 번호를 별도로 반복하지 않아도 된다. 표는 센서/정비 ID/역할 등 해당 행을 식별해야 한다.
- 인용 위치가 실제 답변 주장을 뒷받침한다. 관련 없는 근거를 그럴듯하게 붙이면 인정하지 않는다. 잘못된 주장을 맞는 문서 이름에 연결해도 인정하지 않는다.

사실과 직접 연결된 출처를 한 문장에 묶어 인용해도 된다. 원문 인용 전문을 복사할 필요는 없다. 인용을 본문과 분리하더라도 주장과의 연결이 명확하면 인정한다.

같은 주장을 충분히 뒷받침하는 대체 위치는 원문을 확인하고 해당 근거 단위의 대체로 인정할 수 있다. 이유와 대체 chunk를 채점표에 남긴다. 한 위치를 여러 단위의 대체로 인정하려면 각 단위의 필수 주장을 모두 실제로 뒷받침해야 한다. 두 출처 비교 질문에서는 한 문서만으로 두 문서의 근거를 대체할 수 없다.

자료 부재는 관련 두 문장만으로 증명되는 것이 아니다. Q26·Q28·Q29·Q30에서는 ‘제공된 정적 문서 범위에서 확인 불가’임을 설명하고, 확인 가능한 규칙/사양에는 관련 근거를 연결하면 평가할 수 있다. 이 기준은 전체 공장에 정보가 없다는 주장을 허용하지 않는다.

## 5. 충실성 및 오류 기록

질문에 답하려는 실질적인 내용이 있고 원문에 반하는 단정·무근거 구체적 주장·허위 인용이 없으면 1점이다. 일부 내용 누락만 있으면 내용 점수에서 반영하고 충실성까지 자동 감점하지 않는다. 관련 있고 원문으로 확인되는 추가 설명은 허용한다. 권고나 추정은 사실과 구별되어야 하며, 문서의 필수 지시처럼 표현하면 안 된다.

다음 중 하나라도 있으면 충실성 0점이다.

- 원문과 다른 수치·단위·조건·대상을 정답처럼 단정한다.
- 존재하지 않는 문서/규칙/인용을 만들어내거나 실제로 뒷받침하지 않는 출처를 근거라고 주장한다.
- 자료 없는 실제 원인·발생 확률·현재 센서값·제어 실행 여부·설치 모델을 확정한다.
- 정답과 반대되는 대안을 함께 제시하고 어느 것이 답인지 정리하지 않는다.
- 문서에 없는 운전 허용·필수 조치를 만들어내거나 경보 미발동을 안전 보장으로 바꾼다.

틀린 수치를 말한 경우 해당 내용 요소 0점과 충실성 0점이 함께 적용될 수 있다. 두 항목은 ‘필수 내용 충족’과 ‘답변 전체의 왜곡 여부’를 각각 측정한다. 반면 출처를 아예 쓰지 않은 것만으로 충실성을 0점으로 만들지는 않는다.

빈 답변, 실행 실패, 질문을 그대로 반복한 답변, 무관한 답변은 전체 0점이다. 답할 수 있는 질문에 단순히 ‘모른다’고만 답한 경우도 전체 0점이다. 답변 한계 문항에서 정보 부족을 정확히 밝히면 해당 정답 요소를 인정하고 충실성은 별도 판정한다.

채점표 `reason`에 다음 오류 코드를 필요한 만큼 기록한다. 새 감점을 추가하는 코드는 아니며 실패 분석용이다.

| 코드 | 의미 |
|---|---|
| NUM / UNIT | 수치 / 단위 오류 |
| COND / TIME | 부등호·전제 / 시간 조건 오류 |
| ACTION / TARGET / ORDER | 조치 / 대상 / 절차 순서 오류 |
| MISS | 필수 내용 누락 |
| CITE_MISSING / CITE_FALSE | 인용 누락 / 허위·오귀속 인용 |
| CONFLICT | 출처 차이를 임의 통일 |
| UNSUPPORTED | 무근거 원인·확률·실제 상태 등 단정 |
| NO_ANSWER / EXEC_ERROR | 실질적 답변 없음 / 실행 실패 |

## 6. 보고 지표와 비교 원칙

비교 평가용 **eval 24문항만** 주 결과에 사용한다. dev 6문항 결과는 별도로 표시한다.

| 지표 | 계산 |
|---|---|
| 주 지표: 평균 QA 총점 | 24개 총점의 합 / 24, 5점 만점 |
| 완전 정답률 | 완전 정답 수 / 24 × 100 |
| 내용 충족률 | 내용 점수 합 / 72 × 100 |
| 근거 충족률 | 근거 점수 합 / 24 × 100 |
| 충실성 비율 | 충실성 점수 합 / 24 × 100 |
| 실행 실패율 | EXEC_ERROR 문항 수 / 24 × 100 |

유형별 4문항 점수도 보고한다. 판정보류가 있으면 공식 최종 점수를 확정하지 않는다. 임시 결과를 제시할 때는 제외 개수·사유·실제 분모를 표시하고, 세 시스템에서 같은 문항 집합으로 계산한다. 오류 문항을 조용히 제외하지 않는다. 시스템 실패는 판정보류가 아니라 0점/실패율로 기록한다.

LLM 단독은 자료 접근이 없으므로 근거 점수가 불리할 수 있다. 따라서 총점만으로 생성 모델의 우열을 주장하지 않고 내용·근거 지표를 나란히 보고한다. 같은 모델의 자료 접근 방식 차이를 비교한다. 24개는 소규모이며 문항 간 근거 중복도 있으므로 근소한 차이에 통계적 우월성 주장을 붙이지 않는다.

## 7. 채점 절차와 동결

1. 같은 질문·공통 지침·모델 설정으로 응답을 수집하고 검색 근거 ID를 보관한다. 정답 파일은 모델 입력·검색 대상에서 제외한다.
2. 채점할 때는 시스템 이름을 익명 코드로 바꾼다. 답변과 정답 요소 3개, 원문 근거를 비교한다.
3. 내용 세 칸을 0/1로 기록하고, 인정한 근거 위치와 충실성 판정 이유를 `reason`에 적는다. AI가 채점하면 reviewer에 AI 사용 사실을 적는다. 사람 채점·합의로 가장하지 않는다.
4. 산식에 따라 total 및 strict_correct를 기록한다. 소수는 집계 후 표시 단계에서만 반올림한다. 빈 점수 칸을 0으로 자동 취급하지 않는다.
5. 가능하면 별도 검토자가 재채점한다. 불가한 경우 AI 단독 채점임을 보고하고, 다른 세션 재점검도 독립 인간 검토라고 표현하지 않는다.

이 버전은 사용자 위임으로 확정된 프로젝트 기준이다. 문항·정답·원문·기준 문서의 해시는 `scoring_lock_v1.json`에 기록한다. 성능 결과를 보고 배점이나 문항을 바꾸지 않는다. 불가피한 오류 수정은 새 버전으로 만들고 영향을 받는 세 시스템 모두에 적용한다. 새 채점 기준은 기존 추출 F1_content 86.19%와 별도이며, 이를 재계산하거나 대체하지 않는다.

다음 단계는 **3번 Vector RAG 구현**, 이후 **4번 dev 6문항 시험**이다. 본 기준 확정 작업에서는 두 단계를 실행하지 않았다.
