# 온톨로지 개선 진단 — 1단계 질문 및 근거 고정

후속 실행 완료: [현재 v2 실행·원인 분류 보고서](../../reports/ontology_diagnostic_20261027_verify.md). 아래는 실행 전에 고정한 질문 설계 기록이다. 실제 8건 실행에서 필수 내용의 불일치는 발견하지 못했으나 OD-08의 일본어 출력 문제가 확인됐다. 온톨로지 원인 실패는 입증되지 않았다.

2026-10-27. 원래 예원 v2 KG(2,806트리플)를 고정한 개발 실험이다. 이 단계에서는 질문 8개와 원문 대조 기준을 준비했다. 아직 GraphRAG 답변을 실행하거나 실패 사례를 판정하지 않았다. 모델 비교·KG 교체·온톨로지 변경은 하지 않는다.

## 진단 질문

질문만 담은 실행 입력은 [questions.json](questions.json)이다.

| ID | 진단 대상 | 확인하려는 점 |
|---|---|---|
| OD-01 | 규칙 참조 정방향 | 조건과 참조 규칙의 근거를 함께 회수하는가 |
| OD-02 | 규칙 참조 역방향 | 명시적 지시와 단순 동시 출현을 구분하는가 |
| OD-03 | 온도·지속 시간 경계 | 초과와 이상, 정확히 5분과 5분 초과를 구분하는가 |

현재 규칙 참조 텍스트를 검색하는 기능이 있으므로 OD-01/02가 반드시 실패한다고 가정하지 않는다. 모두 정확히 답한다면 억지로 실패 사례를 만들거나 온톨로지 수정을 필수라고 주장하지 않는다.

## 원문 확인과 실행 전 고정

원문은 기존 검증된 7개 문서·86개 청크에서 가져왔다. 질문별 근거 청크 ID, 페이지, 인용문, 청크 해시, 필수 답변 요소, 금지할 오해를 별도 평가 파일에 저장했다. ground_truth 86건이나 센서 정답 라벨은 사용하지 않았다.

- `evaluation/ontology_diagnostic_20261027/rubric_PRIVATE.json`: 원문·예상 답변 요소·판정 기준. 생성 입력에 넣지 않는다.
- 같은 폴더의 `pre_run_lock.json`: 질문·근거 판정표·원문·KG·검색 설정·생성 설정·코드 해시.
- 같은 폴더의 `prepare_rubric.py`: 이번 자료 준비 기록. 응답 생성 코드에서 import하지 않는다.

OD-02는 SOP-001 규칙 본문 범위에서 참조 대상을 확인했다. 이 범위 밖 문서까지 포함한 전역 완전성은 주장하지 않는다. OD-08은 현재 상태의 정답값을 만들지 않고, 제공 데이터의 시간 범위와 상태 기록 부재를 판정 근거로 삼는다.

예상 답변 요소는 AI가 원문과 대조해 작성했다. 독립 도메인 전문가 검토나 미노출 테스트 세트가 아니다. 기존 개발 사례와 유사한 규칙도 포함하므로 결과를 개발 진단으로 보고한다. 파일 분리는 답을 모델에 직접 전달하지 않기 위한 조치이며 실험자의 과거 정답 노출을 제거하지 않는다.

## 2단계에서 실행할 방식

1. 실행 전 질문·KG·원문·검색 정책·생성 지침 해시를 대조한다. 변경이 필요하면 새 실험 버전으로 구분한다.
2. 질문 파일의 `id`, `question`만 사용해 기존 `live.answer` 경로로 실행한다. 모델·검색 정책·원문은 기존과 동일하게 유지한다.
3. 생성 프로세스는 평가 판정표를 읽지 않는다. 예측 개수나 예상 출처도 검색 힌트로 주입하지 않는다.
4. 질문별 답변·검색 원문·탐색 경로·사용량을 새 실행 폴더에 보존한다. 실패 시 자동 재시도하거나 여러 답변 중 좋은 답변을 선택하지 않는다.
5. 생성 완료 후 별도 검토 단계에서 판정표와 대조한다. 답변을 본 뒤 기준을 바꾸지 않는다. 원문 오류 등으로 기준 수정이 필요하면 원래 기준과 변경 사유를 함께 보존하고 해당 사례를 보류 처리한다.

새로운 질문 임베딩과 답변 생성에는 기존 OpenAI API 비용이 발생할 수 있다. 현재 1단계 준비에는 API 호출이 없다.

## 실패 원인 판정 순서

| 순서 | 확인 | 판정 |
|---|---|---|
| 1 | 현재 원문·관측에 필요한 사실이 존재하는가? | 없으면 데이터 부족. 현재 상태 질문의 적절한 유보는 성공 |
| 2 | 필요한 근거가 실제 생성 컨텍스트에 들어갔는가? | 누락됐다면 우선 검색 문제. 곧바로 온톨로지 문제로 분류하지 않음 |
| 3 | 충분한 근거가 있는데 답변이 잘못됐는가? | 우선 생성·해석 오류. 온톨로지 표현 부족은 별도 가설로 남김 |
| 4 | 필요한 관계가 텍스트에만 있거나 의미가 모호해 재현 가능한 구조 조회가 어려운가? | 표현 한계 후보. 실패와 연결되는 구체적 경로를 제시해야 함 |
| 5 | 최소 표현 변경이 실제 문제를 해결하는가? | 별도 후보 버전에서 검증하기 전에는 원인 확정·채택하지 않음 |

각 사례에 답변 요소 충족, 근거 회수, 잘못된 주장, 실제 경로, 원인, 불확실성을 기록한다. 답변이 맞더라도 구조 조회의 어려움은 별도 관찰로 남길 수 있으나, 답변 실패 또는 정확도 향상으로 포장하지 않는다.

## 수정안으로 넘어가는 기준

관계 추가는 원문 근거가 명확하고, 기존 표현의 한계와 해결할 질문이 구체적일 때만 제안한다. 첫 후보는 규칙 참조 관계이지만 이번 단계에서 채택하지 않는다. 단순 프롬프트·검색 보완으로 해결되는지와 별도 관계가 제공하는 이점을 구분한다.

수정안 검증에서는 기존 텍스트 참조 방식과 직접 RDF 참조 방식을 비교한다. 질문·모델·생성 지침·예산·기초 검색을 고정하고 변경한 부분을 명시한다. 구조 명확성, 출처 보존, SHACL, 잘못된 연결, 답변 회귀를 함께 확인한다. 기존 v2는 끝까지 기준선으로 보존한다.

이번 단계 완료: 질문 8개 작성, 원문 대조 기준 작성, 질문 ID 일치 및 근거 청크 확인, 실행 전 해시 기록. 미완료: 실제 답변 생성, 실패 원인 판정, 수정안 구현 및 전후 평가.
