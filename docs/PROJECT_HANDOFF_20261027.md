# IMAKS 프로젝트 구현 현황과 재현 안내

기준일: 2026-10-27. 현재 로컬 구현의 통합 안내 문서다. 이전 보고서의 ‘미구현’ 문구는 작성 당시 상태이며, 이후 작업은 아래 연결된 보고서로 확인한다. 이 문서가 GitHub 반영 완료를 의미하지는 않는다.

## 1. 목표와 구현 범위

기존 KG와 제조 문서를 통합하고, 조건·조치·근거 관계를 확인할 수 있는 지식그래프를 구축한다. 현재는 예원 v2 KG를 기준으로 문서 질의응답과 과거 센서 데이터의 규칙 일치 후보 설명까지 연결했다.

다른 팀 추출 결과나 priority overlay를 기본 KG에 합치지 않았다. 이번 센서 후보는 별도 후보 그래프에 저장한다. 새 인과관계 발견이나 실운영 고장 진단을 입증한 프로젝트로 표현하지 않는다.

| 흐름 | 입력과 처리 | 결과 |
|---|---|---|
| 문서 질의응답 | 질문 → 임베딩 → 문서 ID·비교 대상·규칙 출처를 고려한 GraphRAG 검색 → 답변 생성 | 답변, 검색 원문, 탐색 관계, 한계 안내 |
| 룰 탐지 | 과거 센서 관측 → 임계값·지속 시간·동일 값 조건 검사 | 규칙 일치 후보와 최초 판정 값·시간 |
| 후보 설명 | 선택 후보 → 센서·실행 규칙·기존 규칙·원문 경로 조회 → 답변 생성 | 관측값, 조건, 출처, 문서상 조치와 한계 |

후보 설명은 후보 ID로 시작하는 별도 그래프 검색이다. 자유 질문용 검색과 같은 알고리즘이라고 설명하지 않는다. 후보 설명에는 추가 임베딩 호출이 없다.

원래 일정상 8차의 룰 기반 탐지기와 문서화에 해당하는 기준 구현을 갖췄고, 이후 GraphRAG 시연의 일부까지 진행했다. 다만 전체 문서 규칙 지원, 자율 Agent, 실시간 입력과 조치 실행까지 완료한 것은 아니다. 일정의 ‘정답 이벤트 14건 선투입’ 완료 여부는 이번 후보 93건으로 대체해 주장하지 않는다.

## 3. 숫자를 구분해서 보고하기

| 수치 | 의미 | 해석 범위 |
|---|---|---|
| 원래 추출 평가 ground_truth 86건 | 문서에서 추출한 정보의 대조 대상 | QA 문항 수 또는 센서 이벤트 수가 아님 |
| 원문 7개 / 청크 86개 | 검색 코퍼스 | ground_truth 86건과 별개 |
| 기존 Vector RAG / GraphRAG 106.5/120, 개선 GraphRAG 120/120 | eval 24문항, 문항당 내용 3·근거 1·충실성 1점 | 이미 본 문항의 개발 재시험, AI 단독·비맹검 채점 |
| 개선 dev 30/30 | 개발 문항 6개 | eval과 합산하지 않음 |
| 임계값 탐지 test F1 56.60% | 메타데이터 경고 임계값의 행 단위 탐지 평가 | 문서 규칙 전체 성능, 사건 단위 F1 또는 추출 F1이 아님 |
| 후보 93건 = 문서 규칙 43 + 메타데이터 50 | 규칙별 연속 일치 구간 | 중복 가능, 확정 이상치 93개가 아님 |
| 검색 준비 93건 검사 / 실제 답변 대표 4건 검토 | 입력·출처·예산 검사 / 기능 검증 | 전체 답변 정확도나 독립 벤치마크 점수가 아님 |

점수 개선에는 여러 검색 변경이 함께 포함됐다. 순수한 그래프 효과나 통계적 우월성으로 해석하지 않는다. 실제 생성 요청에서 정답을 제외했더라도 과거 정답 노출과 개발 재시험의 한계는 남는다.

## 4. 실행과 재현

이 컴퓨터의 저장소 루트에서 PowerShell로 실행한다. 기존 가상환경과 로컬 자료가 있다는 전제다.

```powershell
$env:PYTHONPATH='src'
$env:PYTHONUTF8='1'
..\.venv\Scripts\python.exe -m imaks_kg.rag.demo --port 8766
```

브라우저에서 `http://127.0.0.1:8766/`을 연다. 이미 서버가 떠 있으면 기존 주소를 사용한다. 주소 사용 중 오류가 나면 다른 프로세스를 임의 종료하지 말고 기존 실행 터미널을 확인하거나 `--port 8767`로 바꾼다. 종료는 해당 실행 터미널에서 Ctrl+C다.

- **추가 API 호출 없는 시연:** 저장된 결과 선택 → 결과 열기. 후보 조회도 무료다. 새 생성 버튼을 누르지 않는다.
- **새 문서 질문:** 질문·검색 문서를 OpenAI API에 전송한다. 임베딩과 답변 생성 비용이 발생할 수 있다.
- **새 후보 설명:** 선택 후보의 관측값·실행 규칙·출처를 OpenAI API에 전송한다. 생성 비용이 발생한다.
- API 키는 `OPENAI_API_KEY` 환경변수에 둔다. 공유 문서·Git·브라우저에 키를 붙여 넣지 않는다.
- 오류 시 자동 재시도하지 않는다. 로컬 실행 폴더의 기록을 먼저 확인한다.

새 clone만으로 바로 재현할 수 있는 상태는 아니다. 허가된 로컬 선행 자료가 필요하다.

| 로컬 자료 | 용도 |
|---|---|
| `artifacts/stage6_final_20261016/inputs/kg_build/openai_sol_v2_20261016/graph/candidate.ttl` | 기준 KG |
| `preprocessed/documents/chunks.jsonl` | 원문 청크 |
| `kg_build/vector_rag_v1/` | 새 문서 질문용 검색 인덱스 |
| `kg_build/rule_detector_20261026/` | 봉인된 후보·규칙·별도 RDF 그래프 |
| `kg_build/graphrag_live/` | 저장된 시연 답변·검색·실행 기록 |
| `evaluation/event_explanation_20261026/` | 후보 검색 검사·검토 기록 |

위 경로를 맞추기 위해 비공개 원문이나 평가 정답을 무조건 공개 저장소에 올리지 않는다. 현재 로컬에는 이전 실험과 무관한 변경도 있으므로 공유 시 전체 파일을 일괄 추가하지 않는다.

## 5. 아직 해결하지 않은 부분

실제 작업자 명령, 출입·재실·조치 이력, 설치 제품 매핑이 필요한 규칙은 입력 부족으로 미지원이다. 수치 정의가 불명확한 DRIFT 등의 조건을 임의로 만들지 않았다. STUCK은 정확히 같은 값 11개라는 구현 가정이다. 문서 충돌과 근거 충분성을 별도 판정하는 자동 검증기는 없다.

새로운 데이터나 전문가 검토가 없더라도 현재 구현·재현 기록·한계를 정리해 프로젝트 결과로 제시할 수 있다. 다음 발표 준비에는 [5분 시연 대본](DEMO_SCRIPT_20261027.md)을 사용한다. 현재 자료만으로 미노출 일반화 성능이나 실제 설비 안전성을 보장하지 않는다.
