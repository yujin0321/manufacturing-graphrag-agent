## 비교 설정

- 생성 모델과 지침은 세 방식 모두 `gpt-6.1-sol`과 main v5 실험의 공통 지침을 사용했다.
- 문서 QA에서 두 RAG는 같은 원문 행과 질의 임베딩 순위를 사용했다. Vector RAG는 밀집 벡터 검색을 적용했다. GraphRAG v5는 그래프 관계 확장, 명시적 규칙 참조, BM25 결합과 출처별 근거 구성을 적용했다.
- KG QA에서 두 RAG는 같은 원문과 고정 RDF의 동일한 노드 레코드에 접근했다. Vector RAG는 노드 레코드를 텍스트로 검색했고, GraphRAG v5는 저장된 관계를 조회해 집합·경로를 구성했다.
- 검색 문맥 상한은 문서 QA 4,000토큰, KG QA 8,000토큰이었다. 같은 평가 범위에서는 출력 상한도 동일했다. 문서에는 2,200토큰, KG에는 6,000토큰을 적용했다.
- 비교 단위는 v5 검색 엔진과 공통 생성기의 조합이다. main에서 기본 Agent로 지정한 v4.1은 별도의 운영 경로다. 이 비교에서 검색 전략 여러 요소가 함께 달라져 점수 차이 전체를 그래프 간선의 단독 효과로 해석하기는 어렵다. [main v5 구현 및 설정](https://github.com/yujin0321/manufacturing-graphrag-agent/blob/72d23dd9386d45ab9a81ccadb1957ed1b7d246bb/experiments/graphrag_v5_20261029/README.md)

## 채점과 재현 범위

문서 QA는 main의 고정 문항·정답 요소·5점 채점 기준을 사용했다. KG QA는 main의 RDF 평가 질의가 계산한 결과를 기준으로 필수 내용 3점, 근거 1점, 충실성 1점을 적용했다. 답변 봉인 후 익명화한 답변을 동일 모델의 별도 AI 채점으로 평가했다. 인정한 근거는 답변에 있는 인용과 대조했다. 기존 개발용 문항을 다시 실행한 결과이며 사람 교차 채점은 수행하지 않았다.

문서 Q28의 원래 AI 채점은 세 방식 모두 일반 시간창과 실측 시차를 구분한 답변을 인정했다. 고정 정답의 셋째 요소는 90분 이내라는 수치도 요구하므로, 이 요소의 점수는 세 방식 모두 원문 대조 후 0점으로 정정했다. 원래 채점과 정정 내역을 보존했다. Q18의 0.5점 차이는 GraphRAG가 압력 데이터시트의 적용 안내를 가져오지 못해 생겼다.

KG 문항 ADD-06은 채점용 정답을 만드는 과정에서 `/`가 들어간 RDF 조건 문장이 잘려 AI가 보류했다. 원본 RDF의 `KG:N0105` 레코드와 답변을 대조해 GraphRAG가 `>15분`, `>0.1σ/min`, `5개 이상`을 모두 보존했음을 확인했다. 세 방식의 잠정 점수는 유지했다. 같은 축약은 REL-K03에서도 발견됐지만 그 문항은 해당 조건 수치 대신 규칙의 센서·조치 대상·경로를 묻기 때문에 점수에 영향이 없었다.

최초 실행의 API 429 거절 58건은 기록을 남겼다. 잔액 보충 전 확보된 51개 응답을 보존하고 남은 57개를 이어서 실행했다. KG 문항의 Vector RAG 요청 한 건은 응답을 받기 전에 연결이 끊겨 한 번 다시 보냈다. 연결이 끊긴 요청의 과금 여부는 확인되지 않았다. 생성 설정, 응답과 검색 문맥을 봉인하고 채점 결과의 해시를 기록했다. 수신한 생성 API 응답에 기록된 사용량은 393,023토큰, 공통 임베딩은 82,138토큰, 별도 채점은 293,005토큰이다.

## 실험 해석

제조 문서 QA에서는 두 검색 방식의 점수가 거의 같았다. 고정 KG의 규칙 집합, 간선 방향, 출처 경로를 묻는 문항에서는 GraphRAG v5가 더 높은 평균을 기록했다. 구조화된 관계 조회에서 얻은 근거를 답변에 쓰는 사례와, 전체 목록을 일부만 회수하거나 올바른 항목을 잘못 합산하는 사례가 함께 관찰됐다.
