# 예원 v2 온톨로지 검토 및 후보 관계 채택 판단

작성일: 2026-10-28. 검토 실험일: 2026-10-27. 팀 공유용 통합 보고서.

## 1. 최종 판단

**기본 KG와 실제 GraphRAG는 원래 예원 v2를 유지한다.** 후보 관계 `requiresRuleCheck`는 별도 실험으로 보존하고 실제 검색에는 반영하지 않는다. 이번 검토에서 온톨로지 표현 부족 때문에 답하지 못한 사례는 확인되지 않았고, 후보 관계의 답변 성능 개선도 입증하지 않았기 때문이다.

프로젝트의 확인 가능한 기여는 **기존 KG와 제조 문서를 공통 온톨로지로 통합하고, 규칙·적용 센서·조치 대상·근거를 연결하여 GraphRAG에 활용한 것**이다. 새로운 제조 인과 법칙을 발견하거나 GraphRAG가 온톨로지를 자동 구축했다고 표현하지 않는다.

권장 프로젝트 설명: **IMAKS 제조 문서의 온톨로지 기반 지식그래프 구축 및 GraphRAG 활용**.

## 3. 수행 과정과 결과

### 3.1. 원본 대비 v2의 기여 확인

원본 seed CSV와 실제 로더가 읽는 v2를 비교하고 RDF 집계·대표 노드 조회·SHACL 검사를 수행했다.

- 원본 공정과 센서를 Station 9개, Sensor 22개로 표현했다.
- Document 7개와 문서 추출 Rule 100개를 추가했다. 기존 정비 규칙 8개를 포함해 규칙 노드는 총 108개다. 독립적인 신규 규칙 108개를 발견했다는 뜻은 아니다.
- 108개 규칙 모두 출처 문서와 출처 기록 연결을 가진다. 조건 문자열은 추출 규칙 100개에 있으며 기존 정비 규칙 8개에는 같은 속성이 없다.
- 실제 관계는 `hasSensor` 22개, `feedsInto` 3개, `appliesToSensor` 72개, `actionTarget` 94개, `sourceDocument` 108개, `hasProvenance` 147개다.
- 이 관계 유형은 팀 온톨로지 v1에 이미 정의돼 있었다. v2의 기여는 그 스키마에 맞춘 데이터 통합과 연결이며 관계 유형의 자동 발명은 아니다.
- SHACL 재검사 결과는 적합이다. 이는 구조적 제약 통과이며 문장 내용의 사실성 보장은 아니다.

원본 간선 CSV 341행과 v2의 2,806트리플은 집계 단위가 다르므로 관계 증가율로 비교하지 않는다. v2는 원본 전체 복제도 아니다. 원본 이상 이벤트 14개와 인물 등의 개체는 현재 기본 v2에 적재하지 않았다.

### 3.2. GraphRAG 진단 질문 실행

질문·판정 기준·원문·KG·검색 설정을 사전 고정하고 기존 GraphRAG로 8문항을 실행했다. 규칙 참조 방향, 시간 경계, 상대 임계값, STUCK 정의, 조치 대상, 복수 기준 및 현재 상태의 확인 가능성을 점검했다.

| 관찰 | 결과 | 해석 |
|---|---|---|
| 문서 질문 7개의 필수 근거 회수 | 8개 근거 단위 중 8개 회수 | 해당 진단 범위에서 필요한 원문이 검색됨 |
| 필수 내용 대조 | 불일치 발견하지 못함 | AI 단독·비맹검 검토 결과 |
| 현재 상태 질문 OD-08 | 현재 상태를 확인할 수 없다고 답함 | 문서 지식과 실제 관측을 구분 |
| OD-08 출력 언어 | 일본어로 응답 | 한국어 생성 지침 위반, 온톨로지 결함으로 분류하지 않음 |

평가 판정표와 기대 근거 ID가 실제 API 요청에 포함되지 않았음을 확인했다. 다만 이미 익숙한 자료를 사용한 개발 진단이므로 독립적인 미노출 시험으로 간주하지 않는다. **8문항 모두 성공 또는 정확도 100%라고 보고하지 않는다.**

진단 실행에는 생성 8회, 입력·출력 합계 35,697토큰과 질문 임베딩 797토큰이 사용됐다. 이번 통합 보고서 작성에서는 API를 추가 호출하지 않았다.

### 3.3. 명시적 규칙 참조 관계 비교

SOP-001 규칙 본문 24개 청크를 대상으로 다음 세 방식을 비교했다. 이 실험에는 API 호출과 답변 생성이 없다.

| 방식 | 처리 | 연결 수 |
|---|---|---:|
| A 기존 텍스트 참조 | 기존 검색의 규칙 ID 매칭 식으로 연결 열거 | 7 |
| B 명시적 지시 파서 | 원문의 `verify/check RULE-…` 지시만 추출 | 1 |
| C 후보 RDF | B와 같은 연결을 관계·출처 주장으로 저장 | 1 |

후보 관계는 `RULE-ST04-03 → requiresRuleCheck → RULE-ST02-04`다. 특정 조건에서 다른 규칙을 확인하라는 지시이며, 인과관계나 실제 조치 실행을 뜻하지 않는다. 조건은 기존 출발 규칙과 원문에 남으므로 간선만 보고 무조건적인 지시로 해석하지 않는다.

세 방식 모두 해당 규칙의 정방향·역방향 조회 결과가 같았다. C에서는 실제 SPARQL 조회를 확인했다. A의 추가 6개 연결은 분할된 규칙과 원래 규칙 ID 사이의 일반 검색 참조다. A의 목적이 더 넓으므로 이를 검색 오답 6개로 세지 않는다.

후보는 직접 관계 1개와 ReferenceClaim 1개의 속성을 포함한 7트리플로 별도 저장했다. 정상 후보는 후보용 SHACL과 원문 대조를 통과했다. 인위적 오류 7종에서는 SHACL이 4종을 검출했고, 원문 대조를 함께 적용하면 7종을 검출했다. 방향 반전·가짜 인용·내용이 틀린 해시 등은 구조 검사만으로 검출되지 않았다.

이 결과는 **관계 의미와 방향을 명시하고 출처·구조를 검증할 수 있다는 증거**다. B와 C가 같은 관계를 사용하므로 RDF 덕분에 추출 정확도가 높아졌다는 증거는 아니다. 7종의 오류 주입 결과를 일반적인 오류 검출률 100%로 확대하지 않는다. 좁은 파서는 `consult the guidance in …` 같은 표현을 놓쳤으며, RDF 저장만으로 상류 추출 누락이 해결되지 않는다.

## 4. 채택 판단과 남은 문제

| 항목 | 판단 및 후속 처리 |
|---|---|
| 예원 v2 기본 KG | 유지. 현재 검색·시연 기준선으로 사용 |
| requiresRuleCheck | 채택 보류. 실험 전용 스키마·제약·그래프로 보존 |
| 한국어 출력 위반 | 생성 지침 준수 문제로 별도 관리. 이번 검토에서 수정하지 않음 |
| 현재 상태 질문의 불필요한 창고 카드 | 검색 관련성 문제로 기록. 언어 오류의 원인으로 단정하지 않음 |
| STUCK 탐지 가정 | 탐지기의 동일값 11표본 가정과 문서별 기준의 일치 여부를 별도로 점검할 필요가 있음 |
| 원래 일정의 정답 이벤트 14개 선투입 | 현재 v2에 포함되지 않음. 향후 E2E 요구사항 검토에서 별도 여부·평가 격리를 결정 |

후보 관계를 나중에 실제 적용하려면 다양한 문서·표현에서 추출 누락과 잘못된 방향을 확인하고, 고정된 원문·질문으로 검색 회귀를 검증해야 한다. 현재 결과만으로 기본 v2를 바꿀 필요는 확인되지 않았다.

추가 원문이나 전문가 검증 없이 관계의 제조 도메인 타당성을 확정하지 않는다. 이번 AI 검토는 원문과 구현의 일치 여부를 점검한 것이며 독립적인 도메인 전문가 검증을 대체하지 않는다.

## 5. 팀 공유용 결론

> 예원 v2는 공정·센서·문서·규칙·출처를 공통 온톨로지로 통합한 2,806트리플의 지식그래프다. GraphRAG 진단에서는 검토한 문서 질문의 필수 근거가 모두 회수됐으나, 한 답변의 한국어 지침 위반이 관찰됐다. 규칙 확인 지시를 명시적 관계로 표현한 별도 실험에서는 방향 조회와 구조·출처 검증 가능성을 확인했다. 다만 기존 방식도 해당 조회를 해결했고 답변 성능 개선을 입증하지 못했으므로 후보 관계의 실제 반영은 보류하고 예원 v2를 유지한다.

온톨로지 검토의 이번 범위는 여기까지 정리한다. 다음 작업은 원래 일정의 **GraphRAG + Agent End-to-End 요구사항과 현재 구현의 차이 점검**이다. 현재 질의응답 연결만으로 Agent 단계 전체가 완료됐다고 가정하지 않는다.
