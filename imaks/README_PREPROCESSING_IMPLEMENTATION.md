# 팀 설명용: 각자 구현 작업의 재실행 결과

2026-10-06. 사용자가 선택한 기준은 **기존 평가 구간에서 이벤트 F1이 가장 높았던 평균10/STUCK11/stride1**이다. 이 설정으로 센서 특징·윈도우·예측·평가를 다시 생성했고 기존 211,200행 예측과 분할별 지표를 재현했다. 새로운 맹검 평가나 모든 가능한 설정의 전역 최적을 의미하지 않는다. 앞선 검증 선택 2/10/2와 기존 기본 3/11/1은 별도로 보존한다.

## 센서 처리를 쉽게 설명하면

정규화는 ‘단위와 평소 크기가 다른 센서값을 각 센서의 평소 상태에 비춰 표현하는 것’이다. 중앙값은0에 대응하고, 양수는 평소보다 높음, 음수는 낮음을 나타낸다. 공식은 `(값−학습 중앙값)/max(1.4826×MAD,1e-8)`이다. 정답으로 정상 행을 골라서 학습하지 않았고 학습 중 이상도 원본대로 포함한다.

ST02_SEALING_TMP의 실제 06:05 관측 예를 보면 직전값185.9012°C에서185.0552°C로 변했다. 직전 대비 변화량은 **−0.846°C**,30초=0.5분이므로 분당 변화율은 **−1.692°C/분**이다. 평균10은 직전9개와 이 현재값 전체를 함께 사용한다. STUCK11은 최근11개 값이 거의 변하지 않는지 보는 별도 표준편차다.

원본211,200행은 모두 유지했다. 센서·시간 공백·학습/검증/평가 경계에서 윈도우를 다시 시작한다. 평균10 준비 전594행, STUCK11까지 포함한 전체 특징 준비 전660행은 특징을NaN으로 남겼다. 특징이 모두 준비된210,540행도 별도 저장했지만, 탐지 평가는 전체 행으로 했다. 이상값 삭제·정상값 보정·평활화·결측 채우기·제로 패딩은 하지 않았다.

새 변화량·변화율·최소·최대 등의 특징은 **후속 모델용 데이터로 준비한 것**이다. 현재 강건 통계 탐지기는 순간 편차,10개 평균 편차,STUCK11 플래그를 사용한다. 추가21개 특징을 모두 새 모델에 학습시켰다는 뜻은 아니다.

## 문서와 KG를 쉽게 설명하면

청킹은 긴 문서를 검색·추출할 수 있는 작은 조각으로 나누는 작업이다. 임계값 표는 열 제목과 셀·단위·비교 조건을 함께 남기고, 다음 페이지에 이어지는 표의 헤더도 연결했다. 본문은문자 위치/줄/페이지, 표는표ID/행번호/bbox로 원문을 찾을 수 있다. 과거64청크는 초기 프로토타입이고, 이번70청크는 공통 문서에서 새 규칙으로 재생성한 결과다. 데이터셋 자체가 바뀐 것은 아니다.

임베딩은 청크를 의미 검색용 숫자 벡터로 바꾸는 작업이다. **임베딩 생성 완료와 LLM 정보 추출 완료는 서로 다른 단계**다. 이번에는70개 벡터와70개 추출 요청을 만들었지만 LLM을 호출해 개체·관계·규칙을 생성하거나 정답86건과 채점하지 않았다.

KG는 ‘누가 무엇과 어떤 관계인가’를 연결한다. 예를 들면 `규칙 → 적용 센서`, `규칙 → 출처 SOP`, `규칙 → 조치 대상 스테이션`이다. 노드114개는기존 정적83 + 문서7 + 규칙24, 관계330개는기존269 + 구역관계9 + 규칙관계52다. Rule24개는임계값표22개와원문 수동예제2개로 만들었고 LLM 추출 결과가 아니다. RDF의triple 수에는 속성과 출처도 포함되므로 Neo4j 관계 수와 다르다.

SHACL로 실제RDF2개를 검증했다. 통과예제5개는통과하고 실패예제5개는거부했으며, 질문5개도 다시 조회해 기존 결과와 같음을 확인했다. Neo4j 변환CSV는중복ID와연결대상이없는관계가0개다. 새RDF를GraphRAG검색이나Agent에 자동 연결한 단계는 아니다.
