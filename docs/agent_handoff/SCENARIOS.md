# 대표 사례 순서와 설명문

새 질문을 다시 보내는 대신 아래 저장 기록을 순서대로 조회한다. 읽기 전용 서버에서 비용 없이 재생할 수 있다. 사례는 이미 본 자료의 개발 시연이며 새 성능 평가가 아니다.

| 순서 | 저장 실행 ID | 보여줄 기능 | 확인할 내용 |
|---|---|---|---|
| 1 | `team_main_20261113_01` | 과거 사건 설명과 XAI | ST02 온도 관측→실행 조건→규칙 원문→문서/시계열 출처 연결 |
| 2 | `team_document_20261113_01` | 문서 조건·조치 검색 | MAINT-05의 부등호·기간·권고 조치와 SOP 출처 |
| 3 | `team_kg_20261113_01` | KG 전체 집합 조회 | ST04 센서 3개, 단위 A·m/s·mm/s를 원본대로 보존 |
| 4 | `team_unavailable_20261114_01` | 답변 한계와 보류 | 현재 측정값은 미연결임을 안내, API 호출·가짜 근거 없음 |
| 선택 | `team_seongho_20261113_01` | 대안 탐지 방식 | 원본 연속 2점 후보·확인/해제·미분류·표시용 등급 구분 |

## 1. 사건에서 원문까지

조회: `GET /api/run/team_main_20261113_01`.

설명: “이 사례는 실제 제어가 아니라 과거 시계열의 규칙 일치 후보입니다. 212.8202°C 관측을 실행 규칙과 연결하고, 어떤 원문 조건을 근거로 조건부 조치를 설명했는지 추적합니다. SPIKE는 탐지기의 운영 분류이며, 확정 고장 원인이라고 주장하지 않습니다.”

`xai.incident`, `alarms`, `execution_parameters`, `sources`, `edges`, `verification`을 연결해 읽는다. 문서 조건과 코드 기본값을 구분한다. 종료 시각과 유형 판정 일부는 사후 정보다.

## 2. 문서 질문

조회: `GET /api/run/team_document_20261113_01`.

설명: “MAINT-05의 조건과 조치는 원문 출처와 함께 제공합니다. 실제 설비 값이나 조치 수행을 확인한 결과는 아닙니다.”

이 사례의 실제 경로는 `document`, 문서 방식은 `auto`다. 간선 0개가 정상이다. 그래프가 모든 문서 답변에 기여했다고 설명하지 않는다.

## 3. 그래프의 전체 집합

조회: `GET /api/run/team_kg_20261113_01`.

설명: “ST04에 연결된 모든 센서를 검색 상위 일부에서 추정하지 않고 고정 KG 전체에서 조회합니다. 결과는 3개이며 m/s와 mm/s를 그대로 유지합니다.”

`xai.kg_query.count`, `items`, `edges`를 확인한다. 개수는 코드가 계산한다. 저장 노드의 개수이며 실제 세계의 부재·인과를 증명하는 결과는 아니다.

## 4. 답변할 수 없는 요청

조회: `GET /api/run/team_unavailable_20261114_01`.

설명: “실시간 센서는 연결하지 않았으므로 현재 측정값을 만들어내지 않습니다. 지원 범위를 확인해 답변을 보류합니다.”

`agent_status=insufficient_evidence`, 근거·간선·검토 배열이 비어 있음을 확인한다. 이 사례는 결정적 라우팅으로 생성 모델을 호출하지 않았다.

## 성호 대안의 차이

조회: `GET /api/run/team_seongho_20261113_01`.

설명: “같은 근거 설명 도구를 사용하되 후보를 만든 탐지 정책은 다릅니다. 원본이 분류하지 않은 이상 유형을 임의로 부여하지 않았고, 정상 복귀 확인도 해당 규칙 해제이지 현장 안전 인증은 아닙니다.”

전체 시연은 예원 담당 백엔드의 연결과 출처 추적을 보여준다. UI 표현 방식과 영상 녹화·화면 구성은 UI 담당자가 결정한다.
