# 검색 개선 후 LLM·Vector RAG·GraphRAG 재비교

2026-10-28. 기존 eval 24문항에 대해 **세 방식 모두 새 답변을 생성한 개발 재시험**이다. 정답 이벤트 시연과 추출 F1은 포함하지 않는다.

**결론: 개선 Vector RAG와 개선 GraphRAG가 팀 채점 기준상 모두 120/120점이었다.** 현재 문항에서 GraphRAG의 답변 점수 우위는 관찰되지 않았다. GraphRAG는 지정 원문 근거를 한 개 더 회수했지만, Vector RAG는 동일한 내용을 뒷받침하는 대체 근거로 답했다. 이 대체 근거 판정은 아래에 공개한다.

## 1. 무엇을 개선하고 재실행했나

| 방식 | 이번 입력·처리 |
| --- | --- |
| LLM 단독 재실행 | 검색 없이 질문만 제공. 검색 개선이라는 개념이 적용되지 않으므로 모델·지침을 그대로 유지한 대조군 |
| 개선 Vector RAG — VectorHybrid | 기존 벡터 순위에 어휘 순위를 RRF로 결합. 원문에서 얻은 규칙 ID 우선 검색, 명시 문서별 근거 확보. 최대 24청크·4,000토큰. KG 읽기 금지, 그래프 카드 없음 |
| 개선 GraphRAG | 기존 full graph_v2의 봉인된 검색 입력 재사용. 문서·KG 탐색·출처 매핑과 그래프 카드 포함. 최대 24개 원문 후보·총 컨텍스트 4,000토큰 |

‘Vector RAG’라는 명칭을 유지하되, 이번 버전은 **순수 dense top8이 아닌 혼합 검색**임을 명시한다. 코드의 공통 생성 설정 파일에 남아 있는 초기 `top_k=8`, `hybrid_search=false` 값은 이번 검색 방식의 설명으로 사용하지 않는다. 별도 실행 매니페스트와 검색 입력에 이번 정책을 기록했다.

VectorHybrid 입력은 `ablation.select(..., graph_trace=None)`로 다시 만들고 기존 B 입력과 일치함을 확인했다. 생성 과정에서 `load_graph`와 네트워크 호출을 금지해 KG나 새 임베딩 없이 준비했다. GraphRAG 입력은 기존 개선판 컨텍스트의 해시를 확인했다. 직전 **저장 관계 OFF/ON 실험의 ON은 그래프 카드가 없었으므로 이번 GraphRAG와 구분**한다.

세 방식 모두 `gpt-6.1-sol`, 공통 시스템 지시문, 최대 출력 4,096토큰, temperature/seed 생략을 유지했다. 72개 반환 모델 ID도 모두 일치했다. 각 문항의 세 요청을 최대 3개 병렬로 실행하고 제출 순서를 회전했다. 이전 실행의 답변은 재사용하지 않았다. 이번 72개 요청 간에는 대화 이력이 공유되지 않는다.

## 3. 중요한 판정: Q28의 대체 근거

고정된 원문 청크 ID만 대조한 검색 검사는 다음과 같다.

| 검색 지표 | VectorHybrid | GraphRAG |
| --- | ---: | ---: |
| 정답표 지정 근거 회수 | 34/35 (97.14%) | 35/35 (100%) |
| 지정 근거를 모두 찾은 문항 | 23/24 | 24/24 |

VectorHybrid의 Q28 입력에는 `SOP-001:p1:RULE-ST02-04`가 없다. 하지만 답변 T58은 다음을 인용했다.

- `SOP-003:p1:table2:chunk`: ST02 전류 상승 → ST04 속도 저하, 공유 전기적 결합의 정성적 패턴. 해당 행에 정량 시차·빈도는 없음.
- `SOP-002:p2:table6:chunk`: CORRELATED의 원인 발생 후 90분 이내라는 일반 검출 정의.

답변은 정확한 시차·발생 확률을 알 수 없고 일반 90분 정의를 실제 측정 시차로 사용할 수 없다고 설명했다. SOP-003 패턴을 모든 전류 경고가 반드시 속도 저하를 일으킨다는 규정으로 확대하지 않았다.

기존 팀 기준 §4는 **같은 주장을 충분히 뒷받침하는 대체 위치를 원문 확인 후 인정**하도록 한다. 이에 따라 이 질문에서 필요한 정성적 관계 근거에 한해 SOP-003 표2를 RULE-ST02-04의 대체로 인정했다. WARNING 발생 시 감시하라는 지시 자체나 CORRELATED 90분 정의를 대체한다는 뜻은 아니다. 판정 이유와 대체 청크를 `decisions_PRIVATE.json`에 남겼다.

따라서 **지정 ID 검색 재현율 97.14%**와 **답변 근거 점수 100%**는 서로 다른 지표다. 만약 대체 위치를 전혀 인정하지 않고 정답표의 위치만 허용한다면 VectorHybrid Q28의 근거는 0.5점이 되어 총점 119.5/120, 평균 4.9792, 완전 정답 23/24가 된다. 이는 현재 팀 기준의 공식 점수가 아닌 민감도 설명이며, 이 0.5점으로 그래프 우월성을 확정할 수 없다.

이전 초기 Vector RAG의 Q28은 90분 정의를 놓쳤다. 당시 SOP-003 표를 **90분 정의의 대체**로 인정하지 않은 판정과 이번 판정은 다르다. 이번에는 table6을 직접 인용했고, SOP-003 표를 **정성적 관계의 대체**로만 인정했다.

## 6. 해석과 프로젝트 적용

이번 재시험은 **검색을 개선하면 그래프를 사용하지 않는 혼합 RAG도 현재 문항을 잘 해결할 수 있음**을 보여준다. 앞서 개선 GraphRAG만 재시험한 결과를 근거로 GraphRAG가 Vector RAG보다 우수하다고 말해서는 안 된다.

순수 문서 QA 용도에서는 개선 VectorHybrid가 이번 점수와 토큰 사용량 기준으로 합리적인 선택이다. v2 KG는 규칙·센서·조치 대상·출처의 명시적 조회와 제약 검증을 위한 공통 지식 저장 구조로 유지할 수 있다. 이는 운영 기본 모드를 이번 작업에서 바꿨다는 뜻이 아니다.

보고 문구:

> 같은 모델과 기존 24문항으로 세 방식을 새로 실행한 개발 재시험에서, 개선 Vector RAG(혼합 검색)와 개선 GraphRAG는 팀 기준상 모두 120/120점을 얻었다. Vector RAG 한 문항은 원문 확인을 거친 대체 근거를 인정했다. 현재 결과에서 GraphRAG의 답변 점수 우위는 관찰되지 않았으며, GraphRAG는 더 많은 생성 토큰을 사용했다.

## 7. 한계와 보존

조건 이름을 가린 72개 답변을 원문·정답 요소와 대조한 AI 단독 채점이다. 답변의 KG 언급이나 기권 패턴으로 시스템이 추정될 수 있으며, 채점자는 이미 질문·정답에 노출되어 있다. 독립 인간 검증·완전 맹검·미노출 평가가 아니다. 24문항은 이미 개발에 사용됐고 점수가 포화돼 다른 문항으로 일반화할 수 없다. 정답표는 생성 입력에 넣지 않았다.
