# 검색 개선 후 3종 재비교 실행 조건

사용자 요청: 검색 개선 버전 LLM·Vector RAG를 포함해 다시 비교한다.

- LLM에는 검색 기능이 없으므로 기존 공통 지침으로 새로 실행한다. 이를 검색 개선 LLM이라고 부르지 않는다.
- VectorHybrid는 벡터 순위와 어휘 순위의 RRF 결합, 원문에서 얻은 규칙 ID 우선 검색, 명시된 문서별 근거 확보를 사용한다. 최대 24청크·4,000토큰이며 KG 로딩을 금지한다. 순수 dense top8과 구분해 ‘개선 Vector RAG(혼합 검색)’로 표기한다.
- GraphRAG는 기존 검색 개선판의 봉인된 컨텍스트를 그대로 사용한다. 문서·KG 출처 탐색과 그래프 카드가 포함된다. 직전 저장 관계 OFF/ON 실험의 ON과 같은 입력이 아니다.
- 세 방식 모두 gpt-6.1-sol, 기존 공통 답변 지시문, max_completion_tokens=4096, temperature/seed 생략을 유지한다. 모델 응답의 실제 ID도 확인한다. 설정 파일의 top_k=8/hybrid_search=false는 초기 Vector 구성으로, 이번 검색을 설명하는 값이 아니다. 이번 검색 정책은 run_lock.json과 해당 입력 파일에 별도 기록한다.
- 기존 eval 24문항을 모두 사용한다. dev 6문항은 이번 실행에 포함하지 않는다. 정답 이벤트 14건 시연과 추출 F1은 제외한다.
- 새 답변은 72개다. 각 질문의 세 조건을 최대 3개 병렬로 실행하고 다음 질문으로 넘어간다. 제출 순서를 회전한다. 이전 실행의 생성 응답을 재사용하지 않으며 이번 실행 내 완료 응답만 재개 시 보존한다. 자동 재시도는 하지 않는다.
- 검색 입력은 답변 생성 전에 동결한다. 질문 임베딩은 기존 캐시만 사용해 새 임베딩 호출이 없다. 답변 생성 함수는 정답·채점 파일을 읽지 않는다.
- 72개 생성 완료 후 조건 이름을 가린 응답을 기존 팀 5점 기준으로 AI가 검토한다. 내용 3요소, 근거, 충실성을 각각 기록한다. 점수 집계 전에 판정을 저장한다.
- AI는 기존 질문·정답에 노출되어 있다. 시스템 이름을 가려도 완전한 맹검·독립 인간 평가가 아니며, LLM의 무근거 답변 특성으로 조건이 추정될 수 있다. 결과는 개발 재시험이다.
- 평균·완전 정답 수·내용·근거·충실성·유형별 점수·문항별 차이·실패·토큰 사용량을 보고한다. 답변 거부와 무근거 단정을 구분한다. 차이가 나더라도 순수 그래프 효과나 통계적 우월성으로 표현하지 않는다.
- 이전 점수·KG·온톨로지·운영 검색 코드를 변경하지 않는다. 이번 결과는 별도 폴더에 보존한다.

채점: `scripts/review_refreshed_comparison.py prepare|aggregate`
