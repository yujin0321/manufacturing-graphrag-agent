# 판단 근거 구조화와 제한된 자기수정

2026-11-14, Agent `incident-agent-v2-20261114`. UI 변경은 포함하지 않는다. 실제 모델 호출 없이 고정 입력·봉인 결과·모의 모델 응답으로 검증했다.

이 문서는 첫 구조 검사 시점의 306개 일치·78개 미검증을 기록한다. 이후 [창 연산 확장](WINDOW_CHECKS.md)에서 나머지 78개를 확인했다. 최신 검사기는 `decision-evidence-v2-20261114`이며 기존 결과는 보존한다.

## 새로 확인하는 것

사건의 각 알람에 `DEC-*` 식별자를 부여하고 다음을 한 레코드로 연결한다.

`원본 센서·시각·값·단위 → 봉인 알람 → 실행 IR → KG 규칙 → 실제 원문 청크 ID → 조건 검사 결과`

단위·값·알람 소속·조건/조치 문장·실행 매개변수·원문이 저장된 자료와 다르면 설명 초안 생성 전에 보류한다. 원문 해시는 기존 고정 코퍼스 검사를 사용한다. 모델은 어떤 원문이나 관측을 새로 만들거나 이 검사를 승인으로 덮어쓸 수 없다.

숫자 비교는 Decimal을 사용한다. 지원 연산은 `gt`, `lt`, `outside`다. 경계값은 엄격한 부등호를 보존한다. 이 연산으로 실행되는 규칙에 한해 30초 연속 관측·정상값과 결측 간격에서의 초기화·`지속시간 > 문서 한도`·연속 확정 표본 수·최초 발동 시점을 확인한다. 원본 스캐너의 연속 2점 정책은 2개의 완전한 적격 표본을 요구한다. 이후 관측값을 조건 계산에 사용하지 않는다.

기울기·분산 기반 STUCK·변화량·파생 감시 알람 등은 이번 검사기가 발동 조건을 재계산하지 않는다. 원본 관측과 봉인·출처 연결은 확인하되 해당 `trigger_check.state`를 `unassessed`로 둔다. 이상 유형, 정상 복귀, 사건 묶음, 고장 원인, 실제 조치 수행과 자연어 전체 주장의 참거짓도 이 검사로 보증하지 않는다.

검증은 탐지 정책의 실제 실행과 저장 근거가 맞는지에 관한 것이다. 탐지 정책 자체가 제조 현장에 적합한지, 원문 해석이 전문가 관점에서 옳은지는 별도 검토 대상이다.

여기서 엉뚱한 출처 연결 검사는 규칙과 실제 원문 링크가 맞는지 확인하는 것이다. 서로 유효한 SOP와 데이터시트가 다른 수치를 제시하는 경우 어느 쪽을 실제 설비에 적용할지 자동 결정하는 기능은 추가하지 않았다. 문서의 차이와 실제 설치 모델 미확인은 계속 구분해야 한다.

## 사건 설명을 한 번만 보완

기본값은 기존과 같이 초안1회·검토1회다. 사용자가 API 요청에 `repair_incident=true`를 선택하거나 CLI에 `--repair-incident`를 명시하면, 검토 거절 시 구체적인 문제 목록을 다음 초안에 제공하고 한 번 수정·재검토한다.

```powershell
python scripts/run_xai_agent.py --question '사건 <목록에서 선택한 ID>를 설명해 주세요.' --run-dir kg_build/graphrag_live/new_incident_check --repair-incident
```

위 명령은 실제 API 비용이 발생할 수 있다. 이번 개발에서는 실행하지 않았다. 전송 실패와 불완전한 응답은 보완 신호로 취급하지 않으며 자동 재호출하지 않는다. 구조적 근거가 틀리면 보완으로 넘어가지 않는다. 두 번째도 거절되면 답변을 보류한다. 두 초안과 두 검토를 모두 보존한다. 두 번 연속 승인 수렴 하네스의 구현은 아니다.
