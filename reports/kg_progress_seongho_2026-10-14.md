# 성호 KG 구축・부분 LLM 추출 평가・보완 보고서

## 실제 수행과 범위

지훈 기준 코드에서 전처리를 재현하고 seed KG를 변환한 뒤, 실제 Gemini API로 문서 지식을 추출했다.
사용자 요청으로 이미 받은 gemini-3.1-flash-lite 결과를 고정했다. 전체 문서 추출 완료가 아니다.
완료: SOP-001/003/004, DS-ELEC. 미완료: SOP-002/DS-MECH/DS-THERM.
공개 집계는 이 실험만 대상으로 하며 이전 3.8/3.6 실험의 출력은 섞지 않았다.

| 항목 | 결과 |
|---|---:|
| 자동 규칙 | 56 |
| SOP 예측 | 50 |
| 전체86건 TP / FP / FN | 45 / 5 / 41 |
| 전체 Precision / Recall / F1_content | 90.00% / 52.33% / 66.18% |
| 처리한 SOP59건 TP / FP / FN | 45 / 5 / 14 |
| 처리한 SOP 범위 F1_content | 82.57% |
| 분류까지 일치한 전체 TP / F1 | 30 / 44.12% |
| 근거 검증 통과 / 인용 오류 | 54 / 2 |

미처리 SOP-002의 정답27건은 전체 점수에서 FN으로 포함된다.
처리 문서 범위 점수는 전체 실험 완료 점수가 아니다. 문장 의미 유사도와 수치/분류/진단 정확도를 구분한다.

## KG

| 단계 | 트리플 | 내용 |
|---|---:|---|
| seed+문서 | 639 | Station9/Sensor22/seed정비8/Document7/Provenance47 |
| 검증된 LLM 결과 반영 | 1,654 | 규칙54개 추가, 근거 오류2개 제외 |
| 별도 source-only 보충 포함 | 4,121 | SOP-002 표의 임계값22행+이상 정의5행 추가 |

세 그래프 모두 SHACL 적합(inference=none). 보충27개는 deterministic_source_table로 표기하며 LLM 결과와 점수에 섞지 않는다.
SOP의 Station heading과 명시적 페이지 연속 표 정보를 사용하고, 문맥이 없으면 임의 추정하지 않는다.
임계값110개(22센서×5속성)를 decimal로 저장한다. 이벤트 정답과 신규 인과관계는 넣지 않았다.
seed 정비 규칙은 독립 출처 노드로 보존했다. 의미상 중복 통합은 미완료이다.
Neo4j용 Cypher를 생성했지만 서버 적재·조회는 실행하지 않았다.

## 보완 검증

- 전체 테스트67개 통과: 기존50개+성호 신규17개. 다른 검증 에이전트가 독립 검증한 결과가 아니다.
- 최대 입력86토큰, 모델 제한256토큰, 잘림0개(136문장 확인).
- 같은 텍스트에서 문서별 최대 코사인 합 Hungarian 후 임계값 수용 방식은44매칭.
  사전 고정한 유효 매칭 수 우선 방식45매칭과 정책 차이가 있다. 최초 점수는 바꾸지 않았다.
- 매칭45개 안에서 센서 집합44개·심각도 문자열18개 일치. 이는 전체 필드 정확도가 아니다.
- 숫자 표현 차이9개는 사람 검토 신호이다.
- source-only 보충의 임계값88필드 중84개가 원본 정답과 일치.
  ST03_LABELLING_SPD의 critLo/warnLo/warnHi, ST04_PACKAGING_SPD의 critLo가 다르다.
  원문 값을 정답에 맞춰 바꾸지 않았다. 원문/정답 오류 가능성을 따로 검토한다.

## 출처 조건 차이

SOP의 공정 경보와 데이터시트의 연속 운전 정격·권장 설정은 의미/지속 조건이 다르다.
온도200°C 연속 정격과210°C 경보, 전류14A 연속 정격과15A 경보,
압력 경보의 nominal 대비0.4bar 간격과0.5bar 권장을 검토 후보로 기록했다.
단순 수치 차이를 같은 사실의 오류나 실제 안전 판정으로 단정하지 않는다.
센서 형식으로 데이터시트 시리즈 적용을 가정한 검토이며 실제 제조사 대응은 입증하지 않았다.
