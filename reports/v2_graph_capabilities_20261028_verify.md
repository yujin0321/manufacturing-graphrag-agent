# 예원 v2 KG: 관계 조회·출처 추적·제약 검증

2026-10-28. 이 문서는 답변 정확도 비교와 별도로, 현재 사용하는 v2 KG가 제공하는 기능을 재현 가능한 사례로 설명한다. 새로운 관계·온톨로지 후보를 채택하거나 유료 모델을 다시 실행하지 않았다.

## 먼저 고정한 성능 결과

저장된 관계 탐색 OFF/ON의 기존 평가용 24문항 재시험은 두 조건 모두 평균 **5.00/5점**, 완전 정답 **24/24**였다. 추가 관계 탐색의 답변 점수 이득은 관찰되지 않았다. 기존 결과를 개선된 결과로 교체하지 않는다.

`kg_build/v2_capabilities_20261028/qa_baseline.zip`에 직전 48개 답변 실행 기록, 채점 자료 및 결과 보고서를 보존했다. ZIP 내부 파일을 원본 SHA-256과 대조했고, 원래 실행·채점 봉인도 확인했다. 이 ZIP에는 로컬 비공개 평가 자료가 포함되므로 발표용 산출물은 본 보고서다. `baseline_manifest.json`에는 보호 대상 파일과 해시가 있다.

## 1. 관계 조회: 적용 대상과 조치 대상을 구별한다

**시연 질문:** “ST02 고온 규칙은 어떤 공정을 정지 대상으로 지정하는가?”

LLM 답변 생성 없이 실제 v2에 SPARQL을 실행했다. `candidate-SOP-001::RULE-ST02-02`의 `actionTarget`을 조회하면 **ST02_SEALING, ST03_LABELLING, ST04_PACKAGING**이 나온다. 조건·조치 텍스트도 같은 규칙 노드에서 함께 가져온다.

```sparql
PREFIX im: <https://example.org/imaks/v1#>
SELECT ?targetId WHERE {
  ?rule im:identifier "candidate-SOP-001::RULE-ST02-02";
        im:actionTarget ?target.
  ?target im:identifier ?targetId.
}
ORDER BY ?targetId
```

이것은 **문서에 지정된 조치 대상 조회**다. 현재 온도 측정, 정지 명령 실행, ST02에서 다른 공정으로의 고장 전파 입증이 아니다. 조건은 텍스트 속성이므로 관계만 떼어 무조건 정지 지시로 해석하지 않는다.

**두 번째 조회:** 서버실 공정 → `hasSensor` → TMP 센서 ← `appliesToSensor` ← 규칙 → `sourceDocument` → 문서.

이 경로로 서버실 온도 센서에 연결된 규칙과 출처 문서를 함께 열거했다. 동일 센서를 대상으로 하는 운영 규칙·정비 규칙·임계값 표현을 공통 식별자로 찾을 수 있다. seed 정비 규칙과 문서 추출 규칙이 별도 노드로 남아 있어, 반환 행 수를 독립적인 신규 지식 수로 세지 않는다.

실제 반환 결과는 다음 6행이다. `candidate-` 접두사는 문서 추출 노드의 저장 식별자 일부다.

| 규칙 식별자 | 출처 문서 |
| --- | --- |
| MAINT-05 | SOP-003 |
| candidate-SOP-001::RULE-SRV01-01 | SOP-001 |
| candidate-SOP-001::RULE-SRV01-02 | SOP-001 |
| candidate-SOP-002::SOP-002-EX-13 | SOP-002 |
| candidate-SOP-003::MAINT-05 | SOP-003 |
| candidate-SOP-003::SOP-003-EX-02 | SOP-003 |

재현 쿼리: `stop_targets.rq`, `sensor_rules.rq`. 전체 반환 행: `summary.json`의 `queries`.

## 2. 출처 추적: 규칙에서 원문 위치까지 연결한다

두 문서 추출 규칙을 골라 실제 경로를 조회했다.

| 규칙 | 문서·위치 | 원문에서 확인할 내용 |
| --- | --- | --- |
| RULE-ST02-02 | SOP-001, 1쪽, 해당 규칙 청크 | TMP >210°C, ST02·ST03·ST04 비상정지 |
| MAINT-05 | SOP-003, 1쪽, table1의 MAINT-05 행 | TMP >25°C가 >5분 지속, 보조 냉각, CRITICAL |

경로는 **규칙 → sourceDocument → Document**, **규칙 → hasProvenance → 페이지·인용문·해시**다. 조회한 인용문이 보존된 전처리 원문에 실제 포함되는지, 파일 해시·쪽이 대응하는지, 인용문 SHA-256과 저장 해시가 같은지를 검사했다. 규칙 청크와 표 청크의 서로 다른 출처 형태를 확인했다.

이는 선택한 두 사례의 **추적 가능성과 저장 내용 일치 검사**다. 이번 실행에서 원본 PDF 전체를 새로 시각 검토한 것은 아니며, 108개 규칙의 의미 정확성을 모두 재검증한 것도 아니다. 문서 날짜의 우선순위나 현장 안전성 역시 이 경로만으로 판정할 수 없다.

재현 쿼리: `rule_provenance.rq`. 확인 결과: `summary.json`의 `provenance_checks`.

## 3. 제약 검증: 정상 데이터와 고장낸 복사본을 구별한다

현재 v2와 기존 `ontology_v1/shapes.ttl`을 사용했다. `ontology.ttl`을 제공하고 `inference="none"`으로 검사한다. 매 사례마다 v2를 메모리에 새로 복사하여 **오류 하나만** 넣었다. 원래 KG 파일은 수정하지 않았다.

| 검사 사례 | SHACL 결과 | 확인한 기능 또는 한계 |
| --- | --- | --- |
| 원래 v2 | 통과 | 현재 정의된 구조 제약을 만족 |
| 센서의 공정 소속 제거 | 위반 검출 | S1: 센서는 정확히 한 Station에 소속 |
| 규칙의 문서 연결 제거 | 위반 검출 | S8: sourceDocument 필수 |
| 조치 대상으로 Sensor 연결 | 위반 검출 | S8: actionTarget은 Station |
| 문서 출처의 페이지 제거 | 위반 검출 | S7: 문서 출처 필수 위치 정보 |
| 인용문 해시를 64자리 0으로 교체 | **통과** | 문자열 형식만으로 실제 해시 일치를 알 수 없음 |

마지막 사례는 별도의 **원문·해시 대조에서 불일치를 검출**한다. 따라서 “SHACL 통과 = 문서 내용이 참임”이라고 주장하지 않는다. 구조적으로 올바른 잘못된 수치·대상·인용은 추가 검토가 필요하다.

네 가지 구조 오류의 검출은 이번에 의도적으로 만든 사례의 결과다. 실데이터 전체의 오류 검출률이나 제조 도메인의 정확도 수치가 아니다. 기존에 보류한 `requiresRuleCheck` 후보와 그 전용 SHACL은 이번 사례에 사용하지 않았다.

## 발표에서 보여줄 순서

1. **성능 결과부터 공개:** “관계 탐색 OFF/ON의 답변 점수는 동률이었다.”
2. **조치 대상 조회:** 위 SPARQL과 세 공정 결과를 함께 보여준다. 문서의 조건부 지시임을 설명한다.
3. **원문 추적:** RULE-ST02-02와 MAINT-05의 문서·쪽·인용·해시를 나란히 보여준다.
4. **오류 검사:** 원래 v2는 통과하지만 문서 연결을 지운 복사본은 위반으로 잡힌다는 결과를 보여준다.
5. **한계도 공개:** 형식이 맞는 가짜 해시는 SHACL을 통과하므로 원문 대조가 필요하다고 설명한다.

권장 설명:

> 기존 KG와 제조 문서의 규칙을 공통 온톨로지로 통합하여 규칙의 적용 센서·조치 대상·출처를 조회하고, 정의된 구조 제약을 검사할 수 있게 했다. 기존 문항의 답변 비교에서는 저장 관계 탐색의 추가 정확도 향상은 관찰되지 않았다.

이것은 **온톨로지 기반 KG 관리 기능의 실증**이다. 같은 기능이 다른 데이터베이스로는 불가능하다거나 RDF가 더 빠르다는 비교 실험은 아니다. GraphRAG가 새로운 온톨로지나 제조 인과관계를 자동 발견했다는 의미도 아니다.

## 실행·보존 경로

- 실행 코드: `scripts/show_v2_graph_capabilities.py`
- 결과 폴더: `kg_build/v2_capabilities_20261028/`
- 실제 쿼리 3개: `stop_targets.rq`, `sensor_rules.rq`, `rule_provenance.rq`
- 조회·원문 대조·검증 결과: `summary.json`
- SHACL 원본 리포트: `*_shacl.txt` 6개
- 보존 ZIP·원본 해시: `qa_baseline.zip`, `baseline_manifest.json`
- 이번 산출물 봉인: `complete.json`

기존 가상환경에서 저장소 루트를 기준으로 실행한다. 기존 결과 폴더가 있으면 덮어쓰지 않고 중단하므로, 새로운 실행은 출력 버전을 구분해야 한다.

```powershell
$env:PYTHONPATH='src'
$env:PYTHONUTF8='1'
..\.venv\Scripts\python.exe scripts/show_v2_graph_capabilities.py
```

네트워크를 차단한 상태에서 쿼리·검증을 실행한다. 새 모델·패키지 설치, 유료 API 호출, 온톨로지 변경, 운영 화면 변경, 커밋·푸시는 없다. v2 및 이전 비교 결과의 해시는 실행 종료 시 다시 확인한다.
