# XAI 추가 확장: 규칙 경계 → 종료 검사 → 문서 주장 → 평가

작성일 2026-11-15. 통합 사건 Agent `incident-agent-v5-20261115`.

네 단계 모두 백엔드에 연결했다. UI 구현·탐지 정책 변경·기존 결과 재채점·추가 유료 실험은 수행하지 않았다. 기존 런타임 ZIP을 복원한 상태에서 실행한다. 신규 모델 설치와 추가 원문 임베딩도 없다.

## 1. 경계와 시간 조건 설명

`rag/rule_explanations.py`가 봉인 IR·설정에서 각 규칙의 경계를 읽는다.

- `>`와 `<`는 경계와 같을 때 불충족이다. 범위 밖 조건도 양 끝값에서는 불충족이다.
- 값 완전 고정은 필요한 연속 동일 표본 수에 도달했을 때 충족한다.
- 부호 있는 증가량과 절대 변화량을 구분한다. 기울기는 절댓값 경계 외에 명목값에서 멀어지는 방향 조건도 표시한다.
- 엄격한 지속시간과 확정 표본 수를 구분한다. 예를 들어 30초 간격에서 `60초 초과 + 확정 2회`는 특징 조건 연속 시작 후 최초 120초에 충족한다. 특징 계산의 초기 창은 이 시간에서 제외한다.
- 센서 분해능이나 물리적 최소 조작량을 가정하지 않는다. 미만·같음·초과는 다른 게이트를 고정한 수학적 비교다.

`items[*].boundary`는 축별 비교 결과, 다른 필수 조건, 시간 정책, 실제 발동 관측값과 IR·설정 해시를 반환한다. 파생 감시는 원래 기울기의 경계와 별도 승격 조건을 구분한다. 임계값에 맞춰 실제 설비를 조작하라는 권고 또는 실제 고장이 해결된다는 인과 주장이 아니다.

## 2. 사후 종료·조건 해제 검사

원시 관측을 독립 특징 검사로 다시 계산하여 마지막 조건 충족 시각과 이후 표본을 확인한다. 원래 탐지 함수는 호출하지 않는다. 기존 `window_evidence.rule_proof`의 기본 발동 검사는 유지하고 선택적인 특징 시퀀스 경로를 추가했다.

| 결과 | 뜻 |
|---|---|
| `rule_condition_cleared` | 필요한 정상/비충족 표본을 관측하여 해당 규칙 조건 해제를 확인 |
| `data_gap_unconfirmed` | 관측 공백 때문에 연속 상태 확인 불가. 회복으로 처리하지 않음 |
| `open_at_data_end` | 자료가 끝날 때까지 조건 해제를 확인하지 못함 |
| `feature_unavailable` | 필요한 특징값을 계산할 수 없어 종료 판단 보류 |

기본 엔진은 비충족 1회로 그 알람 구간이 끝나고, 성호 방식은 비충족 2회로 확인하므로 중간의 비충족 1개가 사건 안에 남을 수 있다. 후자는 `status`, `last_positive_at`, `normal_confirmed_at`, `closed_at`, 해제 시작점도 대조한다. 전체 사건의 `end=max(알람 last_positive_at)`도 확인하지만 사건 묶음 구성 전체를 재검증한 것은 아니다.

모든 결과는 `retrospective=true`, `machine_recovery_verified=false`다. 저장된 `recovered`는 탐지 정책상 명칭이며 설비 회복·조치 실행·인과 효과를 뜻하지 않는다. 새 사건 설명에서 검사 불일치가 있으면 게시를 보류한다. 아직 지원하지 않는 경우는 `unassessed`로 표시한다.

## 3. 문서 주장과 원문 연결

통합 Agent의 문서 경로는 `documents.answer(..., claim_mode=True)`를 사용한다. 기존 독립 문서 Agent의 기본 모드와 과거 실행은 보존한다. 독립 실행에서 새 모드를 쓰려면 Python 함수에 `claim_mode=True`를 명시한다. 새 모드는 AI 관련성 검토 없이 실행할 수 없다.

`rag/document_claims.py`는 검색된 고정 청크의 표 행 또는 원문 줄을 발췌 주장으로 만들고 모델은 `DCL-...` ID를 최대 16개 선택한다. 코드는 원문 그대로 답변을 조립한다. 발췌 문구·문서·쪽·행·부모 청크·텍스트/원본 파일 해시·문자 범위를 확인한다. 선택 입력도 검색 모드의 토큰 상한 안에서 제한하며 누락 시 `catalog_truncated=true`, `answer_complete=false`로 표시한다.

없는 ID·다른 검색의 ID·중복·추가 자유 문장·변조된 원문/위치·중복 JSON 키를 보류한다. 결정적 선택 오류에는 AI 검토를 호출하지 않는다. 기존 문서 경로의 최대 초안 2회·검토 2회·검색 2회 상한을 유지한다. 전송 오류는 자동 재시도하지 않는다.

이는 **발췌 중심 답변**이다. 복잡한 상황값 계산·문서 간 새로운 해석·제조 의미의 참거짓은 이번 검사로 인증하지 않는다. 원문 내 지시는 참고자료로 취급한다. 관련성·조건 및 예외의 충분한 선택·질문 충족 여부는 AI 검토 영역이며 새로운 실제 모델 선택 성능은 미측정이다.

`claims[*].evidence_paths.paths[*]`는 사건과 같은 `steps/branches/status/uses_graph` 구조를 사용한다. 문서 발췌의 경로는 `file_lookup`이며 KG 간선을 새로 만들지 않는다. 문자 범위는 **파생 검색 청크 텍스트 기준**으로 원본 PDF 좌표가 아니며, 원본 PDF 배치를 시각 검증하지 않았다. 표 제목 안의 `[SOP-...:table]` 표기는 원문 자체일 수 있어 자유문장용 인용 정규식으로 허위 인용 판정을 하지 않는다. 코드가 붙이는 인용과 발췌의 참조를 따로 검사한다.

## 4. 평가와 재현

결과·분모·통제 오류의 종류·한계는 [XAI 평가 보고서](../../reports/xai_contract_evaluation_20261115_verify.md)에 정리했다. 이는 개발 자료의 참조/정책 검사이며 이상 탐지 정확도·미노출 QA 점수·현장 신뢰도 결과가 아니다.

```powershell
$env:PYTHONPATH = 'src'
python scripts/check_rule_explanations.py
python scripts/evaluate_xai_contract.py
python -m unittest tests.test_rule_explanations tests.test_document_claims -v
```

집계는 `kg_build/xai_extensions_20261115/`에 생성한다. 공유용 집계 JSON은 이 문서와 같은 폴더에 두며 원문·벡터·실제 API 기록은 추가 공개하지 않는다.

## UI 담당자에게 전달할 응답

| 항목 | 사용 |
|---|---|
| 새 사건 `xai.rule_explanations` | 규칙 경계, 시간 정책, 종료 구분, 검사 상태 및 한계 |
| 새 문서 답변 `xai.claim_binding` | 발췌 선택 상태와 `published`. 사건 `CLM`과 문서 `DCL`을 구분 |
| 새 문서 답변 `claims` | 게시된 발췌와 출처·문자 범위·참조 경로 |
| `xai.document_answer_complete` | AI 검토의 질문 충족 판단. 결정적 의미 검증 점수가 아님 |
| `GET /api/rule-explanations/<ID>` | 과거 사건의 현재 경계·사후 종료 점검. 원 답변 해시 보존, 모델 호출 없음 |
| `GET /api/document-claims/<ID>` | 과거 문서 검색 기록에서 현재 발췌 목록 생성. 과거 자유문장 검증이 아님 |

무료 조회와 새 모델 생성은 별개다. 읽기 전용 서버는 무료 조회만 허용하며 새 답변 생성은 계속 차단한다. 과거 기록에 새 필드가 없다고 통과로 표시하거나 과거 점수를 새 기능의 점수로 승계하지 않는다.
