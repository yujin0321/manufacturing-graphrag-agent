# 그래프 유형 QA 벤치마크 v3 (15문항)

2026-10-28 작성·고정. **어떤 시스템도 실행하기 전에** 문항·정답·가설을 고정했다(`lock.json`). 기존 30문항(예원 v2)은 실패 분석에 이미 쓰였으므로, 개선된 검색의 성능은 이 새 문항으로 잰다.

## 왜 새 문항인가

기존 30문항은 대부분 문서 ID와 규칙 ID를 질문에 직접 적었고, 청크 하나로 답할 수 있었다. 그래프 v2가 120/120으로 천장에 닿았고, 그래프가 유리할 수 있는 질문 유형은 거의 없었다.

## 구성

| 유형 | 문항 | 특징 |
|---|---|---|
| 나열형 | G01–G04 | 센서·공정 하나에 걸린 규칙을 여러 문서에서 모두 모으기 (G01은 엔티티 없는 집계형) |
| 다단계 | G05–G08 | 공정 의존 → 규칙 참조 → 정비 해소 순서처럼 2~3단 연결 |
| 현장 표현 | G09–G12 | 문서·규칙 ID 없이 "포장기 진동", "냉장 창고", "실러 전류" |
| 대조 | G13–G15 | 표 하나 안에서 끝나는 조회, 그래프 이득이 없을 것으로 예상 |

각 문항에는 `graph_hypothesis`(advantage / partial / no_advantage)를 **미리** 적었다. 결과가 가설과 다르면 그것도 보고한다(예: G15는 이득 없음으로 예상했지만 오프라인 검색에서는 별칭 사전 덕분에 회수됐다).

## 채점

- 채점 기준은 기존 `docs/benchmark_yewon_v2_20261023/채점기준_확정_v1.md`를 **수정 없이** 재사용한다(내용 3 + 근거 1 + 충실성 1 = 5점).
- 정답 요소 3개와 근거는 `evaluation/benchmark_graph_v3_20261028/answer_key_PRIVATE.json`(Git 제외). 근거 단위는 **행 단위 청크 ID**(예: `SOP-003:p1:table1:chunk#r4` = MAINT-04 행). 답변이 표만 인용하고 행을 특정하지 못하면 근거로 인정하지 않는다.
- 48개 근거 모두 원문에 실재하는지, 핵심 수치가 들어 있는지 스크립트로 검증했다.
- 권장: 답변은 시스템당 3회 생성해 평균과 범위를 보고하고, 팀원 1명이 시스템 이름을 가린 채 교차 채점한다.

## 한계

- 15문항은 작다. 근소한 차이를 우열로 말하지 않는다.
- 문항 작성자(AI)가 v3 별칭 사전도 작성했다. 팀원이 사전을 보지 않고 쓴 문항을 추가하는 것이 가장 좋은 보완이다.
- 문서 기반 QA만 평가한다. 실제 설비 상태, 신규 인과관계 발견, 현장 안전성은 평가하지 않는다.
