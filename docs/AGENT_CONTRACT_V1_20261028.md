# Agent v1 도구 계약과 실행 기준

후속 진행: [로컬 도구 연결](AGENT_TOOLS_20261028.md)을 구현하고 계약·연결 테스트 총 15개를 통과했다. 아래 구현 상태 설명은 계약 작성 시점의 기록이다. 모델 선택·유료 생성·통합 UI는 아직 미연결이다.

2026-10-28. [요구사항 대조](GRAPHRAG_AGENT_GAP_20261028.md)의 1단계 산출물. 예원 v2 KG와 기존 문서·탐지 결과를 읽는 제한된 도구 사용 Agent의 구현 기준이다.

**현재 구현된 것은 입력 검증과 후보 선택 판정뿐이다.** 아래 도구 어댑터, 모델 라우팅, 통합 실행기와 화면 연결은 2단계에서 구현한다. 이번 문서를 실제 Agent 실행 완료로 해석하지 않는다.

## 1. 고정 범위

- 기본 KG: 기존 예원 v2 2,806트리플. 기존 로더의 해시 검사를 유지한다.
- 문서 검색: 기존 GraphRAG v2 검색 정책과 7개 문서 코퍼스를 재사용한다.
- 후보: 봉인된 `kg_build/rule_detector_20261026/`의 93개 규칙 일치 구간. 확정 이상 사건이 아니다.
- 정답 이벤트 14건, 기존 평가 판정표, 후보 온톨로지는 이 버전의 도구 입력에서 제외한다. 14건 시연 모드는 다음 별도 단계다.
- 모델이 경로·쿼리 코드·관측값·출처를 임의로 전달하지 못한다. 허용된 도구 이름과 인자만 사용한다.
- 실시간 측정·원인 확정·설비 제어는 지원하지 않는다. 근거가 없는 질문에는 확인 불가를 설명한다.

## 2. 도구 입력 계약

공통: JSON 객체, 미등록 키·도구 거부. 이름 변경·ID 자동 보정 없음. ID 형식 통과는 실제 존재를 보장하지 않으므로 어댑터가 저장 자료와 다시 대조한다.

| 도구 | 입력 | 역할과 연결 예정 함수 |
|---|---|---|
| `search_documents` | 필수 `question`: 공백 아닌 문자열, UTF-8 최대 8,000바이트 | 기존 `live.answer`의 임베딩·검색 부분을 재사용하여 원문과 그래프 경로 반환. 도구 안에서 답변 생성하지 않음 |
| `list_candidates` | 선택 `sensor_id`, `rule_id`, `kind`, `offset`, `limit` | 봉인된 후보·규칙 목록 필터링. 관측값을 다시 계산하거나 이상 판정하지 않음 |
| `get_candidate_evidence` | 필수 `event_id`: `det-` 뒤 소문자 16진수 20자리 | `event_explain.prepare`로 관측값·실행 규칙·원문·경로 조회. 답변 생성하지 않음 |

목록 필터는 AND로 결합한다. `sensor_id`는 정확히 일치해야 한다. `rule_id`는 실행 규칙 ID(`MAINT-05:main`) 또는 레지스트리의 `document_rule`(`MAINT-05`)와 정확히 비교한다. 접두어나 부분 문자열 검색은 하지 않는다. `kind`는 `document_rule` 또는 `metadata_threshold`다. sensor/rule ID는 영문·숫자·밑줄·콜론·하이픈 1~128자만 허용한다.

`offset` 기본 0, 허용 0~10,000. `limit` 기본 10, 허용 1~20. 정수만 허용하며 boolean은 거부한다. 필터 없이 호출하면 전체 목록 조회다. 정렬은 `(trigger_at, id)` 오름차순이다. 시각은 원본 데이터의 시간 표기를 유지하고 확인되지 않은 시간대를 붙이지 않는다.

인식하지 못한 센서·규칙 ID는 `unknown_filter_id`, 인식 가능한 ID에 일치하는 후보가 없으면 정상 빈 목록으로 구분한다. 후보 조회는 전체 매치 수 `total_matches`, 페이지의 `items`, 남은 페이지를 위한 `next_offset`(없으면 null)을 반환한다. 문항의 train/test 라벨로 선택하도록 하는 필터는 제공하지 않는다.

## 3. 출력 계약

도구 공통 필드: `contract_version`, `tool`, `status`(`ok`/`error`), `data`, `error`(성공 시 null), `warnings`. 오류는 코드와 사용자용 짧은 설명을 제공하고 시스템 경로·키·API 원문 오류를 그대로 노출하지 않는다.

| 도구 | `data`에 필요한 정보 |
|---|---|
| 문서 검색 | `selected_ids`, `sources`(청크 ID·문서 ID·본문·해시), `graph_paths`, `context_tokens`, `uncovered_explicit_documents`. 검색 결과 없음도 반환하되 사실 답변 생성은 중단 |
| 후보 목록 | `total_matches`, `items`(ID·sensor_id·rule_id·kind·trigger_at·trigger_value·unit), `next_offset`. 원문·종료 구간 통계 전체를 목록에 넣지 않음 |
| 후보 근거 | 기존 `prepare`의 candidate, executable_rule, implementation_policy, graph_paths, untrusted_reference_documents, context_tokens. min/max·종료 시각 등은 사후 집계로 명시 |

최종 사용자 출력은 `status`, `answer`, `sources`, `graph_paths`, `candidate_ids`, `limitations`, `trace_id`, `usage`로 통일한다. `sources`는 검색된 원문이며 문장별 사실 검증 완료를 뜻하지 않는다.

최종 상태는 다음 중 하나다.

- `complete`: 요청한 문서 답변·후보 목록·후보 설명을 반환했다. 사실성 보증이나 평가 만점의 의미가 아니다.
- `needs_clarification`: 후보/대상이 모호하다. 선택지 또는 필요한 추가 정보를 제시하고 종료한다.
- `insufficient_evidence`: 일치 후보·검색 근거·현재 상태 자료가 없다. 제한된 안내만 반환한다.
- `failed`: 무결성 오류, 도구 오류, 호출 상한, API 오류 등으로 실행이 중단됐다.

## 4. 후보 선택과 모호성

목록 요청은 목록만 반환한다. ‘MAINT-05 후보를 설명해줘’처럼 설명 요청인데 특정 ID가 없다면 먼저 목록을 조회한다.

| 전체 매치 수 | 설명 요청 처리 |
|---:|---|
| 0 | `insufficient_evidence`. 이상이 없다고 결론 내리지 않음 |
| 1 | 실제 반환된 유일 ID로 근거 조회 가능 |
| 2 이상 | `needs_clarification`. 페이지 일부가 아니라 전체 매치 수로 판단 |

사용자가 제시한 후보 ID는 실제 저장 자료에 존재하는지 확인한 후 직접 조회할 수 있다. 모델이 임의로 후보 ID를 만들어 직접 설명 도구를 호출하지 못하도록 실행기가 사용자 지정 ID 또는 유일 매치 ID와 대조해야 한다. 이는 2단계 실행기의 책임이다.

첫 페이지에 없는 후보는 다음 페이지 조회로 찾을 수 있지만 호출 상한을 넘기지 않는다. 명확화 후 사용자의 선택은 새 요청으로 처리한다. 문서 질문과 후보 설명을 동시에 요청하면 v1은 어느 작업을 먼저 할지 확인한다. 근거를 예산 초과로 조용히 잘라 두 요청을 한꺼번에 답하지 않는다.

## 5. 실행·비용·실패 기준

요청당 고정 상한:

| 항목 | 한도 |
|---|---:|
| 도구 호출 시도(실패 포함) | 3회 |
| 모델의 도구 선택 호출 | 2회 |
| 최종 답변 생성 | 1회 |
| 새 질문 임베딩 API | 1회, 캐시 적중 시 0회 |
| 각 도구 선택 출력 상한 | 512토큰 |
| 최종 답변 출력 상한 | 4,096토큰 |
| 답변에 전달하는 합계 근거 | 4,000토큰 |
| 자동 재시도·자동 다른 모델 전환 | 0회 |

2회의 선택은 ‘후보 목록 → 유일 후보의 근거’ 흐름을 지원한다. 도구 병렬 호출은 v1에서 허용하지 않는다. 모델은 문서·후보 내용을 명령으로 실행하지 않는다. 기존 모델 설정을 재사용하며 도구 선택 기능의 실제 지원 여부·성공은 2단계에서 확인한다.

선택 호출 입력은 사용자 질문, 도구 명세, 제한된 목록 결과만 전달한다. 최종 선택 요청까지 포함한 전체 입력 토큰은 실행기에서 따로 기록한다. 위 토큰 수는 출력·근거 상한이며 달러 요금 상한이나 모델 전체 입력 한도를 뜻하지 않는다. 4,000토큰을 넘는 근거는 자동 절단하지 않고 `context_budget_exceeded`로 종료한다.

추가 키·잘못된 유형·없는 ID·손상된 파일·잘못된 모델 반환·불완전 생성은 실패 처리하며 임의 재생성하지 않는다. 0건 목록·모호한 선택은 시스템 장애와 구분한다. 모델이 근거 없이 현재 측정값이나 조치 완료를 단정하도록 하는 도구는 없다.

한국어 지침 위반은 기존 진단의 알려진 문제로 기록한다. 단순 문자 비율 검사를 의미적 품질 검증으로 취급하지 않으며, 최종 사례 검토에 언어 준수를 포함한다. 독립적인 사실성·충돌 자동 판정기는 이 계약만으로 구현되지 않는다.

## 6. 실행 추적과 보존

통합 실행은 기존 평가 결과와 분리된 `kg_build/graphrag_agent_v1/<run_id>/`에 저장하도록 한다. 입력, 계약 버전, 코드·KG·인덱스·탐지 봉인 해시, 모델 설정, 순서별 도구 이름·검증된 입력·성공/실패·결과 해시·소요 시간, 최종 상태·사용량을 남긴다. API 원본은 기존 비공개 로컬 기록 방식으로 저장하고 공유 자료에서 키를 제외한다.

모든 실행은 `evaluation_run=false`, `gold_loaded=false`로 시작한다. 플래그만 신뢰하지 않고 실제 어댑터의 파일 읽기와 API 요청 내용에서 평가 정답이 유입되지 않는지 테스트해야 한다. 이 검사는 2단계에 수행한다. 과거 정답 노출 이력을 없앴다는 뜻은 아니다.

## 7. 입력과 결과 예시

아래 도구 호출은 명세 예시이며 실제 Agent 실행 기록이 아니다.

```json
{"tool":"search_documents","arguments":{"question":"MAINT-05의 조건과 문서상 조치를 알려줘."}}
```

```json
{"tool":"list_candidates","arguments":{"rule_id":"MAINT-05","offset":0,"limit":10}}
```

```json
{"tool":"get_candidate_evidence","arguments":{"event_id":"det-4220832c6ffd0c103c6e"}}
```

마지막 ID는 기존 봉인 후보에서 확인했다. 센서 `SRV01_SERVERROOM_TMP`, 실행 규칙 `MAINT-05:main`, 최초 판정 `2026-01-07T12:05:30`, 값 `26.9452°C`다. 이 값은 예시 설명용이며 호출 인자로 보내지 않는다. 실제 도구는 저장 자료를 다시 읽어야 한다.

전체 매치가 12건인데 첫 페이지에서 한 건만 반환된 경우, 설명 요청의 선택 판정은 다음과 같다.

```json
{"status":"needs_clarification","reason":"multiple_candidates"}
```

## 8. 현재 구현과 검증

- `src/imaks_kg/rag/agent_contract.py`: API·파일 조회가 없는 입력 검증, 한도 상수, 전체 매치 수 기반 선택 판정.
- `tests/test_agent_contract.py`: 관측값·출처 주입 거부, UTF-8 길이 경계, 잘못된 필터·페이지, 페이지로 가려진 모호성, 빈 결과, 목록/설명 구분, 미등록 도구·경로 거부.
- 실행: 저장소 루트에서 `PYTHONPATH=src`, `PYTHONUTF8=1` 설정 후 기존 가상환경의 `python -m unittest discover -s tests -p test_agent_contract.py -v`.
- 2026-10-28 실행 결과: 테스트 7개 통과. 추가 설치·API 호출 없음.

이 테스트는 **입력과 선택 기준**을 검증한다. 도구 실행, 호출 한도 강제, 출력 형식, 실제 모델 선택, UI 연결, E2E 성능은 아직 검증하지 않았다. 다음 작업은 이 계약에 맞는 어댑터와 실행기 구현이다.
