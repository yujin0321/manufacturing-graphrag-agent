# iMAKS UI 전달 안내

- demo/index.html을 열고 예제 데이터 → 탐지 실행 → 경보 선택 순서로 시연합니다.
- integration/serve-page.html은 예원12 서버와 같은 출처에서 제공하는 단일 HTML입니다. integration/index.html과 api.js는 분리된 편집 원본입니다.
- 백엔드는 팀이 승인한 예원12 작업본 또는 해당 코드를 통합한 main을 사용합니다.

## 로컬 연동

`scripts/run_xai_agent.py --serve`는 이제 기본으로 `sensor-ui/integration/serve-page.html`을 루트(/)에서 제공합니다. `xai_demo.html`을 교체할 필요가 없습니다. 다른 화면을 띄우려면 `--page <파일>` 또는 환경변수 `IMAKS_PAGE`를 사용합니다. 서버 실행 전에 원본 저장소의 런타임 및 의존성 준비 절차를 따르세요.

```powershell
# 저장 결과 조회 + CSV 분석 (API 키 불필요)
.\.venv\Scripts\python.exe scripts/run_xai_agent.py --serve --read-only --allow-local-analysis --port 8770
# 새 질문 생성까지 (.env의 OPENAI_API_KEY 필요, 비용 발생)
.\.venv\Scripts\python.exe scripts/run_xai_agent.py --serve --allow-local-analysis --port 8770
```

브라우저에서 http://127.0.0.1:8770/ 을 엽니다.

- CSV는 UTF-8, 최대 4 MiB, 20,000행이며 열은 timestamp,zone,station_id,sensor_id,sensor_type,value,unit 순서입니다.
- 기존 timeseries_raw.csv도 UI에서 열 수 있습니다. 브라우저에서 서버용 7개 열과 선택 구간을 추출합니다. 큰 파일의 기본 구간은 최근 약 15,000행이며, 전송 한도 안에서 앞선 최대 30분의 관측을 포함합니다.
- 세션 토큰을 가져와 CSV 본문을 POST /api/analyses로 보낸 뒤 완료까지 조회합니다.
- 시간대 표와 목록의 사건은 incident_items를 사용합니다. 상세 화면은 같은 analysis_id와 incident_id로 시계열과 사건 근거를 읽습니다.
- 그래프의 경고 기준선은 센서 메타데이터에서 옵니다. 실제 규칙 조건은 사건의 구조화된 근거에서 확인합니다.
- 업로드 사건 설명은 로컬 코드가 근거로 구성합니다. 정답 14건 자동 비교와 업로드 사건 자유 질문은 이 서버 경로에 포함되지 않습니다.

## 추가 화면 기능
- 업로드에서 분석 시작·종료를 함께 지정하면 시작 전 원본 관측을 선행 계산에 사용합니다. 둘 다 비우면 전체 파일을 분석합니다.
- 저장된 분석 조회와 ZIP 복원은 완료 결과를 다시 엽니다. 결과 화면의 ZIP 내보내기에는 원시 입력이 포함되므로 팀 내부에서 관리합니다.
- 문서·KG 질문 창에서 저장된 질문 실행을 열 수 있습니다. 새 질문은 generation_enabled 서버에서만 가능하며 모델 호출 비용이 발생할 수 있습니다. 읽기 전용 실행에서는 저장 답변만 조회할 수 있습니다.

- 사건 상세의 후속 질문은 같은 분석 ID와 사건 ID의 기존 구조화 근거를 사용합니다. 별도 LLM 호출과 자유 대화 API는 사용하지 않습니다.


## 화면 구성 (8th-yujin, 2026-11-18)

- **왼쪽 사이드바**: 진행 단계(01 파일 업로드 / 02 탐지 결과 / 03 경보 상세, 갈 수 없는 단계는 비활성)와 이전 작업 이어가기(ZIP 복원·저장된 분석 조회·문서·KG 질문). « 버튼으로 접기, 상태는 브라우저에 저장.
- **01 업로드**: 왼쪽 6 센서 파일 업로드 : 오른쪽 4 분석 구간. 분석 시작·종료는 항상 펼쳐진 달력(데이터가 있는 날짜만 선택 가능). 숨겨진 `#analysisStart/#analysisEnd` 입력이 값의 기준이며 달력은 이 값을 읽고 씁니다.
- **02 탐지 결과**: 제목 "탐지 결과 및 분석", 탭 묶음(탐지 결과·평가 | 문서·KG 질문)과 오른쪽 끝 버튼(분석 ZIP 내보내기·업로드로). 경보 목록은 전체 시간순 "첫 번째 경보…" 이름(빨간색) + 작은 날짜·시간.
- **03 경보 상세**: 2행 그리드. 위: 센서 그래프 | 경보 판정 근거. 아래: "무엇이든 물어보세요" 질문 카드(추천 질문 3개, API 비용 없음) | 근거 요약 1~6번 접이식(마지막 "근거 상세 정보"에 출처·원본 JSON·주의사항).
- **답변 표시**: 요약 → 근거 상세. 사건 답변의 요약은 `claims`·`xai.incident`·`xai.decision_evidence`로 코드가 조립(LLM 추가 호출 없음). `[CLM-…]`은 숨기고 문서 인용은 [1], [2] 번호.
- **분석 ID**: 사용자에게는 "11/18 09:37 실행 · 사건 3건"처럼 표시하고 ID는 작게(툴팁에 전체).

## 파일 동기화 규칙

- `serve-page.html` = `index.html`의 `<script src="api.js">` 자리에 `api.js` 내용을 넣은 단일 파일 + 개발용 피드백 스크립트. 화면을 고치면 세 파일을 함께 맞춥니다.
- 개발용 피드백 모드: `http://127.0.0.1:8770/?feedback`에서만 동작(공개 주소에서는 비활성). 오른쪽 아래 버튼 → 글자 드래그 또는 요소 클릭 → 피드백 저장. 목록은 브라우저 localStorage `imaksFeedback`에만 저장됩니다.
