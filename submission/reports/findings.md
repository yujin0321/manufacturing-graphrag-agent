## 4. 문서 추출 검토

원본 PDF 7개, 10페이지를 렌더링하여 텍스트·표와 시각적으로 대조했다. 추출본에 문서 ID와 1-based 페이지를 붙였다. 페이지 2에도 페이지 1의 문서 ID를 유지한다.

- SOP-001 p1과 SOP-003 p1의 긴 스테이션 ID는 원본 표 안에서도 줄바꿈된다. 추후 표 셀 내부 줄바꿈 제거 후 기준 ID 사전과 매칭해야 한다.
- SOP-002 p1의 `pcs/min`과 열 이름 `CRIT_LO`, `WARN_HI` 등이 줄바꿈된다. 단위와 열 제목을 원문 그대로 보존하되 후속 표 구조화 때 정규화가 필요하다.
- SOP-002 p1의 Server Room 표가 p2의 HUM 행으로 이어진다. 페이지 단위 청킹만 하면 스테이션 연결이 사라질 수 있다. 현재는 페이지별 원형을 보존했고 자동 결합하지 않았다.
- SOP-004는 이번 설비 중심 모델의 주된 추출 대상이 아니지만 원본과 추출 결과는 보존했다.
- SOP-002 p1의 ST02 온도 CRIT_HI 210°C와 DS-Thermal p1의 연속 사용 200°C, 전류 CRIT_HI 15A와 DS-Electrical p1의 연속 과부하 14A는 적용 맥락이 다르다. 하나의 임계값으로 덮어쓰지 않고 출처와 조건을 함께 표현해야 한다.
- DS-Mechanical p1의 정확도 값과 괄호 속 비율도 단순히 하나의 값으로 해석하지 않는다. 추후 규칙 추출 시 문서 자체의 수치·조건 검토 대상이다.

추출은 성공했지만, 전체 문서의 모든 규칙이 검증된 트리플로 변환된 것은 아니다. 특히 표 병합과 ID 정규화는 후속 지식 추출 전처리 단계로 남아 있다.

## 5. 누출 방지 정책

탐지 입력: `timestamp, sensor_id, station_id, sensor_type, value, unit`만 사용. `anomaly_label, severity, alarm_flag` 및 기타 사전 계산 필드는 제외. `quality`와 nominal·임계값은 사용 권한이 없는 정보라고 단정하지는 않지만, 기본 실험에서는 제외해서 입력 조건을 명확히 했다. 향후 임계값 기준선 실험은 별도로 정의한다.

정적 seed 입력은 System·Zone·Component·Sensor만 남기고, 관계는 그 노드 사이 contains·part_of·monitors·feeds_into만 허용한다. 이 CSV는 39노드·72관계다. RDF는 그중 이번 온톨로지에 필요한 Station·Sensor·공정 흐름만 구성한다. Person·SafetyEvent·AnomalyEvent·Maintenance 및 정답 관계·필드는 모두 입력에서 제외했다.

`ground_truth.csv`는 SOP 규칙 추출 평가용 정답임이 공식 설명과 CSV 구조에서 확인된다. 규칙 설계/예제 작성에 정답 내용을 참고한 부분은 독립적인 블라인드 추출 성능으로 주장하지 않는다. 현재 점검 예제는 SOP 원문을 수동으로 옮긴 것이다.

## 6. 분할 제안과 한계

`events.csv`에 GT-0001~0009를 development, GT-0010~0014를 test로 제안해 기록했다. 공식 소개의 9/5 구분을 ID 기준으로 따른 것이며 팀 확정 분할은 아니다. ZIP 기준 테스트 이벤트는 모두 1/9에 있다.

- 시간 기준의 개발 구간을 1/6~1/8, 테스트 구간을 1/9로 정하는 안을 회의에서 검토한다. 별도 학습·검증 구간과 정상 구간 선정 규칙도 필요하다.
- 개발 구간에도 이상이 있으므로 전체 개발 구간을 정상 학습 데이터라고 간주하지 않는다.
- 정규화는 학습 구간에만 fit한다. 윈도우는 분할을 먼저 정한 후 생성하고, 경계를 가로지르는 윈도우와 동일 이벤트 공유를 금지한다.
- 제조 공정만 남기면 개발 7개·테스트 2개 이벤트다. 이 테스트로 5개 유형 전반의 분류 성능을 주장하기 어렵다.
- 전체 기준으로도 STUCK·CORRELATED는 개발 세트에만 있어 테스트 5유형 분류 평가는 불가능하다. 유형별 결과는 표본 수와 함께 제한적으로 보고해야 한다.
- 현재 정답을 읽어 데이터 감사를 수행했으므로, 데이터셋을 처음 보는 완전한 블라인드 실험이라고 부를 수는 없다. 이후 평가 라벨을 이용한 임계값 튜닝은 하지 않는다.

## 7. 검증과 이번 주 완료 기준

실행한 노트북 8개 코드 셀 모두 성공. 출력 행 수와 원래 측정값 보존 확인. SHACL 9개 사례에서 기대 통과/실패 결과가 모두 일치했고, 잘못된 예제는 예상 제약에서 실패했다. 실제 정적 RDF도 통과했다. 예제 SPARQL 질문 3개가 값을 반환했다.

남은 팀 결정은 데이터 범위, 학습·검증·평가 분할, 문서 규칙 대상·출처 모델이다. 이상 탐지·LLM 추출·GraphRAG 성능은 아직 측정하지 않았다.
