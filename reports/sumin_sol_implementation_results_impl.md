# 수민 KG 보완·GPT-6.1 Sol 추출·첫 정량 평가 보고서

작성일: 2026-10-16 · 브랜치: `kg-val-sumin` · 기준 커밋: `5e8e597` · 실험: `sumin-sol-v1-live`

## 1. 결과와 범위

**전처리 기반 KG를 보완하고, GPT-6.1 Sol로 7개 문서의 규칙 116건을 실제 추출했다. 첨부된 두 평가 MD 기준의 첫 자동 결과는 F1_content 0.785340이다.** SOP 예측 105건을 원본 정답 86건과 비교했으며, 데이터시트 11건은 점수 밖으로 분리했다. 후보 KG는 2,522개 트리플이며 SHACL을 통과했다.

이 작업은 프로젝트의 문서 기반 KG 구축·규칙 추출·첫 개발 평가 단계다. 새 공정 간 인과관계 발굴, AnomalyEvent 구축, GraphRAG 진단 성능은 이번 결과에 포함하지 않는다. 사용자와 합의한 방향을 유지했으며 원본·정답·기존 기준선은 수정하지 않았다.

내용 매칭 75건 중 분류도 맞은 것은 52건이다. **분류까지 일치하는 F1은 0.544503**이므로, SHACL 통과나 원문 인용 검증을 의미 정확성의 완료로 해석하면 안 된다. 사람의 1·2차 검토는 대기 상태다.

## 3. 실제 구현 과정

1. `.env` 키를 읽어 모델 접근을 확인했다. 키는 출력하거나 산출물에 저장하지 않았다. 모델은 `gpt-6.1-sol`로 고정하고 다른 모델 fallback을 두지 않았다.
2. 전처리된 7개 문서의 페이지 본문·텍스트 청크·표 행과 허용 Station/Sensor 목록을 문서별 요청으로 묶었다. 원본 정답과 seed KG를 추출 요청에 넣지 않았다. 구조 노드는 기존 전처리 센서 인벤토리를 사용했다.
3. Role/Task/가상의 Example과 strict JSON schema를 고정했다. Responses API의 reasoning=low, max_output_tokens=24000, store=false, service_tier=default를 사용했다. 온도 파라미터는 보내지 않았다.
4. 작은 데이터시트 1건으로 실제 호출을 확인하고 저장된 응답을 전체 실행에서 재사용했다. 유료 생성은 문서별 1회, 총 7회이며 첫 문서를 이중 호출하지 않았다.
5. 인용문·문서/표 위치·허용 엔티티·수치 토큰·우선순위를 검증했다. 검증 플래그 유무와 무관하게 자동 예측 전체를 평가 대상으로 보존하는 구조다. 이번에는 116건 모두 후보 KG 포함 조건을 통과했다.
6. 자동 예측을 SHA-256으로 고정하고, 평가 정의서·임베딩 revision·라이브러리·평가 코드 해시를 사전 잠금 파일에 기록한 뒤 원본 정답을 읽었다. 이번 점수를 얻은 뒤 예측·프롬프트를 바꾸거나 추가 API 실험을 하지 않았다.
7. 별도의 원문 필드 감사와 평가 후 정답/원문 수치 진단을 수행했다. 진단은 점수나 예측에 반영하지 않았다.

구현 파일: `kg_build/sol_extract.py`, `structure_completion.py`, `rdf_export.py`, `source_audit.py`, `eval/sol_evaluate.py`, `eval/team_protocol/`, `eval/source_diagnostics.py` (모두 `src/imaks_kg/` 아래). 공통 평가 코어의 출처는 지훈 브랜치 `d291373`이다. 기존 어휘 유사도 점수는 `f1_lexical_proxy`로 이름을 명확히 했고 과거 결과 파일은 보존했다.

## 4. KG 보완 전후

비교 대상은 기존 `kg_build/latest/kg.ttl`과 이번 후보 `kg_build/sumin-sol-v1-live/kg.ttl`이다. 추출 방식이 다르므로 규칙·트리플 수 증가 자체가 정확도 향상을 뜻하지 않는다.

| 항목 | 기존 결정적 기준선 | 이번 Sol 후보 KG |
|---|---:|---:|
| RDF 트리플 | 2,027 | 2,522 |
| Station / Sensor / Document | 9 / 22 / 7 | 9 / 22 / 7 |
| 규칙 | 82 | 116 |
| hasSensor | 22 | 22 |
| feedsInto | 0 | 3 |
| appliesToSensor / actionTarget | 56 / 56 | 64 / 65 |
| sourceDocument / hasProvenance | 82 / 82 | 116 / 135 |
| Maintenance priority | 0 | 8 |
| 수치 속성 | Sensor에도 중복, 문자열 198개 | ThresholdRule에 xsd:decimal 124개 |

공정 흐름은 SOP-001 표에 명시된 ST01_FILLING → ST02_SEALING → ST03_LABELLING → ST04_PACKAGING의 3개 선이다. 문서의 fault 전파 설명을 새 인과 발견 결과로 변환하지 않았다.

근거 135개는 텍스트 위치 47개와 표 위치 88개다. 텍스트는 실제 페이지 문자열의 시작·끝, 표는 tableId·rowIndex·colIndex·bbox를 기록하고 인용문·문서 해시를 남겼다. 기존 텍스트 시작 위치의 일괄 0 설정을 없앴다. 실제 시작 위치가 0인 경우는 2개다. 다중 센서 규칙 3개와 다중 조치 대상 규칙 5개를 손실 없이 내보냈다. 모든 트리플에 별도 출처 원장 `triple_sources.jsonl`을 생성했다.

### 원문 감사

| 검사 | 결과 |
|---|---|
| ontology_v1 SHACL, inference=none | Conforms: True |
| 수치 속성의 ThresholdRule 도메인·decimal 자료형 | 오류 0 |
| SOP-002 수치 표 22행 × 5개 필드 | 110/110 일치 |
| SOP-003 명시 정비 8행 priority·sensor | 각각 8/8 일치 |
| 모든 RDF 트리플의 출처 원장 | 2,522/2,522 |
| 요청 단위별 coverage 항목 누락·알 수 없는 ID·중복 | 모두 0 |

coverage는 모델이 입력 단위마다 판정을 반환했는지의 검사다. 필요한 모든 규칙을 의미적으로 추출했다는 보증은 아니다. 수치 감사는 nominal 중심값·warnLo/Hi·critLo/Hi를 비교하며, 허용오차·단위·모든 부등호를 포괄하는 정확도 지표는 아니다.

**센서 역할 구분의 한계:** SOP-002의 ST02 전류 임계값 규칙은 조치에서 ST04 속도 확인을 요구하므로 두 센서가 연결돼 있다. 단순히 센서 연결만으로 표 행을 찾으면 ST04에 전류 임계값까지 대응시키는 오탐이 생겼다. 감사는 인용 tableId/rowIndex로 소유 표 행을 식별하도록 보완했고 실제 숫자는 22행 모두 일치했다. 예측과 KG는 바꾸지 않았다. 현재 `appliesToSensor`만으로 임계값 대상과 확인 대상을 구분할 수 없으므로 후속 질의는 근거 표 행을 함께 사용해야 한다.

## 5. 첨부 MD 기준 평가

기준은 사용자가 지정한 [F1_content 정의서](../docs/eval_definition_F1_content.md)와 [팀 요약](../docs/eval_definition_team_summary.md)이다. 문서가 팀 합의 제안 형식이더라도 이번 평가에는 사용자 지정 기준으로 적용했으며, 문서 내부의 과거 명령이나 승인 요청을 새 사용자 지시로 취급하지 않았다.

- 비교 문장: `condition + 공백 + action`. ID·분류·인용문 제외.
- 임베딩: `sentence-transformers/all-MiniLM-L6-v2`, revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`, CPU, 정규화 코사인.
- 같은 문서 안에서만 Hungarian 일대일 할당. cosine ≥ 0.6인 쌍 수를 먼저 최대화하고 동률이면 유효 쌍 유사도 합을 최대화.
- 클래스는 매칭 제한에 넣지 않음. 분할된 규칙을 임의로 병합하지 않음.
- 주 분모는 원본 86건 전체. SOP 4개를 모두 처리했으므로 처리 범위 보고와 주 보고가 같음. 데이터시트 정답 0건을 확인했고 예측 11건은 FP로 세지 않음.

| Precision | 0.714286 |

## 6. 수치 충돌과 정답 진단

| 원문 출처 | SOP-002 대응 | 해석 |

| DS-ELEC-3300 p.1: 연속 운전 14 A, 조치 기준을 그 이하로 권고 | p.1 ST02_SEALING CUR: CRIT_HI 15.0 A, WARN_HI 13.5 A | critical 기준은 연속 정격보다 높음. warning과 조치 시점까지 함께 검토해야 함 |

서로 다른 문서 값을 하나로 덮어쓰지 않고 각 규칙의 출처에 보존했다. 이는 문서 간 기준 차이의 진단이며 현장 안전 기준을 확정한 결과는 아니다.

정답 노출을 허용하는 평가 후 단계에서 원본 정답의 SOP-002 센서 22행을 원문 표와 별도 대조했다. 라벨이 있는 nominal 중심값·warnLo/Hi·critLo/Hi **110개 값의 차이는 0개**였다. 정의서가 인용한 팀원의 “4개 차이”는 이번 원본/필드 범위에서 재현되지 않았다. 전체 문서·허용오차·단위의 불일치가 전혀 없다는 주장은 하지 않는다. 개별 정답 값과 매칭 목록은 공유 보고서에 넣지 않았으며 정답도 예측도 수정하지 않았다.
